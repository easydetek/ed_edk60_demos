在一扇门里塞一颗 10.5 GHz 雷达，让它在**不接触、不按键、不掏手机**的前提下知道「门前有人」，
并把这个判断变成一个干净的**高电平触发**——这就是 **EDX106 门锁雷达模组**（AT10LP1T1RDB）能做的事。

我们用 **EDK60 开发板**（ESP32-C6）通过 **I2C** 把它配起来：MCU 每次上电把 7 组参数写进芯片、逐字节回读校验，
然后把芯片 **OUT 引脚**的电平变化翻译成一行一条的 USB 文本事件，橙灯跟着亮。
一个外部电阻都不用，插上 USB 就能看数据。

> **✅ 验证状态（2026-10-27 上板跑通）**：EDK60 + EDX106-N-01 **首次上板即通过**——
> `i2c ok freq=100000 pullup=internal`、`SCAN` 见 `0x28`、`CFG?` **13 个寄存器回读全通过**。
> **实测数字**：常规模式 + `thr=70` → **≥1.0 m 稳定触发**（22 秒内 3 次：2.37 s / 8.75 s / 16.81 s，
> 高电平宽度 2368 / 3198 / 3845 ms）；ULP 模式 + `thr=115` → **仅 ≈30 cm**；
> 闭锁防抖 0.5 s 间隔连挥 3 次 → **只记 1 次事件**；**橙灯随触发点亮**（目视确认）。
> **仍未验证**：电池供电续航、30 分钟长稳、深睡唤醒、外置上拉下 400 kHz。
> 本文**不给任何续航数字**——两份资料给出的电流本身矛盾（见下文「ULP 与距离的取舍」）。

## 场景需求

| 需求 | 说明 | 方案如何满足 |
|---|---|---|
| **非接触** | 手上提东西、戴手套、不想碰公共表面 | 10.5 GHz 多普勒雷达测运动，**零接触** |
| **不要开孔、不要面板** | 门锁外观是产品力的一部分，多一个按钮就要开孔、要防水、要防误触 | 一颗 12.0 × 7.5 mm 的模组**藏在门锁壳体内部** |
| **只要「有人/无人」这一比特** | 门锁的主控不需要距离、不需要坐标、不需要轨迹 | 芯片 **OUT 引脚**直接给电平：**检测到目标 = 高** |
| **能长时间开着不误报** | 走廊里人来人往，门锁不能一直亮 | 阈值 + **闭锁时间** + 延时三件套（都能用寄存器调） |
| **功耗要能被门锁接受** | 电池门锁的静态电流预算是 µA 级 | 芯片有**超低功耗档**（78~341 µA 量级），代价是距离 |
| **免驱动接入** | 现场/演示电脑常是受控环境，不能装驱动 | ESP32-C6 原生 USB CDC，插上就是串口 |
| **参数能现场调** | 不同门的朝向、材质、人流差别很大 | 6 类 USB 文本命令，`SET thr=70` 立刻回读确认 |
| **不依赖云** | 隐私敏感：「有人在家门前」不该上传 | 全链路本地：模组 → 板子 → PC，无网络请求 |

**为什么门锁用雷达而不是 PIR**：

| 维度 | PIR（热释电红外） | **10.5 GHz 雷达（本方案）** |
|---|---|---|
| 检测对象 | 红外辐射变化 → 需要**目标与背景有温差**且**横向切过视场** | **运动**引起的多普勒频移 |
| 装在壳体内 | 需要**红外透射窗**（壳体开窗或用透红外材料） | 可**完全藏在塑胶壳内**（塑胶穿透好，金属不行） |
| 高温/低温环境 | 环境温度接近体温时**灵敏度骤降**（夏天户外、暖气旁） | 受环境温度影响小（芯片标称工作 −20~+85 °C） |
| 穿墙/穿门 | 不能穿透 | **也不能**（金属完全挡死，玻璃/陶瓷也不行）→ 安装面必须留塑胶窗 |
| 输出 | 通常是「有/无」数字脉冲 | 本模组同样是**单比特 OUT**，但**时长、阈值、闭锁全可配** |
| 误触发来源 | 阳光、热气流、宠物 | 运动的金属门、走廊人流、风扇/门帘、**电源纹波** |

一句话：**雷达的优势是「能藏起来 + 不怕环境温度」，代价是「需要配参数、怕金属、怕纹波」。**
这正是本 demo 存在的意义——把「配参数」这件事做成 MCU 每次上电自动完成。

**不能同时接**。换 demo 要拔线 + 重烧固件。

## 关键工程点

### 1. 为什么门锁用雷达而不是 PIR——以及这条路线的真实代价

PIR 便宜、成熟、功耗低，但它有一个对门锁很致命的特点：**必须开窗**。红外要透射，
要么壳体开孔，要么用透红外材料——两个选择都会破坏外观、增加防水难度、并且限制 CMF。
雷达可以**整颗藏在塑胶壳里**，这是它在家用门锁上最大的吸引力。

代价有三条，必须提前认：

| 代价 | 具体表现 | 本方案怎么应对 |
|---|---|---|
| **参数必须配** | 阈值/延时/模式出厂是「外部 pin 决定」，而这颗模组**一个 pin 都没引出** | MCU 每次上电重配 + 回读校验（见下一条） |
| **怕金属** | 金属门/面板紧贴会让灵敏度崩溃；玻璃、陶瓷也不能挡在天线前 | 塑料窗 + 与金属保持 5~12 mm（结构约束，不是固件能解决的） |
| **怕纹波** | 规格书明写纹波超标会「受干扰和误报」，要求 ≤50~100 mV | 用 PC 的 USB-C 供电；改电池/适配器时第一件事是量纹波 |

### 2. 「配置掉电不保存」→ 为什么 MCU 每次重配反而是这个方案最有价值的部分

芯片手册明写两件事：**寄存器掉电不保存**（每次上电后需要配置）、以及**上电不做配置也能工作**（靠外部 pin）。
听起来「不配也能跑」，但在这颗模组上这个安慰是不成立的：

| 三个开关 | 出厂由谁决定 | 模组有没有这个 pin |
|---|---|---|
| 阈值档位（8 档） | 外部 pin（`0x6e` bit6=0） | ❌ 没引出 |
| 延时（3 档） | 外部 delay pin（`0x45` bit0=0） | ❌ 没引出 |
| 工作模式 | 外部 burst_en pin（`0x6c` bit6=0） | ❌ 没引出 |

**模组只有 5 个脚**（`V / G / SCL / SDA / O`），这三路 pin 一个都没引出来，模组内部把它们绑成了什么**未知**。
所以「不配置」等于把三个关键参数交给一个未知量。

而「配置」这件事本身还有一个隐蔽的坑：**写进去可能不生效，但回读是对的**。
例如写完 `0x0f=70` 之后回读仍然是 70（I2C 通路完全正常），芯片却仍在用 pin 档位的阈值——
现场表现就是「**参数改了没反应**」，极容易被误判成「芯片坏了」或「线松了」。

我们的应对是把它做成**结构性保证**，而不是靠人记住：

1. **写顺序**：`0x6e`（阈值走寄存器）排在 `0x0f/0x10`（阈值本身）之前；
2. **单独日志**：每次启动打一行 `ctrl 0x6c=… 0x6d=… 0x6e=… 0x45=… (thr_reg=… delay_reg=… mode_reg=…)`；
3. **编译期断言**：三个控制位必须为 1、三个字节的默认值必须分别是 `0xD3`/`0xF8`/`0xE8`，改坏了**构建直接失败**
   （已做负控验证：把 `0x6e` bit6 改成 0 → `static assertion failed`）；
4. **13 字节回读校验**：不一致就逐条打印 `CFG_MISMATCH`，让人一眼看出是哪一字节没进去。

于是「每次上电重配」这几十毫秒不是开销，而是**把一颗不确定状态的芯片带回已知状态**的固定动作。
这正是这个 demo 最有价值的地方——**它不是一个「读传感器」的 demo，而是一个「配置并持守配置」的 demo。**

顺带一个反直觉的结论：**软复位不改变已写寄存器内容**（手册明写）。
所以「复位→释放→写全配置→回读→开中断」这个顺序，在「复位会清空」和「复位不清空」两种理解下**都正确**
（后一种情况下重复写是幂等的，回读还能顺带验证写入通路）。固件因此不做分支，固定一个顺序。

### 3. ULP 与距离的取舍：一个约 100 倍的电流换一个约 3 倍的距离

这是本项目最有数据的一条结论。同一颗模组、同一套接线、同一安装位置，**只改工作模式与阈值**：

| 配置 | 阈值 | 实测触发距离 | 电流量级 |
|---|---|---|---|
| ULP 模式（`0x6c=0xD3`） | 300 | 需贴很近 | **78~341 µA** |
| ULP 模式 | 115 | **≈30 cm** | 同上 |
| **常规模式（`0x6c=0x53`）** | **70** | **≥1.0 m** | **≈26 mA** |

**结论：探测距离由占空比决定，不由阈值决定。**
ULP 是 burst / duty-cycle 扫描——它把平均电流压到 µA 级，代价就是探测距离被占空比直接压掉；
阈值只是在「已经能测到的距离」上调灵敏度，**改不了天花板**。

于是门锁产品的选择变成一道很直白的题：

| 产品形态 | 该选哪档 | 代价 |
|---|---|---|
| **常供电**（有线/电池可充电、或门锁本来就有常电） | **常规模式** | ≈26 mA 量级，续航要按主电源重新算 |
| **纯电池、要求 µA 级静态** | ULP 模式 | 只能接受 **≈30 cm** 的近距离方案 |

> 🚫 **本文不给任何「能用几个月」的数字。**
> 原因不是谦虚：模组规格书写「常规 &lt;55 µA」，芯片手册写「常规 ≈26 mA」，**两份资料差 3 个数量级**，
> 而且**两份都没有给峰值/启动浪涌**。续航还取决于电池容量、占空比策略、唤醒频率与整机静态电流——
> 这些在本 demo 里**一项都没实测**。谁现在给你一个续航数字，都是编的。

### 4. 抗误触发的闭锁设计：比调阈值更直接的一道工程手段

调阈值是「降低灵敏度」，会影响该响的时候响不响；
**闭锁（lockout）是「同一件事只算一次」**，它不改灵敏度，只改「重复计数」的行为。

本 demo 的时序是这样的：

```text
检测到运动 → OUT 拉高 → 高电平保持 = 芯片 delay（默认 2000 ms）
                                    ↓ 期间若又检测到运动 → 定时器重新装满（二次触发顺延）
OUT 回落 → 闭锁开始计时（芯片 lockout，默认 2000 ms）
                                    ↓ 闭锁期内再检测到运动 → 不产生新事件
闭锁结束 → 可以再次触发
```

**实测验证**：0.5 s 间隔连挥 3 次 → **只记 1 次事件**；1.0 m 处 22 s 内 3 次触发，
间隔 6.4 s / 8.1 s，均 ≥ `delay + lockout` = 4 s，**0 次违例**。

两个必须说清的细节：

- **高电平宽度会大于 `delay`**：实测 2368 / 3198 / 3845 ms，都大于 `delay=2000`。
  这不是误差，是**二次触发顺延**——人手一直在门前动，定时器就一直被装满。
  门锁场景下这是想要的行为（人还在，灯就别灭）；要「到点必灭」，手册里 `0x32` bit6 有关二次触发的位。
- **灯的定时在芯片里，不在 MCU 里**：固件只做「电平 → 灯」的映射，不做任何软件定时。
  所以「灯和 OUT 同步」是结构性正确，不依赖定时精度。

### 5. 一个必须丢弃的时间窗：上电自检期 OUT 恒高 3 秒

芯片上电自检时 **OUT 会强制为高约 3000 ms**（`0x3c/0x3d` 默认 `0x0bb8`）。
如果不处理，设备每次上电都会报一次「有人」——门锁场景下这是「一上电就开锁」的级别。

固件的处理：**自检窗口内丢弃所有事件**，窗口结束打一行 `SELFCHECK done level=… dropped=…`。
两个容易做错的点：

1. **窗口起点是「模组上电」**（IO14 拉高那一刻），**不是「配置写完」**——芯片自检是它自己上电后开始的，
   从「配置写完」起算等于把自检的最后一段暴露成误触发；
2. **`RESET` 命令要重开窗口**，因为软复位同样会重跑芯片内部自检。

另外固件还给 IO2 定了三条纪律：**只配输入 + 内部上拉、从不 `gpio_set_level()`、
先配引脚再给模组上电**。因为 IO2 是 C6 的 strapping 关注脚，而模组没上电时 OUT 是高阻——
先给上拉才能让该脚从第一刻起就有确定电平（高 = 无触发），既不会浮空乱跳，也不会在 strapping 采样窗口里悬空。

|---|---|
| **仍有 4 项未验证** | 电池供电续航（**无数字，两份资料矛盾**）、30 分钟长稳（最长 22 s）、深睡唤醒（未实现）、外置上拉下 400 kHz（未做） |
| **本型号无光敏** | 型号 `EDX106-N-01`，`N = 无光敏`；`0x6c` bit4（关光敏）在本型号**无实际作用**，写 1 属兼容保留。「白天/夜晚不同策略」做不了 |
| **模组没有 delay / burst_en / 阈值档位 pin** | 三路 pin 全部没引出，芯片内部绑成什么未知；本方案靠强制切寄存器**规避**这个未知量 |
| **只给「有人/无人」，不给距离与坐标** | OUT 是单比特电平。要距离/速度/轨迹请换带数据接口的模组 |
| **「有人」是运动感应，不是存在感应** | 10.5 GHz 多普勒测运动；人坐着完全不动可能不触发（本次未专项实测） |
| **10.5 GHz 穿透极差** | 金属完全挡死；玻璃、陶瓷、金属拉手不能挡在天线前；与金属平面保持 5~12 mm，前方必须塑胶 |
| **怕电源纹波** | 手册要求 ≤50~100 mV，超标会误报；本 demo 用 PC 的 USB-C，未实测纹波值 |
| **`SET` 不落 NVS** | 运行期调参**复位即失效**；固化要改默认配置并重新构建烧录 |
| **只做在线监测 + 亮灯** | **未实现**深睡唤醒与锁体驱动；触发只是一个电平事件，怎么用由产品侧决定 |
| **走 H3 就不能同时接其它雷达** | 与 EDV11P / EDV163 共用 IO4/IO5 |
| **不承担安全/控制责任** | 触发信号**未经功能安全评估**，不可直接驱动锁体、门禁联锁等有安全后果的执行机构 |
