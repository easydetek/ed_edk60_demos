## 四、双向通路验证（P1-05 的关键反证）

| 实验 | 操作 | 结果 | 结论 |
|---|---|---|---|
| 反向探测 | 发 `SET 0x10 = 0`（停上报），帧 `45 44 00 0D 31 01 A1 10 00 02 00 00 7B` | 数据流 1.5 s 703 字节 → 3 s **39 字节**；且收到应答 `45 44 00 0D 31 01 A2 10 00 02 00 00 7C` | **PC → 桥 → 雷达 RX 通路有效**，雷达执行了 SET |
| 恢复 | 发 `SET 0x10 = 2`，帧 `45 44 00 0D 41 01 A1 10 00 02 00 02 8D` | 1.5 s 恢复 **446 字节** | 恢复成功 |

> **P1-05 判定**：`IO5 → 雷达 RX` **实测可用**（功能级反证成立）。`H3-A` 到底是 IO0 还是 IO5 的文档冲突，已由功能证据压倒，**不构成阻断**（但仍建议提 ECN 清理 pinmap 描述）。
> 附带教训：手算校验和极易出错。首轮 GET 无应答的真实原因是**我手算的 CS 错**（例如 `GET 0x02` msgid `21 01` 正确 CS 应为 `0x58`，我发了 `0x35`）。联调必须用程序化组帧。

**WARN 来源说明（1 字节，可解释、非缺陷）**：
未归属字节为捕获文件**最后一个字节 `0x45`**（偏移 530971/530972）。采集脚本在 1800 s 到点时于帧中间关闭串口，导致末帧被截断；帧校验器将其归为 `tail_garbage`。这是**采集边界效应**，不是设备/固件行为，也不是丢帧（坏帧 0、重同步 0）。
→ 后续采集脚本可改为「到点后先读完当前帧再关端口」，把该字节也消掉。

> **洁净性结论**：稳态 30 分钟内 **0 个非协议字节**（除末尾 1 字节采集截断），无任何固件文本 → `LOG_DEFAULT_LEVEL_NONE + 关横幅/引脚表 + 源码零 printf + 运行期 ESP_LOG_NONE` 四道保险**实测有效**，R1（控制台污染，原 R=20）可关闭。

## 七、现场处置记录

1. `build_all.ps1 -Demo …` 在 IDF 6.1 下会因 Kconfig 的一条 stderr `NOTE`（`BT_NIMBLE_MESH_PROVISIONER`）被 `$ErrorActionPreference='Stop'` 当成异常中断（**脚本级缺陷，P2**）；本轮改用 `idf.py` 直调绕过。已修（R13）：`Invoke-OneDemoBuild` 内临时 `$ErrorActionPreference='Continue'`，成败只认 `$LASTEXITCODE`。
2. 沙箱限制：`idf.py` 需通过命名管道捕获子进程输出，受限模式下报 `WinError 5`；已在全权模式下完成构建。
3. 采集脚本若含中文注释，PowerShell 5.1 按 ANSI 解码会解析失败 → 采集脚本改为纯 ASCII。
4. **网页工具「连接串口」按钮永远置灰（P0 级用户体验缺陷，已修）**：
   - 现象：用户打开页面后找不到可点的地方，按钮灰色不可用。
   - 定位：无头 Edge 读 DOM 得 `btn-connect disabled=""`；再用探针页确认 `navigator.serial` 实际存在（`typeof = object`）、`isSecureContext = true`。
   - 根因：`state.serialSupported` 初值为 `false`，代码**只在"不支持"分支赋 false，从未赋 true** → `updateButtons()` 里 `disabled = ... || !state.serialSupported` 永真。
   - 修复：`state.serialSupported = ('serial' in navigator);`（显式置位），并同步 `release/track.html`、`release/edv11p/track.html`、文档站 `static/edk60/edv11p/track.html`。
   - 验证：无头 Edge dump 后 `btn-connect` 不再带 disabled；文档站 `docusaurus build` 0 error，产物内 `track.html` 含修复代码。
   - 教训：**"能力检测"必须双向赋值**；此类缺陷静态检查与"页面能打开"都发现不了，只有人点一次才暴露。
5. `build_all.ps1` 的 `Write-DemoConfig` 曾用带 BOM 的 UTF-8 写 defaults，IDF 的 kconfgen 报 `ignoring malformed line`（仅注释行被忽略、CONFIG 仍生效）；已改为无 BOM 写入。
6. `build_all.ps1` 编辑后丢失 UTF-8 BOM 会导致 PowerShell 按 ANSI 解析、整个脚本语法崩（实测）；改完必须复核 BOM 与 `parse errors = 0`。

### 8.1 背压计数器读数（闭合 Gate-2 P1-03）

此前"零丢字节"只有代码与设计依据，**从未读出过数值**。本轮为此给固件加了一个默认关闭的取证开关
APP_EDK60_EDV11P_STATS_VIA_USB（把诊断/统计改从 USB 输出，故意制造可测量的污染），编出取证固件后采集 60 s：

| 采样 | radar→PC | 批数 | uart 溢出 | FIFO 溢出 | 帧错误 | USB 写失败 | USB 丢弃 | USB 短写 |
|---|---|---|---|---|---|---|---|---|
| 12 次（每 5 s） | 累计 **14,653 B** | **553** | **0** | **0** | **0** | **0** | **0** | **0** |

→ 「uart_rx_overflows == 0 且 usb_tx_dropped == 0」判据**成立**，且是在有真实雷达流量（≈244 B/s）的情况下测到的。
取证后已刷回静默量产固件并复验：6 s 收到 741 B、57 个帧头、**0 个非协议字节**。

> 取证过程还踩到一个真实缺陷并修掉：dbg_line 原本只把行尾 \r\n 走 USB、正文仍写 UART0，
> 导致抓回来全是空行。修正后正文与行尾都走 USB。

### 8.2 一条重要的现场行为（新增）

**模组掉电重启后不会自动上报**：实测多次出现「GET 有应答、但没有任何  x70 帧」，
而回读  x05 已是 1、 x10 已是 2；**发一次 SET 0x05=1 后数据流立即恢复**。

影响：网页版默认只读策略下，用户连上后可能**看不到数据**。已在 recipe 的故障排查里加一条处置
（"点一次『下发配置』或手动发 SET 0x05=1 / SET 0x10=2"），并注明这是实测行为而非配置错误。
