## 三、接线（已核实，来自上板实测）

| 信号 | EDK60 侧 | 方向 | 电平 | 说明 |
|---|---|---|---|---|
| 模组 TX → MCU RX | **IO4**（H3 的 `T` 脚） | 入 | 3.3V TTL | UART1，921600 8N1 |
| 模组 RX ← MCU TX | **IO5**（H3 的 `A` 脚） | 出 | 3.3V TTL | 上位机下发的 GET/SET 帧走这条 |
| 雷达电源使能 EN | **IO14** | 出（高有效） | 3.3V | 拉高 = 3.3V_RADAR 上电；运行中不要动 |
| 橙色指示灯（丝印 `L`） | IO15 | 出 | — | 仅指示，与电源无关 |

:::warning 必须插 H3，不能插 H4
H3 = `RES A R T G V P`，H4 = `RES P V G R T A`：信号集合相同但**顺序相反**，
H4 的 `T` 与电源使能同网络，插 H4 会让电源与数据互相干扰。
:::

## 四、串口与协议要点（已核实）

| 项 | 值 |
|---|---|
| 波特率 / 帧格式 | **921600 / 8N1 / 无流控** |
| 字节序 | 大端 |
| 帧头 | `0x45 0x44`（ASCII `ED`） |
| 帧结构 | 头 2B ｜ 整包长度 2B ｜ msgid 2B ｜ op 1B ｜ type 1B ｜ TLV 长度 2B ｜ value N ｜ 校验 1B |
| 校验 | 从帧头起逐字节求和 `& 0xFF` |
| op | `0xA0` GET ／ `0xA1` SET ／ `0xA2` REPORT ／ `0xA3` STATUS ／ `0xA9` ACK |
| 关键 type | `0x05` 工作模式（**1 = 跟踪/人数统计**）／ `0x10` 上报频率（**单位 50ms**，设 100ms 时下发 `0x0002`；设 0 = 不上报）／ `0x20` 检测范围 ／ `0x21` 检测高度 ／ `0x22` 挂高 ／ `0x70` 目标上报 ／ `0xF0` 错误码 |
| `0x70` 载荷 | 重复块：`{zone_id:u8, count:u8, count × {id:u8, x:i16BE, y:i16BE, z:i16BE}}`（每目标 7 字节） |
| 上位机启动动作 | 连上 100ms 后 `GET 0x02`，随后批量 GET/SET；**无文本握手** |

> **已裁决的事实纠正（2026-10-21，以代码与文档实测为准）**
> 1. **上报频率单位是 50ms**，不是 10ms。证据：`EDV11P串口通用协议.md` 第 73 行「单位：50ms，设置为0时不上报」；第 164-169 行示例「设置上报间隔为 100ms」下发的值就是 `0x0002`。演示建议值 **2（=100ms）**，默认回读值 10 实际是 500ms。
> 2. **参考上位机与协议文档都是 UTF-8（无 BOM）**，不是 GBK；按 GBK 读会得到乱码（本项目曾据此走过弯路，文档里如有提及请更正）。

> 关键结论（写在正文里）：**EDK60 桥接固件不需要懂协议**——它只做字节搬运；协议配置全部由上位机发出。
> 这也是为什么本 demo 的固件代码里一行协议解析都没有（可引用源码作证据）。

## 五、坐标系与安装（已核实）

| 项 | 值 | 证据 |
|---|---|---|
| 斜装方式 | 侧装方案 A：绕 +y 倾斜 **60°**，主坐标轴俯角 **30°**，挂高 **200cm** | 参考上位机 `INSTALLATION_PROFILES['tilted']` |
| 坐标系 | **条件句（尚未验证）**：*若*模组使用的是「侧装版固件」，则固件已完成 XYZ 转换，上位机不做旋转；**该前提未经验证**（协议 0x20~0x33 无任何倾角/旋转参数，说明书要求水平安装 0°） | 参考上位机头部注释（仅说明该工具的作者假设）；反证见 `hw-wiring-and-firmware.md` §3.5 |
| 型号分支 | **未定**：需上板 `GET 0x02` 回读确认是 -02（人数统计/轨迹跟踪）还是 -03（跌倒+人存）；判定卡见 `gate-1-disposition.md` 第四节 | 发布说明幻灯片 8 + 协议 `0x70` 标注 |
| 显示口径 | x = 水平横轴 ±500cm；y = 沿地面向前 0~800cm；z = **离地高度**（0~max(200,挂高)） | 同上 |
| 检测范围默认 | x[-500,500]、y[0,800]、高[30,200] cm | 同上 |
| 朝下模式（备选） | 挂高 300cm，z = 挂高 − z_样本 | 同上 |

> 写作要点：60°/30° 是**机械安装参数**，不是软件要做的三角变换。这个边界必须讲清楚，

## 七、验证点（每步「怎么看成功」）

| 步骤 | 期望现象 | 失败先查 |
|---|---|---|
| 上电 | `RADAR` 红灯亮 | 模组是否插 H3；USB 线是否数据线 |
| PC 认到设备 | 设备管理器出现「USB 串行设备 (COMx)」（VID:PID 303A:1001） | 换线 / 换口 |
| 上位机连上 | 日志出现模块信息回读（版本号） | 端口选错；雷达没上电 |
| 开始跟踪 | 画布上出现轨迹点，人数 ≥1 | 工作模式未切到 1；上报频率为 0 |
| 走动 | 轨迹跟随人移动，方向合理 | 安装方式/挂高参数与实物不符 |
| 多人 | 人数随进出变化 | 检测范围/灵敏度设置 |

## 八、常见问题（全部来自本项目真实踩坑，可放心写）

| 问题 | 原因 | 解决 |
|---|---|---|
| 串口助手看到一片乱码 | 这是**二进制协议帧**，不是文本 | 用上位机或网页工具，别用文本模式 |
| 完全没数据 | 模组插在 H4 / 雷达没上电 / 端口选错 | 依次核对：红灯 → H3 → COM 口 |
| 有帧但没轨迹 | 工作模式还是 0（调试） | 发 `SET 0x05 = 1`（上位机自动做） |
| 轨迹整体偏移 | 挂高/安装方式与实物不一致 | 按第六节参数表核对 |
| 网页点「连接」没反应 | 用了 Firefox/Safari，或页面非 https | 换 Chrome/Edge；用线上 https 页面 |
| 偶发丢帧 | 数据流里混入了日志文本 | 用本项目固件（已关日志）；或看 `--raw-dump` |
