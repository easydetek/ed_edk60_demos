## 1. 三处必须说明的纠正（已按此实现，覆盖任务书最初描述）

任务书最初要求「移植 .py 里的斜装旋转函数（绕 +y 倾斜 60°、主轴俯角 30°）」。
逐行核对 .py 后确认：**.py 中不存在任何旋转/三角变换代码，网页端也不得做旋转。**

| # | 纠正 | 证据 |
|---|---|---|
| 1 | 坐标**不做旋转**。固件上报的 x/y/z 已是安装姿态下的坐标，上位机只做显示翻转 | .py 第 12 行注释「安装方式需与固件一致；固件 XYZ 已完成转换，本程序不重复旋转」；第 849 行「固件上报的 XYZ 已属于当前安装坐标；屏幕翻转不改变数值标签」 |
| 2 | 侧装（tilted）只定义**显示口径 + 默认值**，无旋转矩阵 | .py 第 148-153 行 `INSTALLATION_PROFILES`；第 645-656 行 `projection_bounds`；第 898-901 行 `_to_scene_point` |
| 3 | 60° 倾角 / 30° 俯角是**机械安装信息**，只写进文档，不进入任何计算 | .py 第 8-9 行 docstring；第 722-724 行仅用于在 YZ 平面画一条示意虚线（本网页只做 XY 俯视，故不绘制该虚线） |

因此 `track.html` 里的「几何参数」是：**安装方式（侧装60° / 朝下）、挂高 cm、显示范围 cm、轨迹点数**，
没有任何角度输入框、没有旋转矩阵、没有三角函数变换。

## 2. 帧结构（发送与接收同一套）

```
+--------+--------+--------+--------+------+------+----------+--------+--------+
| 0x45 44| 长度   | msg id |  op    | type | TLV长度  | value  | 校验   |
| 2B     | 2B BE  | 2B BE  | 1B     | 1B   | 2B BE    | N B    | 1B     |
+--------+--------+--------+--------+------+------+----------+--------+--------+
长度 = 整包字节数（含帧头与校验和）；校验和 = 从帧头起逐字节求和 & 0xFF
```

| 字段 | 偏移 | 长度 | 编码 | 说明 | 来源 |
|---|---|---|---|---|---|
| 帧头 | 0 | 2 | `0x45 0x44` | 固定 | 协议文档第 41 行；.py 第 90 行 |
| 长度 | 2 | 2 | uint16 **大端**，整包 | 最小 11（无载荷）、最大 4096 | 协议文档第 43 行；.py 第 257 行、第 94-95 行 |
| msg id | 4 | 2 | uint16 大端 | 1…0xFFFF，跳过 0 | 协议文档第 45 行；.py 第 338-341 行 |
| op | 6 | 1 | uint8 | 0xA0/0xA1/0xA2/0xA3/0xA9 | 协议文档第 56-63 行；.py 第 99-103 行 |
| type | 7 | 1 | uint8 | 见 §3 | 协议文档第 67-101 行；.py 第 106-137 行 |
| TLV 长度 | 8 | 2 | uint16 大端 | = 帧长度 − 11 | 协议文档第 49 行；.py 第 306-311 行 |
| value | 10 | N | 视 type | 见 §3 | — |
| 校验和 | 10+N | 1 | uint8 | `sum(bytes[0..10+N-1]) & 0xFF` | 协议文档第 52 行；.py 第 327-329 行 |

**解析器容错规则（逐条对齐 .py `feed()` 第 229-276 行）**

| 情况 | 处理 | .py 行号 |
|---|---|---|
| 缓冲区无 `0x45 0x44` | 丢弃；仅在末字节为 `0x45` 时保留该字节（可能是下一帧帧头） | 245-250 |
| 帧头前有杂散字节 | 跳过并计入 `noiseBytes` | 251-252 |
| 声明长度 < 11 或 > 4096 | 计坏帧，**只滑过 1 字节**继续找帧头 | 258-261 |
| 缓冲区不够一帧 | 等待更多数据（保留到下次拼接） | 263-264 |
| 校验和错 | 计坏帧，滑过 1 字节重新同步 | 295-298 + 268-271 |
| TLV 长度 ≠ 帧长度 − 11 | 计坏帧，滑过 1 字节 | 306-311 |
| 缓冲区 > 8192B | 丢弃旧数据，保留最后 4096B | 237-241 |
| 0x70 载荷越界（`idx+2>len` 或 `idx+count*7>len`） | 判坏帧并计数，丢弃本帧 | .py 第 390-401 行（异常路径） |

## 4. 坐标约定与几何参数

### 4.1 结论：世界坐标 = 固件上报坐标，网页不做任何旋转

| 轴 | 取值（侧装 60°） | 含义 |
|---|---|---|
| x | −500 … +500 cm | 水平方向，以模组地面投影为 0 |
| y | 0 … 800 cm | **沿地面、从墙/模组地面投影向前**，0 在墙根 |
| z | 0 … max(200, 挂高) cm | **离地高度**（侧装下 `z` 直接就是离地高度） |

- 侧装默认挂高 **200 cm**、显示范围 **800 cm** → x[-500,500]、y[0,800]。
- 朝下安装（ceiling）：x、y 均为 ±显示范围，**离地高度 = 挂高 − z**（.py 第 850 行）。

### 4.2 世界坐标 → 画布坐标

```
x0,x1,y0,y1 = projectionBounds(显示范围, 是否侧装)      // .py 第 645-656 行
侧装： x0 = -范围*5/8, x1 = +范围*5/8, y0 = 0, y1 = +范围
朝下： x0 = y0 = -范围,  x1 = y1 = +范围
s  = min((W-左pad-右pad)/(x1-x0), (H-上pad-下pad)/(y1-y0))   // 等比，不拉伸
px = ox + (x - x0) * s
py = oy + (y1 - y) * s                                    // y 向上增大，等价 .py 的 -y 翻转
```

`.py` 第 898-901 行 `_to_scene_point` 在 XY 平面下就是 `QPointF(x, -y)`，即屏幕 y 轴向下、
世界 y 向上；本网页用 `py = oy + (y1-y)*s` 得到同一效果（`+y` 画在画布上方）。

## 6. 自测用例（帧解析 + 帧构造 + 只读计划）

帧的十六进制是用 .py `create_frame()` 的等价逻辑生成的（`createFrame()`），
校验和用独立实现（PowerShell 逐字节求和）复核过，两者一致。
**C1–C6 同时内置在 `track.html` 里**（按钮「运行帧解析自测」），运行时用同一份数据做断言，
做到「文档即测试」。C1–C5 验证帧层，**C6 验证「默认只读」这一条 Gate-1 整改要求**。

### C6 — 只读计划：连接流程里不允许出现任何 SET（P1-06）

`buildReadOnlyQueryPlan()` 的返回值必须满足：

| 断言 | 期望 |
|---|---|
| 计划条目数 | 16 条（1 条模块信息 + 5 条基础 + 10 条高级） |
| 其中 `op === 0xA1 (SET)` 的条数 | **0** |
| 其中非 `op === 0xA0 (GET)` 的条数 | **0** |
| 必须包含的 type | 0x02 / 0x05 / 0x10 / 0x20 / 0x21 / 0x22 |
| 时序 | 单调不减，首条 100 ms |

配合运行期兜底：任何在 `writeBusy=false` 时发到线上的 SET 都会让 `state.unexpectedSets` 递增并打红字告警。
页面自测与离线脚本都会断言该计数为 0。

### C1 — GET 模块信息 0x02（空载荷）

```
发送帧（11 字节，msg id = 1）
45 44 00 0B 00 01 A0 02 00 00 37
                          ^^ 校验 = (0x45+0x44+0x00+0x0B+0x00+0x01+0xA0+0x02+0x00+0x00) & 0xFF = 0x137 & 0xFF = 0x37
```
期望：解析出 1 帧，`msgId=1, op=0xA0, type=0x02, dataLen=0`，坏帧 0，噪声 0。

### C2 — SET 工作模式 = 1（0x05，1 字节）

```
45 44 00 0C 00 02 A1 05 00 01 01 3F
```
期望：1 帧，`msgId=2, op=0xA1, type=0x05, dataLen=1`，载荷 `01`，坏帧 0，噪声 0。

### C3 — SET 挂高 = 200cm（0x22，uint16 大端 0x00C8）

```
45 44 00 0D 00 03 A1 22 00 02 00 C8 26
```
期望：1 帧，`msgId=3, op=0xA1, type=0x22, dataLen=2`，载荷 `00 C8`（=200），坏帧 0，噪声 0。

### C4 — STATUS 0x70：2 个感应区 / 5 个目标 / 含负数坐标

载荷（39 字节 = 0x27，整包 50 字节 = 0x32）：

完整帧：

```
45 44 00 32 00 31 A3 70 00 27
01 03 02 FF 88 00 6F 00 95
03 FF E4 00 26 00 CB
04 00 24 FF 48 00 C7
02 02 05 FF F0 00 5E 00 B0
06 FF 75 FF 4A 00 D3
```

|---|---|---|---|---|---|

### C5 — 重同步：3 字节噪声 + 好帧 + 坏校验和帧 + 好帧

```
输入字节流：
00 11 22                                          ← 前导噪声（无帧头）
45 44 00 0C 00 02 A1 05 00 01 01 3F               ← 好帧（=C2）
45 44 00 0C 00 09 A1 05 00 01 01 00               ← 校验和故意写 0x00（正确应为 0x46）
45 44 00 0B 00 01 A0 02 00 00 37                  ← 好帧（=C1）
```

期望：

| 指标 | 期望值 | 说明 |
|---|---|---|
| 解析出的帧 | 2 帧：`type=0x05 msgId=2`、`type=0x02 msgId=1` | 坏帧被丢弃且不影响后续帧 |
| 坏帧计数 | 1（校验和错） | 计入状态条「坏帧」 |
| 丢弃字节数 `noiseBytes` | 14 | 3 字节前导噪声 + 坏帧被打断后滑过的 11 字节 |

> 说明：`noiseBytes` 统计的是「被同步逻辑丢掉的字节」，坏帧整段也会因重新同步被滑过，
> 因此是 14 而非 3。这是有意保留的语义（与 .py 的「滑过 1 字节找回帧头」一致）。

## 7. 界面与行为设计

### 7.1 连接后自动执行的动作：**只读查询，零写入**（P1-06 整改后）

| 时刻（连接成功起） | 动作 | .py 对照 |
|---|---|---|
| +100 ms | `GET 0x02` 模块信息 | 第 1867 行 |
| +300 ms 起，每 50 ms | `GET 0x05 / 0x10 / 0x20 / 0x21 / 0x22` | 第 2993-3010 行 |
| +550 ms 起，每 50 ms | `GET` 高级配置 10 条（0x23/0x24/0x25/0x26/0x27/0x28/0x29/0x2A/0x2F/0x33） | 第 3012-3044 行 |
| —— | **连接流程到此为止：一条 SET 都不发** | Gate-1 P1-06 |

- 查询计划由纯函数 `buildReadOnlyQueryPlan()` 生成（16 条，全部 `op=0xA0`），
  自测用例 **C6** 会断言其中不存在任何 `op=0xA1`，并且界面从未自动触发写入。
- 连接后界面显示的「设备回报」「当前回读」全部来自设备应答；设备没回读的项显示「未回读」，
  **不做任何默认值推断**。

### 7.4 写入路径（唯一会发 SET 的入口，P1-06）

```
用户点「下发配置…」或「演示用一键配置」        ← 只有这两个入口
   ↓ 按钮上方固定警示：将改写雷达模组当前配置（工作模式 / 挂高 / 上报频率）
   ↓ window.confirm() 二次确认（列出将要写入的三项 目标值）
   ├─ 取消 → 一条帧都不发，日志记「已取消」
   └─ 确定 → 逐条发送，**逐条等待应答**：
        SET 0x05 工作模式  ─→ 等 0xA2 REPORT 或 0xA9 ACK
           ↓ 收到应答后静默 50 ms（有应答才计时，不是固定间隔盲发）
        SET 0x22 挂高      ─→ 等应答
           ↓
        SET 0x10 上报频率  ─→ 等应答
```

| 约定 | 实现 |
|---|---|
| 应答匹配 | 事务表 `pending: msgid → {type}`；**msgid 优先**，设备未回显 msgid 时**退化为按 type 匹配** |
| 超时 | 单条 **500 ms**（`CFG.write.timeoutMs`）无应答即中止 |
| 失败处理 | 中止并把失败项写进侧栏时序日志 + 主日志，**后续项不再发送**；`pending` 清零、按钮恢复 |
| ACK 错误码 | `0xA9` 且 `code≠0x01` 时按 `ACK_MESSAGES` 显示中文原因（帧头错误/校验和错误/不支持的命令/参数错误） |
| 运行期兜底 | 若在 `writeBusy=false` 状态下发出 SET，`state.unexpectedSets++` 并在日志打红字告警（正常应恒为 0） |
| 离线演示 | 模拟模式内置「模拟设备」：会按协议格式应答 GET、按新值回显 SET（40 ms 时延），因此无硬件也能演示完整时序 |

### 7.2 渲染

- 画布：俯视 XY，等比缩放、不拉伸；网格步长按 1/2/5/10×10^k 自动选取（同 .py）。
- 目标：20 cm 半径圆 + 火柴人 + 3 行标签（`#ID Z区号` / `XYZ` / `离地 xx cm`），标签自动避让边缘。
- 轨迹：每目标 50 点虚线拖尾，颜色 = `palette[id % 24]`。
- 目标消失（500 ms 无更新，或新帧里没有它）：轨迹转入淡出队列，1.5 s 内渐变消失（**D3**，.py 是直接删）。
- 状态条：串口、连接状态、帧率（近 1 s 的 0x70 帧数）、坏帧数、当前人数、累计出现人数、最后上报时间、收字节。
- 侧栏：当前目标表（含离地高度）、设备回报（模块信息/工作模式/频率/挂高/检测范围/检测高度/区数量/ACK）。
- 日志：折叠面板，每条含 `收/发/模拟` 标记 + 十六进制（超 64 字节截断）+ 解析摘要，最多 400 行，可暂停/清空。

### 7.3 模拟演示（无硬件验收用）

**不产生假数据绕过管线** —— 而是构造**合法的 0x70 字节流**再喂给同一个解析器：

```
4 个目标的合成坐标
  → buildTargetPayload() 打包成 zone 区块字节
  → createFrame(0xA3, 0x70, payload) 生成带正确长度与校验和的真帧
  → state.parser.feed(frame)（与串口完全相同的入口）
  → handleTargetReport() → 同一套渲染 / 日志 / 统计
```

| ID | 感应区 | 路径（t 为秒） | 作用 |
|---|---|---|---|
| 1 | 1 | `x = -380 + 35·sin(0.5t)`；`y = 60 + 560·‖((0.055t) mod 2) − 1‖`；`z = 100 + 18·sin(0.9t)` | 沿 y 轴往返走动（近墙↔远墙） |
| 2 | 1 | 圆心 (250, 400) 半径 165 的圆，`θ = 0.62t`；`z = 105 + 22·sin(1.3t)` | 绕圈（演示转向） |
| 3 | 1 | 李萨如：`x = 330·sin(0.42t)`，`y = 420 + 270·sin(0.77t + 1.0)`；`z = 95 + 30·sin(0.55t + 2.0)` | 覆盖画面中部的交叉轨迹 |
| 4 | 2 | 每 16 s 内出现 9 s：`x = -60 + 70·sin(0.8t)`，`y = 720 − 40·(cyc/9)`，`z = 150 + 25·sin(0.6t)` | **定时出现/消失 → 演示人数 4↔3 变化与轨迹淡出** |

- 每 100 ms 一帧（模拟固定周期，不受「上报频率」输入影响）；坐标裁剪到 x∈[−499,499]、y∈[1,799]、z∈[31,199]。

## 10. 设计决策记录

| 编号 | 决策 | 理由 |
|---|---|---|
| ~~D1~~ **已废止（Gate-1 P1-06）** | ~~连接后自动下发工作模式/挂高/上报频率~~ | 原为「连上就能看到数据」；但自动 SET 会改写用户设备配置、且不等应答，违反协议「Get/Set 异步、由 Report 回复」的约定。**已改为只读，见 D9** |
| D2 | 0x70 同时接受 0xA3 与 0xA2 | 见 U2；多一条分支的代价小于漏帧的风险 |
| D3 | 目标消失后轨迹淡出 1.5s | 任务明确要求「目标消失后轨迹淡出」；比 .py 的立即删除更利于线上演示 |
| D4 | 多感应区重复目标只保留一份（同 .py） | 重叠感应区会重复上报同一 ID，去重后人数才正确 |
| D5 | 模拟模式也走「造真帧 → 解析器」而非直接塞结构体 | 才能同时验证帧构造、校验和、解析、渲染整条链路，且日志里看到的是真十六进制 |
| D6 | 解析器用偏移指针而非每次 slice 缓冲区 | 921600 波特率下每秒可达数千字节，避免频繁分配；行为与 .py 逐字节等价（已用「逐字节喂入」用例验证） |
| D7 | 不使用 localStorage 保存任何参数 | 任务约束「不使用 localStorage 存敏感数据」，干脆一个都不存 |
| D8 | 上报频率默认值取 **2（=100ms）**，所有默认值集中到 `CFG.defaults` | U1 已裁决为 50ms/单位（协议文档第 73、164-169 行）；把默认值收进 `CFG.defaults` 后，HTML 初值与脚本里的 `clampInt` 兜底只有一个来源，避免再出现「页面写 10、脚本兜底写别的」这类自相矛盾 |
| **D9** | **默认只读**：连接后只发 GET；写入必须「显式按钮 + `confirm()` 二次确认」 | Gate-1 P1-06。工具是给客户看演示/排障的，不应替用户改设备配置；把写入收敛到唯一入口后，可审计、可回滚（不点即不改） |
| **D10** | 写入**逐条等应答**（0xA2/0xA9，msgid 优先、type 兜底），单条 500 ms 超时即中止 | 协议文档第 107 行「Get/Set 采用异步模式，接收方使用 Report 回复」。固定间隔盲发会在设备忙时静默丢命令，且失败不可见 |
| **D11** | 加运行期兜底：非确认流程里发出 SET 会 `unexpectedSets++` 并红字告警 | 让"未来某次改动又偷偷发 SET"这件事在自测与运行时立刻暴露，而不是等评审发现 |
