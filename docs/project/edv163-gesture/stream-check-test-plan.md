# 流校验测试计划 — EDK60 × EDV163 手扫（挥手识别）Demo

> 2026-10-23 ｜ 测试工程师（opcs-test-engineer）｜ 对应计划 `docs/project/edv163-gesture/plan.md` §六 验收判据
> 被测工具：`tools/edv163_gesture_check.py`（本计划所有数值由该脚本自动产出，人工只负责组织场景）
> 产物目录：`logs/edv163-gesture/`

---

## 一、这份计划要证明什么

EDK60 固件对本 demo 是**纯字节透传桥**：UART 115200 收、原生 USB CDC 发，中间不解析、不改写。
因此「桥有没有丢字节、文本行是否完整、混杂的二进制帧是否被正确整帧跳过」**无法从固件侧证明**，
只能由 PC 侧对同一条字节流做客观统计：

| 要证明的命题 | 统计口径 | 判据 |
|---|---|---|
| 桥没丢字节、没改写字节 | 字节守恒：总收字节 = 文本行字节 + 二进制帧跳过字节 + 无法归属字节（差额必须为 0） | 恒等式（工具内建，报告 `byte_accounting`） |
| 设备在正常节奏输出 | 文本行率 | P1 |
| 文本行没有被污染/切碎 | 坏行率 + 行间隔空档 | P2 / P5 |
| 二进制帧被整帧跳过、没吃掉文本 | 校验通过率 + 长度非法数 + 「帧区间含换行」告警 | P3 / P4 |
| 数据语义合理（挥手/坐标/触发） | target 比例、坐标护栏、action 值域、触发事件 | P6 / P7 / P8 / P9 |

**前提**：本 demo 没有协议文档，格式唯一来源是厂商上位机源码 `gesture_monitor.py`（755 行，含正则与
`MixedStreamParser`）+ 同目录 `README.md`。工具内的六条正则逐字照抄该源码，顺序也一致
（`DBG` 的 wave/depth 变体必须先于通用 `action=` 变体尝试）。

## 二、判定阈值表（含来源，可直接辩护）

阈值全部写在 `tools/edv163_gesture_check.py` 的 `THRESHOLDS` 常量里，`--help` 与报告打印的是**同一份**数值
（不存两处口径）。下表「来源」列就是每个数字的辩护理由。

| ID | 判据 | 阈值 | 来源 / 辩护理由 |
|---|---|---|---|
| P0 | 有效 GESTURE 行数 | ≥ 1 | 前提而非标准：一行合法的 GESTURE 都没有 = 采集无效，其余判据无意义。此时先查波特率/接线，别急着看别的 |
| P1 | 文本行率 | **5.0 ±20% → 4.0~6.0 行/秒** | 标称来自固件「约每 200 ms 一行」（上位机模块 docstring 与 README §串口协议）。±20% 用来吸收：二进制帧抢占同一 UART 带宽、USB CDC 的批量聚合与主机读抖动、以及行被二进制帧边界切分时的计数损失。**不含**「固件改了输出周期」——那属于规格变更，必须同时改阈值并走 ECN |
| P2 | 坏行率 | **< 1%** | 计划 §六 与风险 G1 的既定口径。绝对量换算：10 分钟 × 5 行/秒 = 3000 行，1% = 30 条。干净固件应为 **0**；1% 是「容错上限」而不是目标——超过就说明日志/格式在**持续**污染，不是偶发 |
| P3 | 二进制帧校验通过率 | **= 100%** | 校验和是「这一帧在线路上没被破坏」的唯一证据。分母只算「长度合法、能确认是帧」的帧；纯文本流（没有二进制帧）记 N/A，不算缺陷 |
| P4 | 长度非法帧数 | **= 0** | 长度字段合法区间 11~4096 来自厂商 `MixedStreamParser`（MIN/MAX_BINARY_FRAME）。出现非法长度 = 流里有假帧头（污染）或切帧错位，两种都必须查清 |
| P5 | 行间隔 > 1 s 的空档次数 | **= 0** | 200 ms/行 → 1 s 空档 = **连丢 5 行以上**。USB 重枚举、固件卡顿、解析吞行都会表现为这种「成段空档」，比平均行率更灵敏（平均值能把一次断流摊平） |
| P6 | target=1 比例 | 挥手场景 **≥ 50%**；静置场景 **≤ 10%**；`auto` 不判定 | 语义来源：`target=1` = 10 帧位置窗已形成。挥手场景手在视场内且要做动作，大部分时间应有有效目标；静置场景无人时偶发误检不应超过 10%。**故意不设万能区间**：一个场景一个口径，`--expect-hand auto` 只报告 |
| P7 | 坐标越界行数 | **= 0**（护栏 `\|x\|,\|y\| ≤ 1.00 m`、`0 ≤ z ≤ 2.00 m`） | 厂商界面显示范围是 X/Y ±0.40 m、Z 0~1.00 m（README §位置图）。这里放宽 **2.5 倍** 做护栏：只挡「小数点跑掉、字段串位、NaN/Inf」这类明显错位，不挡真实边界值 |
| P8 | 未知 action 值频次 | **= 0** | 合法值域 -2/-1/0/1/2（挥手）+ -3/+3（靠近/远离）。厂商界面会把越界值**静默当「无挥手」**，所以必须由工具抓出来（固件改编码/字段串位的唯一线索） |
| P9 | 距离触发事件数 | 挥手场景 **≥ 1 次**；静置场景 **= 0 次**；`auto` 不判定 | 触发规则照抄厂商界面：`target=1 且 z < 阈值`，**严格小于**，等于阈值不触发。`--threshold-cm` 默认 20（与厂商 Spinbox 默认值一致，范围 0~100） |

**N/A 与观察项不阻断**：没有时间基准（`--file` 未给 `--duration`）时 P1/P5 记 N/A；
纯文本流时 P3 记 N/A；`--expect-hand auto` 时 P6/P9 记 N/A。
观察项（不进 PASS/FAIL，但必须写进 Gate 记录）：DBG 行出现、空行、流尾半行、
帧区间含换行、重同步次数、无法归属字节段里的日志特征串、行间隔中位数偏离 0.2 s 超过 ±40%、
采集时长不足计划 90%。

## 三、用例集

优先级：**P0 = 上板必做、阻断放行**；P1 = 应当做；P2 = 有风险时补做。

### T-GS-01 30 分钟静置（无人挥手）｜P0

| 项 | 内容 |
|---|---|
| 目的 | 证明长时间连续输出不丢行、不空档、不误污染；并给「无目标」基线 |
| 前置 | ① EDV163（挥手固件）插在 **H3**；② 固件为手扫 demo（115200 透传）；③ 雷达前方 1 m 内**无人、无移动物体**（关空调扫风）；④ PC 串口空闲 |
| 命令 | `py -3 tools\edv163_gesture_check.py --port COM6 --baud 115200 --duration 1800 --expect-hand absent --save-raw logs\edv163-gesture\idle30.bin --raw-dump` |
| 观察指标 | P1 行率、P2 坏行率、P5 空档次数、P6 target=1 比例、P9 触发事件、字节守恒差额、重同步次数 |
| 通过标准 | 退出码 **0**；**P0~P9 全部 PASS 或 N/A**；坏行 = 0（最差 < 1% 且每条都能解释）；空档 = 0 次；target=1 比例 ≤ 10%；触发事件 = 0；`unaccounted_bytes` = 0；实测时长 ≥ 1620 s（90%） |
| 证据留存 | `logs/edv163-gesture/edv163_gesture_check_<ts>.json` + `.log`、`idle30.bin`、`unattributed_*.bin`（若有）、Gate 记录里贴 P0~P9 表格截图/文本 |
| 失败处置 | 有坏行 → 看 `bad_samples` 与 `unattributed_*.bin`，先判「是不是固件日志」（G1）；有空档 → 查 USB 是否重枚举（换口/换线复测）；target=1 比例高 → 查安装位置抖动/反射物 |

### T-GS-02 10 分钟持续挥手（四方向各 ≥20 次）｜P0

| 项 | 内容 |
|---|---|
| 目的 | 证明「挥手场景」下文本流完整、动作编码覆盖全部方向、坐标与触发合理 |
| 前置 | 同 T-GS-01 的 ①②④；操作者站在雷达正前方 **z≈0.2~0.8 m**（计划 §七 推荐站位）；对 **左/右/上/下** 各挥 **≥20 次**，间隔 1~2 s，全程录像（用于事后核对方向） |
| 命令 | `py -3 tools\edv163_gesture_check.py --port COM6 --baud 115200 --duration 600 --expect-hand present --threshold-cm 20 --save-raw logs\edv163-gesture\wave10.bin --csv logs\edv163-gesture\wave10_lines.csv --raw-dump` |
| 观察指标 | P1/P2/P3/P5（流完整性）+ P6 target=1 比例 + P8 未知 action + action 分布 `-2/-1/0/1/2` + CSV 的 action 时间戳序列 |
| 通过标准 | 退出码 **0**；P0~P5、P7、P8 全部 PASS；P6 target=1 比例 ≥ 50%；`wave` 表里 **-2/-1/1/2 四个非零方向各 ≥ 20 次**（与人工计次对照，误差 ≤ 10%）；未知 action = 0；**人工抽检 10 条 CSV 行，方向与录像一致** |
| 证据留存 | JSON/LOG、`wave10.bin`、`wave10_lines.csv`、录像、人工计次表（方向×次数） |
| 失败处置 | 某方向次数不足 → 手势幅度/站位问题（G5），先调站位复测 3 次再判固件；没识别出方向但 target=1 正常 → 交硬件/算法侧；出现 `±3` → 正常（靠近/远离），不算方向错 |

### T-GS-03 阈值触发对照（z 在 15~25 cm 之间移动）｜P0

| 项 | 内容 |
|---|---|
| 目的 | 证明「触发」判据（`target=1 且 z < 阈值`）与 z 读数一致，且等于阈值不触发 |
| 前置 | 同 T-GS-02；准备一把尺/卷尺，地面标 15 cm / 20 cm / 25 cm 三条线 |
| 步骤 | 手依次停在 **25 cm → 20 cm → 15 cm**，每档保持 ≥ 5 s，重复 3 轮；每轮换档时记录时刻（手机秒表或口头打点） |
| 命令 | 同 T-GS-02，但改 `--threshold-cm 20`（默认）并保留 `--csv`；离线可复算：`py -3 tools\edv163_gesture_check.py --file logs\edv163-gesture\wave10.bin --duration 600 --threshold-cm 20 --csv logs\edv163-gesture\wave10_t20.csv`（再用 `--threshold-cm 18` / `22` 复算两遍做灵敏度对照） |
| 观察指标 | `trigger.triggered/not_triggered`、`trigger.onset_preview`（触发时刻 + 当时 z）、CSV 的 `z_cm` 与 `triggered` 列 |
| 通过标准 | ① 25 cm 档：`triggered=0`；② 15 cm 档：`triggered=1`；③ 20 cm 档：**z 读数 < 20.0 时触发、≥ 20.0 时不触发**（严格小于，逐行核对 CSV）；④ 触发时刻与换档时刻偏差 ≤ 1 s；⑤ 三档 z 中位数单调（25 > 20 > 15，容差 ±3 cm） |
| 证据留存 | 三个阈值的 CSV + JSON、视频、尺子标注照片 |
| 失败处置 | 触发与 z 对不上 → 先确认没混用旧 capture（看 JSON `thresholds`）；z 读数整体偏移 → 安装角度/模组差异，记入风险而非判工具错 |

### T-GS-04 混流压力（同时有点云二进制帧时文本是否仍完整）｜P1

| 项 | 内容 |
|---|---|
| 目的 | 验证 G3：二进制帧与文本混在同一流时，帧界判断错会让后续文本全乱。本用例专门盯「帧跳过之后文本是否恢复」 |
| 前置 | 同 T-GS-02；尽量让人在视场内**做小幅移动**（促使固件输出点云帧），持续 10 分钟 |
| 命令 | 同 T-GS-02（`--raw-dump` 必开） |
| 观察指标 | `binary.frames_ok / frames_checksum_error / frames_len_invalid / bytes_skipped`、`binary.frame_swallowed_newline`、P2 坏行率、P3、P4、`unattributed.segments` |
| 通过标准 | `frames_ok ≥ 1`（**证明真的存在混流**，否则本用例无效，需补测）；P3 = 100%、P4 = 0；坏行率 < 1% 且**没有任何坏行紧跟在帧之后**（对照 `bad_samples.line_no` 与帧偏移）；`frame_swallowed_newline = 0`；`unaccounted_bytes = 0` |
| 证据留存 | JSON（`binary.detail` + `unattributed.segments`）、`--raw-dump` 落盘的 `unattributed_*.bin` |
| 失败处置 | 有帧但坏行紧跟其后 → 帧跳过长度算错（切帧 bug），把该段 `.bin` + 偏移交给嵌入式侧；`frames_ok = 0` → 本用例未生效，标注「未验证」而不是「通过」 |

### T-GS-05 无硬件自测（CI 门槛）｜P0

| 项 | 内容 |
|---|---|

## 六、已知边界（必须写进 Gate 记录，避免过度解读结论）

1. **这是文本协议，任何固件日志都会直接污染「数据行」**——比二进制协议脆弱得多。
   二进制协议里一条日志只是垃圾字节，帧边界仍然可靠；文本协议里一条 `printf` 会变成一个**坏行**，
   甚至把相邻的 GESTURE 行切断成两条坏行。所以：
   - 工具只能**检测**污染（坏行率、重同步次数、垃圾段里的日志特征串），**不能预防**；
   - 根治手段在固件侧（零 `printf`，沿用前两个 demo 的四道静默保险）；
   - 一旦坏行率 > 1%，先怀疑日志/格式，不要先怀疑雷达。
2. **没有协议文档**。格式、编码、容错策略一律以厂商上位机源码 `gesture_monitor.py` 为准
   （见其 `GESTURE_RE` / `DUAL_GESTURE_RE` / `DBG_*` 与 `MixedStreamParser`）。固件版本一变，
   格式就可能变（风险 G2）：工具同时支持正式格式、旧格式 `wave=/depth=`、四种 `DBG:` 行，
   并用 `dbg_unmatched` 单独统计「像 DBG 但字段对不上」的行——这类行是格式变更的第一信号。
3. **二进制帧只跳过、不解析**。本 demo 不做点云可视化，因此工具只能证明「帧的边界与校验正确」，
   不能证明「帧内容正确」。`frames_ok = 0` 时 T-GS-04 记「未验证」，不许记「通过」。
4. **校验错帧的处置与厂商上位机不同**：厂商 `MixedStreamParser` 在校验失败时只丢 **1 字节**重同步；
   本工具按声明长度**整帧跳过**，否则后半截帧会粘到下一行文本上、让那一行永远解析不出来。
   代价是：若长度字段也错，可能吞掉一段文本 —— 因此工具额外检查「被跳过的帧区间内是否含换行」，
   命中就告警（`binary.frame_swallowed_newline`）。两套口径的差异会体现在坏行/重同步计数上，Gate 需注明。
5. **旧格式 `depth` 的统计口径与厂商不同**：厂商在 `GESTURE: … wave= depth=` 分支把 depth 丢弃
   （`depth_action=0`），本工具仍把它记进 `depth` 表（只认 ±3），便于核对固件到底发了什么。
6. **`±3` 的极性是推断**：按 DBG 分支语义与「z 减小 = 靠近」定为 **+3 靠近 / −3 远离**。
   厂商界面不显示该值，故不影响任何判据；如需对外解释，先与固件侧确认。
7. **离线分析没有时间戳**：`--file` 必须配 `--duration` 才能算行率/行间隔，且「时刻」是按字节位置
   线性插值出来的，只用于对齐与统计，**不代表真实到达时刻**。特别注意：一个 300 字节的点云帧会在这条
   插值时间轴上占掉与长度成比例的「时长」（实测 ≈1.3 s / 300 B @600 s 采集），从而**假报空档**——
   所以离线模式下 P5 的空档结论只作参考，**定论必须用 `--port` 实测**（工具会在 warnings 里同时列出
   空档次数与累计时长，便于区分「18 次 × 1.3 s」这类插值伪影与真实断流）。
   实测校核：491 KB / 9000 行 / 18 帧的 30 分钟合成流，离线复算耗时 0.4 s，字节守恒差额 = 0
   （`491406 = 486006 + 5400 + 0`），可作为工具在处理真实 30 分钟数据时的容量证据。
8. **坐标护栏（P7）只是护栏**，不是精度验收。真实定位精度需要另设工装与多点标定，本 demo 不承诺。
9. **工具不替代目检**：网页端「显示的方向与动作一致」由 T-GS-02 的人工抽检承担（对齐计划 §六.2）；
   `x>0 显示在左` 这类视觉语义必须人眼看一次。
10. **采集不足 90% 时长时结论只覆盖已采集区间**，工具会自动写入 warnings，Gate 不得据此判 PASS。

## 八、附：工具用法与退出码

```powershell
# 场景 1：10 分钟挥手（本次 Gate 主用例）
py -3 tools\edv163_gesture_check.py --port COM6 --baud 115200 --duration 600 `
      --expect-hand present --threshold-cm 20 --save-raw logs\edv163-gesture\wave10.bin `
      --csv logs\edv163-gesture\wave10_lines.csv --raw-dump

# 场景 2：30 分钟静置
py -3 tools\edv163_gesture_check.py --port COM6 --duration 1800 --expect-hand absent

# 场景 3：离线复算（不接硬件、不需要 pyserial）
py -3 tools\edv163_gesture_check.py --file logs\edv163-gesture\wave10.bin --duration 600 --expect-hand present

# 场景 4：无硬件自测
py -3 tools\edv163_gesture_check.py --selftest
```

| 退出码 | 含义 |
|---|---|
| 0 | PASS（自测时 = 逐项对账全部通过） |
| 1 | FAIL（自测时 = 存在不符合项） |
| 2 | 参数或环境错误（阈值越界、文件不存在、串口打不开、缺 pyserial） |

产物：`logs/edv163-gesture/edv163_gesture_check_<时间戳>.json|.log`、`unattributed_<n>.bin`（仅 `--raw-dump`）、
`edv163_gesture_selftest_<时间戳>/`（仅 `--selftest`）。
