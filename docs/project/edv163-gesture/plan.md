# 项目计划 — EDK60 × EDV163 手扫（挥手识别）Demo

> 2026-10-23 ｜ 项目经理 ｜ 流水线复用 EDV11P（人数统计）/ EDV163（水位）两套已验证方案

## 一、目标与范围

| 项 | 内容 |
|---|---|
| 目标 | EDK60 把 **EDV163 挥手识别固件**的串口数据（**115200**）纯字节透传到原生 USB；网页端实时显示**挥手方向（左/右/上/下）+ 目标坐标 + 距离触发**，并给出 X-Z / X-Y 两个位置视图 |
| 协议来源 | **无协议文档**。唯一依据是厂商上位机 `gesture_monitor.py`（755 行）+ README，已逆推出完整格式 |
| 已定决策 | DEC-163G-01 用文本行协议（不是二进制帧协议）｜DEC-163G-02 网页端**只读**（上位机源码无任何写入）｜DEC-163G-03 交付范围同前（固件 + 网页 + 工具 + 文档 + 发布）｜DEC-163G-04 **可上板实测**（手上模组正是挥手固件） |
| 不做 | 不做点云可视化（二进制帧只跳过不解析）、不做手势自定义训练、不做多设备组网 |

## 二、协议（从源码逆推，作为唯一事实）

| 项 | 值 |
|---|---|
| 串口 | **115200 8N1**（工具也允许 230400/460800/921600） |
| 输出节奏 | 约 **200 ms/行** |
| 正式行 | `GESTURE: target=<0\|1> x=<m> y=<m> z=<m> action=<-2..2>`（数字支持科学计数法） |
| `target` | 1 = 位置有效；0 = 10 帧位置窗未形成（x/y/z 全 0） |
| `action` | **-2 下挥 / -1 右挥 / 0 无挥 / 1 左挥 / 2 上挥**；**±3 = 靠近/远离**（界面不显示） |
| 混杂二进制帧 | `0x4544` 开头，长度 bytes[2..3] 大端，合法 **11~4096**，校验 = 前 n-1 字节求和 &0xFF；解析时必须整帧跳过 |
| 旧格式兼容 | `GESTURE: ... wave=N depth=N`；`DBG: ... pos_m=( x y z ) ... action=N [lock=M]` |
| 方向 | 上位机语义：X-Z 俯视（z 向前，0~1 m，x>0 显示在左）；X-Y 正视（x>0 在左，y>0 向上，±0.40 m） |
| 距离触发 | 阈值默认 **20.0 cm**（0~100），`target=1 且 z<阈值` → 触发 |

## 三、与之前两个 demo 的差异

| 维度 | EDV11P 人数 / EDV163 水位 | **EDV163 手扫** |
|---|---|---|
| 波特率 | 921600 / 256000 | **115200** |
| 数据形态 | 二进制帧（TLV/转义） | **文本行 + 偶发二进制点云帧** |
| 解析难度 | 帧同步、校验、转义 | **文本正则 + 二进制帧跳过**（更简单，但对"串里混日志"更脆弱） |
| 写入需求 | 需要下发配置 | **完全只读**（设备无命令接口） |
| 上板可行性 | EDV11P 可 / 水位被模组固件阻塞 | **可**（手上模组就是挥手固件） |

## 五、风险登记

| ID | 风险 | P | I | R | 缓解 |
|---|---|---|---|---|---|
| G1 | **文本协议最怕串里混日志**：任何 `printf` 都会变成"坏行"，比二进制协议脆弱 | 4 | 4 | **16** | 固件沿用四道静默保险（零 printf）；工具统计"坏行率"作为洁净度判据 |
| G2 | 协议无文档，靠逆推；固件版本变化可能改格式 | 3 | 4 | 12 | 解析器同时支持正式/旧格式/`DBG:` 三类；坏行率 >1% 立即告警；README 里写明"以源码为准" |
| G3 | 二进制点云帧与文本混在同一流，帧界判断错会导致后续文本全乱 | 3 | 4 | 12 | 先按 0x4544+长度+校验整帧跳过（照厂商实现），再按 `\n` 切文本；自测必须含"两行文本中间夹一帧二进制" |
| G4 | 波特率搞错（沿用 256000/921600） | 3 | 5 | 15 | 新 demo 默认 **115200**；上板第一件事看行率是否 ~5 行/秒 |
| G5 | 挥手识别依赖安装距离/角度，现场不触发 | 3 | 3 | 9 | 教程写明推荐站位（z 约 0.2~0.8 m、正对雷达）；用"距离触发"卡片辅助判断是否在有效区 |
| G6 | `action=±3`（靠近/远离）被误显示成挥手方向 | 2 | 3 | 6 | 只映射 -2~2；±3 仅内部计数（与厂商界面一致） |

## 六、验收判据

1. **流完整性**：10 分钟采集，行率 5±20% 行/秒、坏行率 <1%、二进制帧校验通过率 100%、无 >1 s 空档
2. **功能**：网页端挥手方向与实际动作一致（左/右/上/下各 ≥10 次）；`target` 与 z 读数合理；阈值触发与 z 对得上
3. **构建**：19/19 全量回归通过
4. **只有文字，没有图形观感问题**：无（两个位置图必须按厂商语义：x>0 在左）
