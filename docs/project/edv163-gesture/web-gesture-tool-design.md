## 0. 一句话方案

EDK60_VA 只做 **UART 115200 ⇄ 原生 USB** 的纯字节透传，**不在固件里解析任何协议**；
`gesture.html` 用 Web Serial 打开串口后**只读**收字节，在浏览器里
先跳过 `0x4544` 二进制点云帧、再按 `\n` 切文本行、再用厂商正则解析遥测，
最后渲染"挥手动作大字 / 目标坐标 / 距离触发 / X-Z 俯视 + X-Y 正视"。

v1.1 追加**挥手动画层**：任一方向挥手触发一个全视口半透明浮层，手掌沿该方向平移 2.5 s
（`pointer-events:none`，不挡交互）；**动画期间（含淡出）只冻结"动作大字"的显示**，
解析、计数、日志、直方图一律照常（见第 16 节）。

v1.2 追加**两个方向取反开关**（左右 / 上下）：只改「显示名 + 配色」「动画方向」「日志注解」三处，
**不改设备行为、不改统计口径**，且**不做持久化**（刷新即恢复两个都关）。见第 17 节。

## 2. 逐字段映射表（含源码行号）

### 2.1 正式遥测行（唯一主路径）

格式（源码模块 docstring 第 5-7 行、README 第 63-65 行）：

```
GESTURE: target=<0|1> x=<米> y=<米> z=<米> action=<-2..2>

| 字段 | 类型 | 含义 | 源码行号 | 本页对应 UI |
|---|---|---|---|---|
| `target` | `0` \| `1` | `1` = 目标位置有效；`0` = 10 帧位置窗尚未形成，此时 x/y/z 均为 0 | 第 69-70 行 `target=(0\|1)`；README 第 69 行 | 位置卡片 tag `target=0/1`；`target=0` 时坐标显示 `—` 且标注「目标位置未就绪」 |
| `x` | 米（float） | 目标横向坐标 | 第 64 行 `x=(NUM)` | 位置卡片 X（3 位小数，带符号） |
| `y` | 米（float） | 目标纵向坐标 | 第 64 行 | 位置卡片 Y |
| `z` | 米（float） | 目标前向距离 | 第 64 行 | 位置卡片 Z + 触发判定 + 两张位置图 |
| `action` | `-2..2`（`±3` 也出现） | 挥手结果编码 | 第 65 行 `action=(-?\d+)`；第 123 行夹取 | 动作大字（`±3` 不显示为动作，只计数） |

**数字口径**（源码第 61 行，本页 `NUMBER_SRC` 逐字照抄）：

```
NUM = [-+]?(?:\d+(?:\.\d*)?|\.\d+)(?:[eE][-+]?\d+)?

即：普通小数、`+` 前缀、前导小数点（`.5`）、科学计数法（`1.2e-2` / `3.4E-2`）全部接受。
自测用例 C5 覆盖这四种写法。

## 6. 混合流解析：二进制帧跳过 + 文本重同步

### 6.1 为什么必须"跳过整帧"

模块 docstring 第 9-10 行、README 第 73 行：串口里**同时存在** `0x4544` 点云二进制帧与文本行。
若只按 `\n` 切行，二进制载荷里的任意 `0x0A` 都会被当成行尾，把后面的 `GESTURE` 行撕碎。

### 6.2 帧格式（源码第 178-236 行）

```
偏移  0  1  : 0x45 0x44               ← 帧头 'ED'
偏移  2  3  : 长度大端 (total)         ← 含帧头与校验字节的总长，合法 11~4096
偏移  4..total-2 : 载荷
偏移  total-1    : 校验 = sum(前面 total-1 字节) & 0xFF
```

常量：`MIN_BINARY_FRAME = 11`、`MAX_BINARY_FRAME = 4096`、`MAX_TEXT_BUFFER = 16384`（第 187-189 行）。

### 6.3 算法（本页 `GestureStreamParser.feed`，与源码逐判定对齐）

每一轮循环取两个位置：`headerAt` = 缓冲里第一个 `45 44`；`newlineAt` = 缓冲里第一个 `0x0A`。

```
循环 while 缓冲非空:
  ① newlineAt ≥ 0 且 (headerAt < 0 或 newlineAt < headerAt)：
       取 [0, newlineAt) 为一整行，去掉行尾所有 \r，消费到 newlineAt+1；
       非空则交付为一条文本行。            ← 源码第 203-208 行
  ② 否则 headerAt ≥ 0：
       先把 headerAt 之前的字节当噪声丢掉（计 noiseBytes）；   ← 第 212-213 行
       不足 4 字节 → 等下一批；                              ← 第 214-215 行
       total = buf[2]<<8 | buf[3]
       total ∉ [11,4096] → 丢 1 字节、重同步；               ← 第 218-220 行
       不足 total 字节 → 等下一批；                          ← 第 221-222 行
       sum(buf[0..total-2]) & 0xFF ≠ buf[total-1] → 丢 1 字节、重同步；  ← 第 225-227 行
       否则：整帧 total 字节丢弃，计 binFrames++，不参与文本解析。       ← 第 228 行
  ③ 既无帧头也无换行：
       缓冲 > 16384 则只保留尾部 16384 字节（计噪声裁剪）；   ← 第 232-233 行
       退出等待下一批。
```

**为什么校验失败只丢 1 字节而不是整帧**：源码 docstring（第 178-183 行）明确写
"疑似帧头但校验失败时仅丢弃一个字节重新同步，避免错误长度吞掉后续 GESTURE 文本"。
本页照抄——**不能**因为校验失败就按 `total` 跳过，否则一个假帧头会把后面几秒的数据一起吃掉。

### 6.4 事件与计数口径（本页新增，只加观测不改判定）

| 计数器 | 含义 | UI 位置 |
|---|---|---|
| `binFrames` | 完整、长度合法、校验通过的 `0x4544` 帧，被整帧跳过 | 顶栏「跳过二进制帧」+ 右列「丢弃二进制帧」 |
| `resync` | 帧头候选但被判非法 → 丢 1 字节重同步的总次数 | 顶栏「重同步」+「重同步次数」 |
| `lenRejected` | 其中长度不在 11~4096 的 | 仅内部/自测 |
| `sumRejected` | 其中校验和不符的 | 仅内部/自测 |
| `noiseBytes` | 帧头前被丢弃的字节 + 缓冲区溢出裁剪 | 右列「噪声字节」 |
| `textLines` | 交付出去的非空文本行 | 内部 |
| 坏行（文本层） | 交付了行但匹配不上 6 条正则 | 顶栏「坏行」 |
| 有效行（文本层） | 匹配成功 → 驱动 UI | 顶栏「有效行」 |

### 6.5 文本层重同步（本页**唯一**对厂商实现的功能性增强）

**问题**：校验失败的帧只丢 1 字节，残留字节（含 `0x44`/载荷）会粘在**下一行文本**前面，
变成 `\x44\x00\x0e…GESTURE: target=1 …`。厂商实现里这一行走 `^GESTURE:` 锚点直接失败 → **这一行丢了**
（源码第 226 行注释接受了这个代价）。

**本页做法**：整行匹配失败时，若行内出现已知行前缀（`GESTURE:` 或 `DBG:`）且下标 > 0，
就从该下标处**再匹配一次**；成功则该行照常驱动 UI，同时 `trimmedLines++` 并在日志里注明
"已重同步（丢掉前置 N 字节）"。

- 正则**一个字都没改**，只多一次"找前缀"的机会；
- 不会凭空造数：前缀必须真实存在，且前缀之后必须完整匹配正则；
- 坏行计数仍然独立——找不到前缀就记坏行，不掩盖问题。

自测 C8（校验错帧插在两行文本中间）与 C10（行首垃圾字节）就是专门验证这条的：
**坏行 0、有效行 3/1、`trimmed` ≥ 1**。

**超时（freshness）**：距最后一条有效行 > `CFG.staleMs = 1500 ms` 时判「遥测超时」，
坐标置 `—`、触发置「未触发」、两张图回到「目标位置未就绪」。
源码对应逻辑是 1.0 s（第 714-723 行 `_update_freshness`）；本页放宽到 1.5 s
（200 ms × 5 行的余量，避免偶发丢一行就闪"超时"），差异记入决策 D5。

### 7.4 状态条（顶栏第二行，11 项）

连接状态（带圆点：灰=未连接 / 绿=已连接 / 蓝=模拟中）、串口、波特率、
**行率（行/秒）**、**有效行**、**坏行**、**跳过二进制帧**、重同步、**最后一行时间**、收字节、
**方向取反（无 / 左右 / 上下 / 左右+上下，v1.2）**。

行率口径：最近 `5 s` 窗口内的有效行数 ÷ 5（`state.lineTimes` 内滑窗）。
最后一个 chip 只读：它显示右列两个取反复选框的**当前生效状态**，
点它没有动作（开关本体在右列「显示选项」面板里，第 17 节）。

### 7.5 右列（独立滚动，5 个面板 + 脚注）

连接参数（波特率下拉 + 8N1 说明）｜距离阈值（镜像输入 + 判定式说明）｜
显示选项（显示 ±3 计数 / 显示原始日志 / **左右挥手方向取反 / 上下挥手方向取反**）｜
会话统计（运行时长、有效/坏/重同步行、丢弃二进制帧、重同步次数、噪声字节、收字节、行率 + **action 直方图**）｜
帧解析自测（按钮 + 结果框）｜脚注（离线单文件 / 只读声明）。

两个取反复选框各跟一行小灰字提示（要点：「勾选后仅改变**页面显示与动画方向**，
不改变设备行为（本站不向设备发送任何数据）」）。它们**不进入**顶栏的会话状态，
但顶栏状态条另有一个只读 chip 显示当前生效状态（`方向取反 无/左右/上下/左右+上下`）。

直方图：`action −2..2` 五行 + `±3` 两行（受开关控制），每行含色块、编码、次数、
占比条。分母口径 = 挥手动作总数（`±3` 两行用"动作总数 + 靠近远离总数"作为分母），
见 `renderHistogram()`。

> **直方图与取反的关系（v1.2，容易搞错）**：
> **行的身份（键）永远是原始码** —— `stats.actions[String(rawCode)]`，所以各方向计数、
> 总数、占比一分都不变；**只有标签与色块走生效名**（`displayActionName/Color`），
> 括号里仍打原始码，取了反的追加 `· 取反`。例：勾了左右取反后，原 `1` 那一行显示
> 「右挥手 1 · 取反 8 次」——"8 次"仍然是 `action=1` 的次数，不是 `action=-1` 的。
> 这样"统计口径"和"用户看到的语言"各归各位，跨版本对数据也不会错位。

会话统计里另有 **「动画期忽略 N」**（`#ss-skip`）：挥手动画播放期间（含淡出）被忽略的
**新挥手事件**次数。它只统计"去重后的新事件"，同一次检测的残留帧不计入（见第 17.4 节）。

### 7.6 原始日志（定高 / 内部滚动 / 可折叠）

`#logbox` 深底等宽字体（继承 level.html 的 `#0f172a` / `#cbd5e1`），每行 = 时间戳 + 着色正文：

| 类别 | 颜色 | 文本样式 |
|---|---|---|
| 文本行 | `#7dd3fc`（`.rx`） | `文本行  GESTURE: … → 左挥手`（或 `· 目标未就绪` / `· 已重同步（丢掉前置 N 字节）`）；**取了反时**改成 `→ action=1 → 显示为「右挥手」(已取反)`（保留原始码） |
| 二进制帧 | `#fca5a5`（`.bx`） | `跳过二进制帧 #3  len=17  45 44 00 11 01 02 …` + `[0x4544 · 校验和 OK]` |
| 重同步 | `.bx` | `重同步：校验和不符 期望 0xAB 实得 0xAC（帧长 14），丢 1 字节` |

## 8. 模拟演示（无硬件验收）

`buildSimChunk(tick)` 生成**真实字节流**（含 `0x4544` 二进制帧），
经 `feedInbound()` 走**与串口完全相同**的解析 + 渲染管线——不是"直接改 UI"的假演示。

| 项 | 值 |
|---|---|
| 节奏 | 200 ms 一拍（对齐固件输出节奏） |
| 坐标 | `x = 0.18·sin(0.70t)`、`y = 0.12·sin(0.53t)`、`z = 0.30 + 0.22·sin(0.90t)`（米，`z ∈ 0.08~0.52`） |
| `z` 的用意 | 周期约 7 s，反复穿过默认 20 cm 阈值 → 触发卡片会真的在「触发/未触发」之间跳 |
| 动作序列 | 24 拍一个周期：无挥手×2 → 左挥×3 → 无挥手 → 右挥×3 → target=0×2 → 上挥×3 → 无挥手 → 下挥×3 → 无挥手 → `+3` → `−3` → target=0 → 无挥手×2 |
| `target` 切换 | 周期内 3 拍为 `target=0`（x/y/z 全 0），其余 `target=1` |
| 合法二进制帧 | 每 9 拍插一帧（载荷 12 B，总长 17 B，校验正确）→ 计「跳过二进制帧」 |
| 校验错的帧 | 每 23 拍插一帧（载荷 9 B，总长 14 B，校验 +1）→ 计「重同步」，其残留靠文本层重同步救回 |
| 载荷设计 | 刻意只用 `0x01~0x0C`，**不含** `0x0A/0x45/0x44`，避免自己造出假行尾/假帧头而把用例测成假阳性 |

模拟与真串口**互斥**（勾选模拟会要求先断开串口；连串口会先停模拟）。

## 9. 页内帧解析自测（18 条）

所以启动时的静默自测不会真的放动画；C18 里临时改到的 `CFG.invert` 在 `finally` 里还原）。

| # | 用例 | 断言要点 |
|---|---|---|
| C1 | 正式行 `action=1` | 1 行 / target=1 / x,y,z / 左挥手 |

| C3 | `action=-2/-1/0/1/2` | 显示名与配色逐条对照 `WAVE_ACTION_INFO` |

| C5 | 科学计数法 | `1.2e-2 → 0.012`、`-3.4E-2 → -0.034`、`1.56e-1 → 0.156`、`.5 → 0.5`、`+.25`、`2E-1` |
| C6 | 旧格式 `wave=2 depth=3` | 上挥手 + depthAction=3 |
| C7 | `DBG:` 两种变体 | target=1 取到 pos_m 与 action；target=0 坐标为 0 |
| C8 | **混入二进制帧**（合法 + 校验错，跨 3 个 chunk 断开） | `binFrames=1`、`resync≥1`、有效行 3、**坏行 0**、`trimmed≥1` |

## 14. 设计决策记录

| ID | 决策 | 备选 | 理由 |
|---|---|---|---|
| D1 | 解析器**逐判定照抄**厂商 `MixedStreamParser`，包括"校验失败只丢 1 字节" | 自创状态机 | 现场数据只可能被厂商实现验证过；改判定=自造风险 |
| D2 | 在文本层**新增一次前缀重同步**（不改正则） | (a) 完全照抄（接受丢行）(b) 改正则容忍前缀 | (a) 会让每次校验错都白丢一行；(b) 会削弱锚点、可能从垃圾里造出数据。折中方案代价最小且可观测（`trimmedLines`） |
| D3 | 校验失败的二进制帧**不计入** `binFrames`，单独计 `resync` | 都算"跳过帧" | 两者含义不同（一个是正常点云帧，一个是坏帧头），混在一起会让"跳过帧数"失去诊断价值 |
| D4 | 触发配色用**绿**（任务书要求） | 照厂商红 `#dc2626` | 任务书明确写"触发（绿）"；为唯一视觉偏离，记档以免后人误以为抄错 |
| D5 | 遥测超时 **1.5 s**（厂商 1.0 s） | 照抄 1.0 s | 200 ms/行，1.0 s 只容 5 行；偶发丢 1~2 行就闪"超时"会误导演示。1.5 s 仍能明显提示断流 |
| D6 | 三张卡片压在**一个面板**里（`grid` 三分栏） | 三个独立面板 | 1280×720 下纵向预算只有 544 px，拆三个面板会挤掉位置图高度（level.html 的 `--hero-h` 132 px 已是同款取舍） |
| D7 | 布局与配色**直接复用** level.html 的设计 token（`--fg/--sub/--line/--brand/--ok/--err`、`.chip`、`.tag`、`.switch`、面板圆角 12 px） | 重新设计 | 同项目三个网页工具视觉与手感应一致；也便于用户在两页之间迁移 |

| D9 | `±3` 保留 `rawAction/depthAction`（源码正式行会丢） | 照抄丢信息 | 任务书要求"±3 仅内部计数"，丢信息就做不出计数；显示语义未变 |
| D10 | 单元格宽高比、日志 400 行上限等"观感/内存"参数写进 `CFG` 而非散落各处 | 硬编码 | 便于上板后按实况调（如 400 → 800） |
| D11 | 动画锁定期**只冻结"动作大字"**（名称/配色/来源标签），直方图、坐标、行率、日志照常 | 整块冻结"所有动作相关 UI" | 需求原文第 3 条明确写「必须继续正常解析与计数（行率、有效行、坏行、坐标、日志、**直方图**都要照常更新）」——直方图在"照常"清单里；"不更新动作相关统计的可视部分"因此按**动作展示区**理解（大字与配色）。两处表述的取舍记在此处，避免后人以为是漏实现 |
| D12 | `skippedDuringAnim` 只统计**去重后的新事件**，同一次检测的残留帧不计 | 每条被忽略的行都 +1 | 一次检测连出 6 行，若按行计会变成「忽略 6」这种无意义数字；按事件计才能回答"这段时间用户又挥了几次" |
| D13 | 动画用 `requestAnimationFrame` + `transform:translate3d` 驱动，不用 CSS `transition` | CSS 过渡更省代码 | ①锁定期需要与动画共用同一个时间基准（`durationMs` 到点即解锁），CSS 过渡的 `transitionend` 在标签页后台/降帧时不可靠；②纯函数 `animPlan/animOpacity` 可在 Node 桩环境逐帧断言（C14~C17 + 桩环境 21 项）；③`translate3d` 走 GPU 合成，观感与 CSS 过渡等同 |
| **D14** | 取反做成**映射层一个纯函数** `effectiveAction(code, inv)`；`actionName/actionColor/CFG.actions/CFG.animDirs` **一行不改** | (a) 复制一张反向方向表 (b) 在 4 个消费点各写一次 `if (invert) -code` (c) 改协议表本身 | (a)(b) 都是"两份真相"，漏改一处就会出现"名字翻了动画没翻"（正是需求第 2 条要防）；(c) 改协议表会让日志原始码、直方图键、C3 用例同时失去锚点。单一纯函数 + 两个 `display*` 包装，既保证三处自洽，又让 `plan.action/effective/inverted` 三个字段可以自证 |
| **D15** | 取反状态**不持久化**（不写 `localStorage`/Cookie/URL/hash） | 记住用户的开关选择 | ①本页"零本地存储"是硬不变量，破例会连锁削弱静态审计的可机检性；②取反是"我怎么看这台设备"的临时视角、不是设备配置，隐性持久状态会让人下次打开时困惑；③换固件/换端口会串状态；④排查"到底设备有没有反"时，刷新即回默认只有 1 秒；⑤见第 17.4 节 |

## 16. 挥手动画层与动画锁定期（v1.1 新增）

> 需求原文：「当发生左挥手时，屏幕弹出一个手掌从左到右，动画时间大约 2~3s，这个期间忽略任何
> 回收状态更新，当发生其他方向的挥手也一样。」
> 一句话实现：**全视口 `pointer-events:none` 浮层 + 内联 SVG 手掌 + `requestAnimationFrame`
> 平移 2.5 s + 期间冻结"动作大字"的显示（解析与计数完全不停）**。

### 16.1 方向表（用户拍板，实现不做"纠正"）

坐标口径：`from`/`to` 是 `[-1,1]` 的归一化比例，渲染时映射为
`百分比 = 50 + ratio × (50 − marginPct)`，`marginPct = 8` → **8% ↔ 92%**（起终点都不贴边）。

| `action` | 显示名 | 动画：起点 → 终点 | 归一化 `from → to` | 手掌朝向 `rotate` |
|---|---|---|---|---|
| `1` | 左挥手 | **屏幕左侧 → 屏幕右侧**（横向） | x 轴 `-1 → +1`（8% → 92%），y 恒 50% | `+90°`（指尖朝右） |
| `-1` | 右挥手 | **屏幕右侧 → 屏幕左侧**（横向） | x 轴 `+1 → -1`（92% → 8%），y 恒 50% | `-90°`（指尖朝左） |
| `2` | 上挥手 | **屏幕下侧 → 屏幕上侧**（纵向） | y 轴 `+1 → -1`（92% → 8%），x 恒 50% | `0°`（指尖朝上） |
| `-2` | 下挥手 | **屏幕上侧 → 屏幕下侧**（纵向） | y 轴 `-1 → +1`（8% → 92%），x 恒 50% | `180°`（指尖朝下） |
| `0` / `±3` / 其它 | — | **不触发动画** | `animPlan()` 返回 `null` | — |

> 屏幕坐标系是 `y` 向下，所以"屏幕下侧"= 92%、"屏幕上侧"= 8%。
> 手掌 SVG 默认指尖朝上，移动方向靠 `rotate` 让指尖顺着运动方向（另叠 `±6°` 摆动，看着像在"挥"）。

### 16.2 时长、缓动与几何（全部在 `CFG.anim` 里可调）

| 参数 | 默认值 | 说明 |
|---|---|---|
| `durationMs` | **2500** | 用户口径 2~3 s，取中值；含最后 300 ms 淡出 |
| `fadeMs` | 300 | 最后 300 ms 透明度 1 → 0，之后整层移除 |
| `marginPct` | 8 | 起终点各留 8% 边距 → 横向 8% ↔ 92%，纵向同理 |
| `sameEventWindowMs` | 300 | 同值 action 间隔 ≤300 ms 视为"同一次检测"（见 16.4） |
| `ease` | `[0.4, 0, 0.2, 1]` | `cubic-bezier(.4,0,.2,1)`，牛顿迭代实现（`animEase()`），可在 Node 里断言 |
| `trailCount` / `trailLagMs` | 4 / 45 | 4 条渐隐残影，每条比手掌滞后 45 ms（不透明度 0.26→0.10） |
| `wobbleDeg` / `wobbleCycles` | 6 / 3 | 摆动幅度与周期数（只影响旋转，不改变起止点） |
| `sizeRatio` / `minSizePx` / `maxSizePx` | 0.17 / 88 / 176 | 手掌边长 = `min(视口宽, 视口高) × 0.17`，再夹到区间；1280×720 → 122 px，1920×1080 → 176 px |
| `zIndex` | 9000 | 高于 `.topbar`（z-index:5）与所有面板 |
| `reducedMotionMs` / `reducedFadeInMs` | 800 / 200 | `prefers-reduced-motion` 专用（见 16.6） |

时间轴：`0 → moveMs(2200) = 位移段（缓动到终点）`，`2200 → 2500 = 淡出段`，`2500 = 解锁并移除浮层`。

### 16.3 锁定语义：**解析不停，只冻结动作展示**

状态机唯一真值是 `state.animLock`：

```
idle ──新事件──▶ playing(animLock = true) ──满 durationMs（含淡出）──▶ idle(animLock = false)
```

| 锁定期内（含淡出）的行为 | 是否变化 | 实现位置 |
|---|---|---|
| 解析字节流、切行、6 条正则 | **照常** | `feedInbound()` / `applyLine()` 完全没被拦 |
| 有效行 / 坏行 / 重同步 / 跳帧 / 收字节 / 行率 | **照常** | `state.stats`、`lineRate()` |
| 坐标（X/Y/Z）、两张位置图、距离触发卡片 | **照常** | `updateHero()` 里只 gate 了动作大字那一段 |
| 日志（文本行 / 二进制帧 / 坏行） | **照常** | `logLine()` |
| action 直方图（计数与占比条） | **照常** | `renderHistogram()` 未 gate（见决策 D11） |
| 靠近/远离（±3）计数小字 | **照常** | 同上 |
| **动作大字（名称 / 配色）与来源 tag** | **冻结在触发动作** | `updateHero()` 里 `if (!state.animLock) { … }`；触发瞬间由 `paintActionCard()` 定格 |
| 新的挥手事件 | **不重启、不切换、不补播** | `animRequest()`：`skippedDuringAnim++` + 日志 `（动画播放中，忽略 action=X）` |

- 「动画期忽略 N」显示在**右列 · 会话统计**（`#ss-skip`），锁定期内实时增长。
- 解锁瞬间 `animFinish()` 会主动回调一次 `updateHero()`，把大字拉回**最新遥测**
  （期间被忽略的方向**不补播**，只回到最新状态）。
- 动画期间**解析从未暂停**是硬要求：桩环境断言 ⑤ 在锁定期内喂一行 `GESTURE` + 一行垃圾，
  验证 `validLines +1`、`badLines +1`、`行率 > 0`、`actions['1'] +1`，而 `h-action` 仍停在触发动作。

### 16.4 同一次检测去重（6 连帧只播 1 次）

实测固件每次检测会连出 **6 行相同 `action`**（约 200 ms 一行，总跨约 1.2 s）。
规则实现为纯函数 `animClassify(code, prevAction, prevAt, at)`：

| 输入 | 判定 | 效果 |
|---|---|---|
| 非零 action，与上一次**同值**且间隔 **≤300 ms** | `residual: true` | 残留帧：不播、不计 `skipped`，只累加 `state.anim.residualFrames` |
| 非零 action，与上一次**不同值** | `isNew: true` | 新事件 → 播（锁定期内则记 `skipped`） |
| 非零 action，间隔 **>300 ms** | `isNew: true` | 新事件（手停了再挥，算新的一次） |
| `action=0` | 不计事件 | 记下"这次挥完了"；之后的同值动作算新事件 |
| `action=±3` | `ignore: true` | 靠近/远离与挥手方向无关：不触发、也**不扰动**去重状态 |

> 注意窗口是"**相邻两行的间隔**"而不是"整组的跨度"：6 行相隔 200 ms，第 2~6 行全部
> 落在 300 ms 窗口内 → 只算 1 次事件（桩环境断言 ④：`starts=1, residual=5`）。

### 16.5 渲染实现（DOM / CSS / 性能）

- **浮层**：`#gestureAnimLayer.anim-layer`，`position:fixed; inset:0; pointer-events:none;
  z-index:9000; overflow:hidden`。由 JS 在触发时 `createElement` 建、动画结束 `removeChild` 移除，
  HTML 里没有静态节点（不占布局、不影响首屏）。
- **图形**：内联 SVG（`createElementNS`，`viewBox="0 0 96 116"`），**一个 `<path>` 的 6 个子路径**
  （掌 + 4 指 + 拇指）。同一个 `fill` 的非零环绕 = 并集，所以重叠处不会加深透明度、也没有描边接缝；
  `fill: rgba(11,107,203,0.20)`、`stroke: rgba(11,107,203,0.55)`、`filter: drop-shadow(…22px)` 柔光。
  **零外链、不依赖 emoji 字体**（CJK/emoji 字体缺失时 emoji 会渲染成方框，SVG 不会）。
- **动效**：`transform: translate3d(x,y,0) rotate(deg) scale(1)` + `opacity`，只走合成层；
  每帧一次 `requestAnimationFrame`，结束时停止排帧。
- **拖尾**：4 个同形状元素，各自按 `t − lagMs` 求位置，透明度 0.26/0.21/0.15/0.10。
- **不拦截交互**：`pointer-events:none` 同时写在 CSS 与内联样式里（`pointer-events` 是继承属性，
  子元素一并失效），所以动画期间仍可点按钮、滚右列、拖窗口。
- **不写本地存储、不联网、不碰串口**：动画层与只读不变量无关，桩环境静态区 38 项仍全过。

### 16.6 可访问性（`prefers-reduced-motion: reduce`）

| 项 | 正常 | 减少动效 |
|---|---|---|
| 时长 | 2500 ms | **800 ms** |
| 位移 | 8% → 92% | **不位移**，静态出现在视口正中（50%/50%） |
| 透明度 | 位移段恒 1，末 300 ms 淡出 | 淡入 200 ms → 保持 500 ms → 淡出 300 ms |
| 拖尾 / 阴影 / 摆动 | 有 | 全部关闭（CSS 媒体查询里 `.anim-trail{display:none}`、`filter:none`） |

判定在**触发瞬间**做（`matchMedia('(prefers-reduced-motion: reduce)')`），所以运行中切换系统设置
不会打断正在播的这一次，下一次会按新设置走。

### 16.7 调试钩子 `window.__gestureAnim`

```js
window.__gestureAnim = {
  trigger(actionCode, opts),   // 触发一次动画；返回 true = 真的启动了
  isLocked(),                  // 当前是否在锁定期（含淡出）
  state(),                     // 只读快照：action/axis/phase/from/to/xPct/yPct/opacity/skipped…
  last(),                      // 上一次已结束的动画（action/startedAt/endedAt）
  plan(code, opts),            // 纯函数：{from,to,durationMs,moveMs,fadeMs,rotate,reduced}
  finish(),                    // 立即收尾解锁（截屏脚本跳过等待用）
  _frame(ts),                  // 手动推一帧（Node 桩环境用，浏览器里不需要）
  _cfg()                       // 关键配置回显（durationMs / marginPct / sameEventWindowMs…）
};
```

`trigger()` 的语义**与遥测事件一致**：锁定期内调用只会计 `skipped` 并返回 `false`；
截屏/自测需要强制重入时用 `trigger(code, { force: true })`。

`state()` 快照在 v1.2 多了三个字段：`effective`（生效码）、`inverted`（这次动画是否取反）、
`invert`（当前两个开关）。取反开关自己的钩子是另一个对象 `window.__gestureInvert`，见第 17.6 节。

### 16.8 已知边界（写在这里免得被当成 bug）

| # | 边界 | 原因 |
|---|---|---|
| A1 | 锁定期内动作大字不刷新（最多 2.5 s） | 需求要求"期间忽略任何状态更新"（决策 D11） |
| A2 | 被忽略的方向不补播 | 用户明确"只播第一个触发的" |
| A3 | 同向挥手若中途丢行 >300 ms，可能被当成第二次事件重播 | 去重窗口是 300 ms（可用 `CFG.anim.sameEventWindowMs` 调大，但会延迟"手停了再挥"的响应） |
| A4 | 动画不改变任何统计口径 | 直方图仍按"解析成功的行"计数，与动画无关 |
| A5 | 手掌是手绘简化轮廓，不是写实图形 | 单文件零外链约束下不引入素材；如需真实素材，可换 `HAND_PATH_D` 常量（唯一改点） |

## 17. 方向取反开关（v1.2 新增）

> 需求原文：「是否可以增加两个开关，分别用于取反左右挥手方向和上下挥手方向」。

### 17.1 作用范围（只有三处，别扩大）

| # | 受影响 | 表现（以 `action=1` + 左右取反为例） | 代码入口 |
|---|---|---|---|
| ① | **动作大字**（显示名 + 配色） | 「右挥手」+ `#2563eb`（对向动作的颜色）；来源 tag 追加「· 已取反」 | `updateHero()` → `displayActionName/Color()`；锁定期由 `paintActionCard()` 定格（同样追加标记） |
| ② | **动画方向** | 手掌**从右到左**（92% → 8%），与显示名一致 | `animPlan()` 用 `effectiveAction(code)` 作为 `CFG.animDirs` 的查找键 |
| ③ | **日志注解** | `→ action=1 → 显示为「右挥手」(已取反)`（**保留原始码**） | `applyLine()` |
| — | 直方图**标签**（含色块 / `· 取反` 标记） | 行显示「右挥手 1 · 取反 N 次」 | `renderHistogram()` 的 label/color 走 `displayAction*`，**count 仍取原始码的键** |
| — | 顶栏状态 chip | `方向取反 无 / 左右 / 上下 / 左右+上下` | `updateStatusBar()` → `invertLabel()` |

**明确不受影响**（写在这里，防止下次"顺手"扩大范围）：

| 项 | 为什么不改 |
|---|---|
| `actionName()` / `actionColor()` / `CFG.actions` | 这是**设备与厂商上位机的协议约定**（源码第 104-110 行逐字照抄）。取反是"显示口径"，不能改协议表，否则 C3 用例、日志原始码、直方图键全部失去锚点 |
| `state.stats.actions[...]` 的键 | 统计口径必须与 `action` 码一一对应；跟随取反会让"昨天的数据"和"今天的数据"不可比 |
| `rawAction` / `depthAction` / `waveAction` | 解析层产物，与展示无关（`±3` 的 `waveAction` 仍落 0） |
| `animClassify()` 的去重键（`state.anim.lastAction`） | 去重问的是"设备是否在同一次检测里连发了 6 行相同码"，属**设备行为**，必须按原始码判；若按生效码判，勾了取反后 `1` 与 `-1` 会互换身份，去重语义就错了 |
| 设备行为 | 本页**没有任何写入路径**，取反纯前端；串口侧一个字节都不会变 |

### 17.2 实现层：映射层一个纯函数（单一真值 + 单一改点）

```js
CFG.invert = { lr: false, ud: false };      // 唯一真值（内存，不持久化）

function effectiveAction(code, inv) {       // inv 省略时读 CFG.invert
  const n = Number(code);
  const f = normInvert(inv);                // {lr, ud} 归一化
  if (!f.lr && !f.ud) return n;             // 两个都关：零开销直通
  if ((n === 1 || n === -1) && f.lr) return -n;   // 左右取反
  if ((n === 2 || n === -2) && f.ud) return -n;   // 上下取反
  return n;                                 // 0 / ±3 / 其它：恒不变
}
function displayActionName(code, inv)  { return actionName(effectiveAction(code, inv)); }
function displayActionColor(code, inv) { return actionColor(effectiveAction(code, inv)); }
```

设计取舍（为什么不是"在 `CFG.animDirs` 里复制一份反向表"，也不是"在 4 个消费点各翻一次"）：

| 方案 | 结论 |
|---|---|
| 复制一张反向方向表（8 条） | ❌ 两份真相必然漂移；改 `marginPct`/方向表时要改两处；`rotate` 还得记得翻 |
| 在 `animPlan`/`updateHero`/`日志`/`直方图` 各写 `if (invert) -code` | ❌ 4 份判断逻辑，漏一个就"名字翻了动画没翻"（正是需求第 2 条要防的） |
| **映射层一层 `effectiveAction()`**（采用） | ✅ 1 个纯函数 + 2 个 display 包装；方向表、协议表一行不改；`plan.action`（原始码）/`plan.effective`（生效码）/`plan.inverted`（是否取反）三个字段同时给出，日志与快照都能自证 |

`animPlan()` 的关键改动（**唯一**改动点）：

```js
const raw = Number(code);
const n = effectiveAction(raw, o.invert);   // ← 取反在这里发生
const dir = CFG.animDirs[String(n)];        // ← 方向表照旧按码查
// …
return { action: raw, effective: n, inverted: (n !== raw), name: dir.name, /* from/to/rotate… */ };
```

于是「显示名（`dir.name`）+ 配色（`actionColor(effective)`）+ 动画方向（`dir.from/to`）+ 日志措辞」
四者**必然自洽**——它们都来自同一个 `n`，不可能出现"名字说右挥手、手掌却从左往右飞"。

`opts.invert` 允许显式传入（自测用）：`animPlan(1, { invert: {lr:true,ud:false} })`
→ 右挥手 92%→8%。页面运行时**不传**，一律读 `CFG.invert`。

### 17.3 与统计口径的关系（**键 / 标签分离**）

| 层 | 用哪个码 | 原因 |
|---|---|---|
| `GestureStreamParser` 解析 | 原始码 | 解析是协议的镜像，不能有展示逻辑 |
| `state.stats.actions[String(wave)]` | **原始码** | 统计口径与 `action` 码一一对应：勾不勾开关，各方向次数、总数、占比**完全不变** |
| 直方图行**顺序/键/次数/占比条** | **原始码** | 同上；跨会话、跨版本可比 |
| 直方图行**标签/色块/`· 取反` 标记** | 生效码 | 用户看到的名字必须与动作大字一致 |
| 动作大字 / 动画 / 日志注解 | 生效码（日志同时给原始码） | 需求第 2 条的"三处自洽" |

一句话：**取反只改"怎么说"，不改"怎么数"**。所以勾了开关后直方图会出现
「右挥手 1 · 取反 8 次」——"8 次"是 `action=1` 的 8 次，不是 `action=-1` 的（`-1` 那行会显示「左挥手 … 」）。
若哪天要让"取反后的名字"成为统计键，那是**换口径**，需要新的数据结构与迁移说明，不在本开关范围内。

### 17.4 为什么不持久化（`localStorage` / URL / Cookie 都不用）

| 理由 | 说明 |
|---|---|
| 1. 不变量优先 | 本页从 v1.0 起就有"**零本地存储**"的硬不变量（静态区 16 项），它同时也是"只读、无副作用"的一部分。为一个展示开关破例，会让后续评审很难再说"本页不落任何东西" |
| 2. 状态语义正确性 | 取反是**"我怎么看这台设备"的临时视角**，不是设备配置。落盘后用户下周再打开会疑惑"为什么左右反了"，而且没有可见的来源提示（一旦进入 `localStorage` 就是隐性状态） |
| 3. 多设备/多端口会串 | 同一台电脑可能连不同固件版本（编码约定可能不同）；持久化会把"上一台的取反"带进"下一台" |
| 4. 排查路径要干净 | 现场判断"到底是不是设备反了"，第一步就该是**刷新页面回到默认**——不持久化让这一步永远只有 1 秒 |
| 5. 合规/审计 | 本页是"只读监视器"，不落任何用户状态，静态审计（`无 localStorage/cookie`）可以继续保持"零命中"这种可机检的形式 |

刷新后行为：两个复选框回到未勾选、chip 回「无」、`CFG.invert = {lr:false, ud:false}`（自测 ⑫/I8 覆盖）。

### 17.5 切换开关为什么不重启动画（锁定期语义的延伸）

`applyInvert(lr, ud, from)` 只做四件事：写 `CFG.invert` → 同步两个复选框的 `checked` →
更新顶栏 chip → `updateStatusBar()`（直方图标签）+ `updateHero()`（动作大字）。

它**不碰** `state.anim` / `state.animLock` / `ANIM.*`：不 `animTeardown()`、不 `animStart()`、不重排帧。
而 `updateHero()` 里"动作大字"整块本来就有一道 `if (!state.animLock)` 的闸门（第 16.3 节），
所以：

| 时刻 | 勾选后会发生什么 | 为什么这样是对的 |
|---|---|---|
| 空闲（动画没在播） | 下一次 `updateHero()` 立刻把大字换成生效名 | 用户立刻看到效果，不需要重连 |
| **动画正在播** | 本次动画的 `plan` 是触发瞬间算好并冻结的（`from/to/name/rotate` 都在 plan 里），**不重新计算**；大字被锁定期 gate 住，仍是触发时的名字 | 需求明确"动画进行中被勾选，只影响下一次触发"。重算 plan 会让半途的手掌瞬间跳位/换向，观感更像 bug |
| 动画收尾 | `animFinish()` → `updateHero()`，大字按**当时的** `CFG.invert` 拉到最新遥测 | 收尾自然过渡到新口径 |

对应断言：⑦（`runId` 不变、`inverted` 仍 false、起止点仍 8%→92%、大字仍「左挥手」）与
⑦-b（收尾后同值再触发才翻，且没有"补播"）。

### 17.6 调试钩子 `window.__gestureInvert`

```js
window.__gestureInvert = {
  set(lr, ud),        // 两个参数都不给 → 两个都关（显式复位）；只给一个 → 另一个保持原值
  get(),              // → { lr, ud }
  effective(code, inv?),  // → 生效码；inv 省略时读当前开关
  label(inv?),            // → '无' / '左右' / '上下' / '左右+上下'（只读辅助）
  plan(code, inv?)        // → animPlan(code, {invert})（只读辅助，便于截图脚本核对方向）
};
```

语义细节（v1.2 自测抓出来的歧义，已写死）：`set()` **无参** = 两个都关；
`set(true)` = 只开左右、上下**保持原值**。这样"只切一侧"和"全部复位"都能一行写完，
不会出现"我明明调了 `set(true)` 却把上下也关了"。

### 17.7 已知边界

| # | 边界 | 原因 |
|---|---|---|
| B1 | 勾了取反后，**日志里的原始码与显示名不一致**（`action=1` 却显示「右挥手」） | 这正是需求要的（保留原始码便于对协议），注解里已标 `(已取反)` |
| B2 | 取反**不改变**直方图各行的次数 | 键按原始码（17.3）；若需要"按取反后口径统计"，是另一个功能 |
| B3 | 取反状态**不跨标签页、不跨刷新** | 不持久化（17.4）。跨标签一致需要 `BroadcastChannel`/存储，与"零存储"冲突 |
| B4 | 勾了取反后**自测仍报 18/18** | C14/C16/C17 显式传 `invert: INV_OFF`（见第 9 节注）——否则用户会误以为"勾了开关页面就坏了" |
| B5 | 取反**不能**"修正"真实设备的编码反了 | 它只是显示层遮罩。若上板发现四向全反，根因在固件/编码约定（U2），必须回填，不能靠开关糊过去 |
