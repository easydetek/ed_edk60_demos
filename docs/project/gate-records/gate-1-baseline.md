## 三、引脚结论复核（硬件工程师复核）

| # | 结论 | 依据 | 复核结果 |
|---|---|---|---|
| 1 | 主控 = ESP32-C6-MINI-1-N4，53 脚，4MB Flash | 原理图 M1 + 用户确认 | ✅ |
| 2 | LED_RX = **IO8**、LED_TX = **IO9**，均低电平点亮 | R6/R7 + LED2/LED3 到 GND | ✅ |
| 3 | BOOT 键 = **IO9**（低有效，strapping 脚） | SW2 TS-1088-AR020016 | ✅ |
| 4 | 雷达 UART RX = **IO14** | H4-T | ✅ |
| 5 | 雷达电源使能 = **IO15**，`EN ── R2(10k) ── GND`，**默认关闭，输出高即使能** | U4/EN + R2 | ✅ **（曾误读为上拉到 5V，见第五节）** |
| 6 | LED4（丝印 **L**，橙）由 **IO15** 经 R9(330Ω) 驱动 = 雷达电源指示灯 | R9 + LED4 | ✅ **（更正后新增）** |
| 7 | I²C SDA = **IO6**、SCL = **IO7** | H1 网络标号 | ✅ |
| 8 | ADC 全在 ADC1：A0..A5 = IO0..IO5；IO6 = CH6；IO7 无 ADC | C6 datasheet + IDF `adc_channel.h` | ✅ |
| 9 | USB D−/D+ = **IO12/IO13**，原生 USB Serial/JTAG（无需转换芯片） | C6 datasheet（GPIO12=USB_D-、GPIO13=USB_D+，P1 固定） | ✅ |
| 10 | 控制台 UART0 = IO16/IO17（H2 的 D0/D1） | C6 默认 UART0 引脚 + 原理图 H2 | ✅ |
| 11 | 深睡 EXT1 仅 **IO0..IO7**；IO9 不支持 ext1 | IDF v6.1 `esp_sleep.h` 注释「ESP32-C6: 0-7」 | ✅ |
| 12 | 板载无任何 I²C 器件、无显示屏、无存储 | 通读原理图 | ✅ |
| 13 | 板上有 3 颗「常亮」结构，其中只有 LED1(ON) 是纯电源指示 | R10+LED5 挂 3.3V_RADAR；LED4 挂 IO15 | ✅ **（更正）** |

## 五、本次评审发现的问题（按严重度）

| 级别 | 问题 | 处置 |
|---|---|---|
| **P0** | 雷达电源使能极性一度读反（误判 R2 为 10k 上拉到 5V ⇒ 默认使能、需开漏拉低；实际为 10k 下拉到 GND ⇒ 默认关闭、推挽拉高使能） | 在更高分辨率下逐层重读原理图确认并全面更正；关联风险 R-01；已下发返工通知 |
| **P1** | IO15 与 LED4 共用这一事实最初被漏看，导致「雷达电源指示灯」被错误归给 LED5 | 已更正：LED4 = 雷达电源指示（IO15 驱动）；LED5 = 3.3V_RADAR 轨指示 |
| **P1** | 对「模块是否引出 IO12/IO13」存在不确定性 | 登记为 H-06 待实测；若 MODULE 未引出则「USB 转串口」需改用外接方案 |
| **P2** | 原理图 PDF 文本层无法直接逐字提取（字体重叠、CMap 缺失），早期依赖低分辨率整图判读 | 已改为高分辨率分区渲染读图；并把读图方法写进风险登记册的经验沉淀 |
| **P2** | 深睡按键唤醒（IO9）不在 C6 的 RTC 域，方案存在降级可能 | 已在 demo 规格中要求对该 API 返回值容错，并提供 EXT1 备选 |
