## 二、上板操作清单（按顺序做，每步都有明确判据）

### 第 0 步：接线与串口

| 目的 | 怎么接 | 判据 |
|---|---|---|
| 看日志（推荐先做这个） | USB-C 线插开发板（要**能传数据**的线） | 电脑设备管理器出现「USB 串行设备」；`ESP-IDF: Select port to use` 里能看到该端口 |
| 交互式控制台 | USB-TTL 串口板：TX→H2 的 **D0/RX(IO16)**，RX→H2 的 **D1/TX(IO17)**，GND 共地，115200-8-N-1 | 串口终端能看到启动横幅 |

> ⚠️ 串口板必须是 **3.3V 电平**；5V 电平的发送端不要直连 IO16。

### 第 1 步：基础外设组（5 个 demo，验证板子活着）

| # | 选这个 demo | 预期现象 | 若不符，查这里 |
|---|---|---|---|
| 1.1 | `hello_board` | 串口打印 EDK60 横幅（模组/Flash/MAC/复位原因/引脚表）+ 每 5 秒心跳 | 串口没输出 → 检查烧录成功、端口是否选对 |
| 1.2 | `blink` | 丝印 RX 的黄灯 1Hz 慢闪、丝印 TX 的黄灯 5Hz 快闪 | 灯不亮 → 确认板子上丝印，别把 ON(绿) 当成可控灯 |
| 1.3 | `button` | 按 BOOT 键：串口打印「按下/松开 + 按住时长」；按住 ≥2s 标为长按 | 上电就进下载模式 → 别在上电时按住 BOOT |
| 1.4 | `uart_echo` | 从 IO16 发字符 → 原样回显（ASCII + HEX 双视图）；每 5 秒主动发心跳 | 无回显 → 检查 TX/RX 是否接反、共地 |
| 1.5 | `adc_read` | 每通道打印 raw + 校准 mV；末尾一行 CSV | 悬空脚读数乱跳是正常的；要测电压请共地并**不要超过 3.3V** |

### 第 2 步：板载硬件结论验证（**本次最重要的实测**）

> **推荐路径：直接用 demo 5.1 `radar_bridge` 一步搞定**
>
> 它启动时会自动扫描候选引脚（IO14/IO15/IO2..IO5）找出**哪一根在收数据**，
> 并顺便把波特率也试出来 —— 这同时把下面的 H-01 与 H-04 一起定论，**不用万用表**。
> 只有当你需要确认「电压是否真的到位」时，才需要动万用表（下面的表）。

选 `radar_bridge`，按下面三条逐一确认：

| 编号 | 操作 | 判据 | 对应风险 |
|---|---|---|---|
| **H-01（最重要）** | 看控制台输出的「步骤 1/2：识别接收脚」表格 | **哪根脚收到字节、哪根就是数据线**；表格会把每根脚收到的字节数/字节种类数逐个列出 | R-01 |
| H-02 | 对照 demo 打印的使能脚电平 | 使能脚输出低 → EN≈0V；输出高 → EN≈3.3V，且 3.3V_RADAR 有输出（万用表量 H4 的 P/V） | R-01 |
| H-03 | 观察丝印 "L" 的橙色 LED4 | 使能时应亮（它由使能脚驱动），可作「雷达已上电」的肉眼判据 | R-02 |
| H-04（可选） | 看「步骤 2/2：识别波特率」的评分表 | 字节数多 + 字节种类丰富的那个波特率即为正确值；也可在 menuconfig 直接手填 | — |

#### H-01 判定表（**原理图上 U4 的 EN 网络标号有歧义，必须靠这一步定论**）

原理图在 EN 走线上同时出现 `RADAR_PWR_EN` 与 `IO14`，单页图纸无法唯一判定 EN 接哪个脚。
请按下面这张表判读：

| 你测到的现象 | 结论 | 我要做的事 |
|---|---|---|
| 某根候选脚**收到明显数据流**（如 IO14 收到几千字节、多种字节） | ✅ **可能 A 成立**：EN 接 IO15，IO14 = 雷达数据线 | 关闭该风险项，现有代码无需改动 |
| **IO14 上没有数据，但 IO15 上有** | ❌ **可能 B 成立**：EN 接 IO14，IO15 是数据线 | 把「雷达 TX → MCU 的接收脚」改成 15、把「电源使能脚」改成「不占用」，并重估雷达 UART 方案 |
| 所有候选脚都收不到字节，但橙灯亮、H4 的 P/V 有 3.3V | 模组没在输出数据（波特率不在候选里 / 未插好 / 需先收配置命令） | 按 demo 打印的 6 条排查清单逐条走，把你的实测回给我 |
| 橙灯不亮、H4 的 P/V 为 0V | 雷达电源没上电（使能脚不是 IO15，或 AP7362 的 EN 门限问题） | 请反馈实测数据，我重新读图分析 |
| 橙灯不亮 | IO15 未在驱动 LED4（与读图不符） | 同上，请反馈，我重新读图 |

> **为什么建议先看数据、而不是先量电压**：数据流是**最直接的证据** —— 哪根脚在吐字节，哪根就是模组的数据线。
> 电压只能说明「电源通了」，不能说明「数据线是哪根」。

> 若 **H-01/H-02 不成立**（橙灯不亮 / 3.3V_RADAR 没电压），请立刻告诉我：这意味着雷达模组无法由软件供电，需要改硬件或改用其他控制方式，我会同步修订文档与 demo。

### 第 3 步：雷达数据透传到 PC（你要的核心用途）

选 `radar_bridge`（demo 5.1）：

| 编号 | 操作 | 判据 |
|---|---|---|
| **H-06** | 插 USB-C，设备管理器 → 端口 → 出现「**USB 串行设备**」；用任意串口助手打开它 | 波特率**随意填**（USB CDC 不依赖波特率）；应在里面看到持续刷新的**雷达原始字节**（建议 HEX 显示） |
| 追加 | 在串口助手里发几个字符 | 若本地回环自测开着（默认），会**原样回显** → 证明「PC → 板子」通路也通 |
| 追加 | 看控制台每 10 秒的统计行 | `雷达→USB xxx 字节/xx 次` 持续增长 = 链路在工作 |
| 追加 | 看真实数据时 | 建议在 menuconfig 关掉「本地回环自测」，避免回显混进雷达流 |

> ⚠ **为什么 USB→雷达 这条方向不通**：C6 的 UART1/UART2 没有 IOMUX 默认引脚，
> 且 H4 没引出 MCU→模组 的数据线（IO15 被电源使能占用），所以默认只有
> 「雷达 → PC」。若你改板引出一根空闲 GPIO，把 demo 参数里的
> 「MCU → 雷达 RX 的发送脚」填上即可打通反向。

## 三、遇到的已知限制（不是 bug，先看这里）

| 现象 | 原因 | 处理 |
|---|---|---|
| 丝印 ON 的绿灯一直亮 | 直接由 3.3V 供电，不受程序控制 | 正常，可作对照 |
| `i2c_scan` 扫不到任何器件 | 板上**没有**板载 I²C 器件 | 从 H1 排针外接（SDA=IO6, SCL=IO7, 3V3, GND）；长线请加 4.7k 上拉 |
| `deep_sleep` 时 USB 断开 | 深睡会关闭 USB PHY | 正常；靠 LED 闪次数与唤醒后日志判断 |
| 上电直接进下载模式 | 上电时按住了 BOOT（IO9 是 strapping 脚） | 松开后按 RESET |
| 插 USB 只看到日志开头一段 | 主机枚举期丢日志 | 在 menuconfig 里把 `EDK60 板级配置 → 启动等待` 设为 500~2000ms |
| 同板 3 颗 LED 让深睡电流偏高 | ON(绿,3.3V) + LED5(RADAR,3.3V_RADAR) 在深睡时仍耗电 | 见 `deep_sleep` demo 的功耗说明；如需极致低功耗要改板 |
| 编译时打印 `warning: Private include directory ... belongs to component esp_wifi` | ESP-IDF 自身的组件校验告警（wpa_supplicant 与 esp_wifi 的 include 归属） | 与本工程代码无关，可忽略 |
