# Gate 记录 — EDK60 × EDX106 门锁感应 Demo（demo 5.5）

> 2026-10-27 ｜ 项目经理 ｜ 结论：**GO —— 已上板验证，发布 v1.0.0**

## 一、与前三套的本质差异（决定了本项目的验证方式）

| 维度 | EDV11P / EDV163（三个 demo） | **EDX106 门锁** |
|---|---|---|
| MCU 角色 | 纯字节透传桥（UART→USB） | **I2C 主控 + GPIO 中断**（协议语义在固件里） |
| 配置 | 上位机下发 | **芯片掉电不保存 → MCU 每次上电重配** |
| 接线 | H3 一个插座 | H3 五根线（V/G/SCL/SDA/OUT），**需自行接线** |
| 数据形态 | 二进制帧 / 文本行流 | 触发事件（电平跳变）+ 文本行日志 |
| 站点页面 | 只读 | **读写双向**（`SET`/`LED`/`RESET` 需确认） |

## 二、上板验证结果（2026-10-27，用户现场确认）

### 2.1 一次通过的项目
| 项 | 实测 |
|---|---|
| I2C（**内部上拉**，100 kHz，SCL=IO4 / SDA=IO5） | ✅ `i2c ok freq=100000 pullup=internal` |
| 从机存在性 | ✅ `SCAN` 见 `0x28`；`id reg0x0d=0x0a expect=0x0a` |
| 三个"必须走寄存器"的控制位 | ✅ `0x6e=0xe8(thr_reg=1)`、`0x45=0x01(delay_reg=1)`、`0x6c` mode_reg=1 |
| 配置回读 | ✅ `cfg ok`，13 个寄存器逐字节一致（`verified=1`） |
| OUT 触发 | ✅ `trig=1` → `trig=0 width=2364`（>2000 因二次触发顺延） |
| 橙灯 | ✅ 用户确认「每次触发都看到灯亮」 |
| 闭锁防抖 | ✅ 0.5 s 间隔连挥 3 次 → 仅 1 次事件 |

### 2.2 关键工程结论：**探测距离由功耗模式决定，不是阈值**
| 模式 | 电流（手册） | 实测距离 |
|---|---|---|
| ULP | 78~341 µA | **≈30 cm**（thr=115） |
| **常规** | **≈26 mA** | **≥1.0 m**（thr=70） |

- 两者电流差约 **100 倍**，属芯片工作机制，**调参无法弥合**。
- 1.0 m 场景实测：22 s 内 3 次触发（2.37 / 8.75 / 16.81 s），高电平 2368 / 3198 / 3845 ms。
- **用户确认 1.0 m 满足门锁场景** → 定稿为常规模式。

### 2.3 定稿参数（已进 `sdkconfig.defaults.door_lock_edx106`）
```
常规模式（_ULP_MODE 不设置）  thr=70  delay=2000 ms  lockout=2000 ms
LED 跟随 OUT                  I2C 100 kHz 内部上拉（无需外部电阻）
```

## 三、本项目拦下的坑（工程价值）

| # | 坑 | 处置 |
|---|---|---|
| 1 | **`0x6e` bit6=0 时阈值由外部 pin 决定**，只写 `0x0f/0x10` 静默失效 | 三步强制走寄存器（`0x45`/`0x6e`/`0x6c`）+ 回读校验 + 启动日志打印 |
| 2 | 模组把 delay / burst_en / 阈值档 / 光敏 pin **全部内部绑死未引出** | 一律走寄存器；列为风险 D10 |
| 3 | 板上 I2C 上拉 R13/R14 为 **DNP** 且挂 IO6/IO7（与本接线无关） | 改用 **C6 内部上拉 + 100 kHz**，用户无需任何电阻；外置上拉降级为量产建议 |
| 4 | IO2 是 strapping 脚 | OUT 配输入+内部上拉、不驱动；Plan B = IO3（A3） |
| 5 | ULP 模式导致只能测 30 cm | 切常规模式；**明确"要 1 m 必须常供电"** |
| 6 | 开机自检期 OUT 恒高 3 s | 固件在自检窗口内丢事件；UI/文档标注"自检期非触发" |
| 7 | 高电平宽度 > 设定延时 | 二次触发顺延，属正常；文档写明避免误判 |

## 五、已知边界（对外必须写清）

1. **没有任何续航/平均功耗数字**——模组规格书写「常规 <55 µA」而芯片手册写「常规 ≈26 mA」，两份资料差 3 个数量级，实测未做（待实测 T-5）。
2. **30 分钟长稳未做**（本次最长 22 s）。
3. **深睡唤醒未实现**（OUT 在 IO2，属 C6 EXT1 域，产品化可直接用）。
4. **400 kHz 未验证**（样机全程内部上拉 100 kHz；量产建议外置 2×4.7 kΩ）。
5. `SET` 参数**不落 NVS**，复位即回固件默认（设计上依赖"每次上电重配"，这本身更可靠）。
6. 模组**无光敏**（型号 `EDX106-N-01`），`0x6c` bit4 仅兼容保留。
7. 供电纹波要求 **≤50~100 mV**（规格书），超标会误报。

## 六、经验沉淀

1. **"照抄厂商参考代码"要先判断它的目标场景**：那份配置是**电池门锁省电**用的（ULP），直接拿到"要 1 m 距离"的场景里必然不达标——**功耗参数是场景相关的，不是通用默认值**。
2. **一次只测一个变量**：异步沟通下"按秒走位"无法对齐，固定距离 +（可选的）相对时间轴才是可复现的测法。
3. **回读校验比"写成功"重要**：本芯片有多个"外部 pin 优先"的位，写进去不生效时**回读仍是期望值**（因为回读的是寄存器），所以必须校验**控制位本身**（`thr_reg=1`/`delay_reg=1`），而不只是数值。
