# 项目计划 — EDK60 × EDX106 门锁雷达（正对检测）Demo

> 2026-10-26 ｜ 项目经理 ｜ 状态：**方案阶段**（等用户确认 4 个决策点后开工）

## 一、目标

EDK60（ESP32-C6）通过 **I2C** 配置 EDX106（AT10LP1T1RDB 10.5 GHz 雷达感应芯片），并监测其 **OUT 输出电平**（检测到目标 → 输出高），把「触发事件 + 配置状态」通过原生 USB 报给上位机/网页，形成门锁感应 demo。

与前三个 demo（EDV11P 人数、EDV163 水位、EDV163 手扫）的本质差异：
| 维度 | 前三个 | **本次 EDX106** |
|---|---|---|
| 数据通路 | UART 透传到 USB（MCU 只搬字节） | **I2C 主控 + GPIO 中断**（MCU 主动读写寄存器） |
| 协议位置 | 全在上位机 | **在 MCU**（寄存器语义、时序、状态机都在固件里） |
| 接线 | H3 一个插座 | **I2C 两根 + OUT 一根 + 电源两根**，要自己接 |
| 配置保持 | 上位机下发 | **芯片掉电不保存 → 每次上电必须由 MCU 重配** |

## 二、已核实的硬件事实

### 2.1 芯片侧（AT10LP1T1RDB 寄存器手册 V1.2，11 页，已解析）

| 项 | 值 |
|---|---|
| 总线 | **I2C 从机**，7 位地址 **0x28**（写 0x50 / 读 0x51 的 8 位形式），**最高 400 kHz** |
| 寄存器 | 111 字节，偏移 **0x00~0x6f**，连续读写自动加一；单字节读用**重复起始** |
| **掉电保持** | **不保存**（手册明写"每次上电后需要配置"） |
| 默认可用 | 上电不做配置也能工作（靠外部 pin 定灵敏度/延时） |
| 自检 | 上电自检输出高电平约 **3 s**（0x3c/0x3d，单位 ms，改后需软复位） |

关键寄存器（与用户参考代码逐一对应）：

| 寄存器 | 名称 | 默认 | 作用 | 参考代码写入 |
|---|---|---|---|---|
| 0x00 | Rstn_sw | 0x01 | 0x00 软复位 / 0x01 释放（复位后需重载配置） | — |
| **0x0f/0x10** | signal_det_thr_1_1/1_2 | 0x06/0x00 | 感应阈值低 8 位 / 高 2 位（0~1023） | `threshold` |
| 0x0d | signal_det_len | 0x0a | 窗口长度（默认 10 个采样点 = 50 ms @200 Hz） | 不改 |
| 0x30/0x31 | power_det_win_len/thr | 0x04/0x03 | 观察 4 个窗口、其中 3 个超阈值即触发 | 不改 |
| 0x32 | power_det_ctrl | 0x04 | bit6 关二次触发；bit5:4 GPIO 逻辑（00 高有效/10 低有效） | 不改 |
| 0x5a | gpio | 0x04 | bit0 GPIO 由寄存器控制 / bit2 强制输出 | 不改 |
| 0x3c/0x3d | 自检时间 | 0x0bb8 | 3000 ms | 不改 |
| **0x45** | Time_flag_out_ctrl | 0x00 | **bit0=1 延时由寄存器控制** | `0x01` |
| **0x46~0x49** | Time_flag_out_1~4 | 0x00,0x04,0x00,0x00 | 高电平延时 delay[31:0]，**单位 ms**（默认 0x0400 = 1024 ms） | `delay_time` |
| **0x52/0x53** | time_undet_prot | 0xe8/0x05 | **灭灯保护（闭锁）时间**，单位 ms（默认 0x05e8 ≈ 1512 ms） | `0x07D0` = **2000 ms** |
| 0x60 | rx_tia_gain | 0x33 | 第一级接收增益（3 dB/step，**值越大增益越小**） | `0x33`（默认） |
| **0x6c** | cnf_1 | 0x03 | bit4=1 关光敏；bit6=1 工作模式由寄存器；bit7=0 常规/1 超低功耗 | `0xD3` = 超低功耗 + 关光敏 |
| **0x6d** | cnf_work_time | 0xf3 | bit3=1 参数可调；bit2:0 功耗档（越大越耗电） | `0xF8`（bit2:0=000 = 最低功耗档） |
| **0x6e** | cnf_burst_time / power_th_dr | 0x98 | **bit6=1 阈值由寄存器**；bit5=1 burst 可调；bit4:3 burst 频率 | `0xE8`（bit6=1、字节 4:3=01） |

> 参考代码的意图解读：**超低功耗模式 + 阈值走寄存器 + 延时走寄存器 + 闭锁 2 s + 关闭光敏**，用于电池门锁。
> 注意 0x6e 默认 0x98 的 bit6=0 → 阈值由**外部 pin** 控制；写 0xE8 后 bit6=1，阈值才由 0x0f/0x10 生效。**这两步必须一起做**。

### 2.2 EDK60 侧（既有工程实测结论）

| 资源 | 引脚 | 说明 |
|---|---|---|
| I2C | **SDA=IO6、SCL=IO7**（H1 排针丝印 SDA/SCL） | BSP 已有 `edk60_i2c_init()` / `edk60_i2c_probe()`，默认 100 kHz，**内部弱上拉** |
| 空闲 GPIO | **H2 的 D2~D7 = IO18/19/20/21/22/23** | 全部空闲，可任选一根接 OUT |
| 已占用 | IO4/5（H3 雷达 UART）、IO14（雷达 EN）、IO15（橙灯）、IO8/9（LED/BOOT）、IO16/17（控制台）、IO12/13（USB）、IO6/7（I2C） | 不要复用 |
| USB | 原生 USB CDC（免驱） | 上报事件与配置的通道 |

**建议接线（待用户确认）**：`EDX106 VCC → H1 3V3`、`GND → H1 GND`、`SCL → IO7`、`SDA → IO6`、`OUT → H2 D2（IO18）`。

## 三、方案设计（草案）

### 3.1 固件 demo：`door_lock_edx106`（编号 5.5）

启动流程（严格按手册时序）：
1. `edk60_i2c_init()` → 400 kHz（手册支持）→ probe 0x28 确认在线（**不在线就报错并停在诊断模式**）
2. 读校验：`0x0d` 应为 0x0a（版本/存在性探针）
3. 软复位：`0x00=0x00` → 延时 → `0x00=0x01`（手册：复位后内部重载配置，**复位后须重新写全部配置**）
4. 写配置块（按用户参考值，集中成一张表，Kconfig 可覆盖）：0x6c/0x6d/0x6e/0x0f/0x10/0x45..0x49/0x52/0x53/0x60
5. **回读校验**：把写入的 8 个寄存器读回来比对，不一致就上报 `CFG_MISMATCH`
6. 配置 OUT（IO18）为输入 + 上/下降沿中断；等过自检期（≈3 s，可配）后进入监控
7. 事件上报：每次 OUT 变化 → 打印一行结构化文本（便于网页解析）：
   ```
   EDX106: t=123456 trig=1 hold=2000 lockout=2000 thr=300 mode=ulp
   ```
   并在 `trig=1` 时点亮橙灯（IO15）随延时同步熄灭

诊断/调参（USB 文本命令，只读优先）：
- `CFG?` 回读全部关键寄存器（十六进制 + 语义）
- `SET delay=<ms> thr=<0..1023> lockout=<ms> mode=<normal|ulp> light=<on|off>`（写寄存器 + 回读确认）
- `SCAN` 重扫 I2C 总线
- `TRIG?` 当前电平/最近一次触发时间戳

### 3.2 网页演示 `release/edx106.html`（若确认要）
- Web Serial 连 115200 → 解析 `EDX106:` 事件行
- 大字「有人/无人」+ 触发计数 + 最近触发时间 + 高电平保持时长
- **时序图**（触发脉冲可视化：高电平区间 + 闭锁窗口）
- 配置面板：延时/阈值/闭锁/功耗模式/AI 建议值，写入需确认（沿用前三套的"默认只读 + 显式确认"）
- 模拟演示模式（无硬件）

### 3.3 验证判据（Gate）
1. I2C 通信：probe 0x28 ACK、8 个关键寄存器写入后回读一致
2. 功能：正对 0.5~2 m 移动 → OUT 由低变高，保持 `delay` ms 后回落；闭锁期内再移动**不应**再次触发
3. 时序实测：高电平宽度 vs 配置值偏差（示波器/逻辑分析仪或 MCU 打点）
4. 超低功耗模式下的响应延迟与误触发率（走廊/关门/开门场景各 30 次）
5. 掉电重启后**自动重配**成功（连续 10 次上电）
6. 构建 20/20 回归通过

## 四、风险登记（初版）

| ID | 风险 | P | I | R | 缓解 |
|---|---|---|---|---|---|
| D1 | **配置掉电丢失**：忘了每次上电重配，现场表现为"默认参数、灵敏度不对" | 4 | 4 | **16** | 上电必走配置块 + 回读校验 + 不匹配上报 |
| D2 | 0x6e bit6=0 时阈值由**外部 pin** 控制，只写 0x0f/0x10 不生效 | 4 | 4 | **16** | 0x6e 与 0x0f/0x10 **同一事务**写入并回读校验 |
| D3 | I2C 上拉不足（板内弱上拉 + 外接线长）导致 ACK 不稳 | 3 | 4 | 12 | 400 kHz 先降到 100 kHz 验证；必要时并 4.7 kΩ 上拉 |
| D4 | OUT 电平极性/驱动能力与 EDK60 输入不匹配（开漏需上拉） | 3 | 4 | 12 | 上电先用万用表/逻辑分析仪确认；固件支持极性 Kconfig |
| D5 | 超低功耗模式降低灵敏度/响应变慢（手册明确影响距离） | 3 | 3 | 9 | 两档模式都测，给出对比数据 |
| D6 | 强光/金属门/走廊人流造成误触发 | 3 | 3 | 9 | 阈值推荐区间 + 光敏开关策略 + 现场调参记录 |
| D7 | 自检期 ≈3 s 内输出为高，被误判为"有人" | 3 | 3 | 9 | 固件在自检期丢弃事件并上报 `SELFCHECK` |
| D8 | 软复位后配置被重载，若复位与写配置顺序错则参数不生效 | 2 | 4 | 8 | 固定顺序：复位 → 释放 → 全部写入 → 回读 → 才开中断 |

## 七、硬件规格书判读结果（2026-10-26 补充）

模组规格书 `edx106.pdf` 是**纯扫描件**（无文本层），已用 PyMuPDF 渲染后逐页目视判读（4 页全部读清）。

### 7.1 关键事实
| 项 | 值 | 影响 |
|---|---|---|
| 模组引脚 | **只有 5 个：V / G / SCL / SDA / O** | 无 delay pin、无 burst_en、无光敏脚、无复位脚（型号 `EDX106-N-01`，N=无光敏） |
| 电气 | 输入 **2.7~4.8 V**，输出 **3.3 V±0.1 V**（推挽） | 与 EDK60 3.3 V 直连，**不需要电平转换** |
| 频率/波束 | 10.525 GHz，波束 **79.7°(XZ) / 128.7°(YZ)** | 正对检测张角很大，安装角度容忍度高但需防侧向误触发 |
| **纹波要求** | **≤50~100 mV** | 超标会误报（电源质量比电流更重要） |
| 供电余量 | 3.3V_RADAR（AP7362-33SP-13，1.5 A）vs 模组需求 | 余量极大，**PC USB-C 供电足够，不需要外部电源** |
| I2C | 7 位 **0x28**、≤400 kHz、无地址选择脚 | 与 AN-003 两处独立印证 |

### 7.2 三条新增风险
| ID | 风险 | P | I | R | 缓解 |
|---|---|---|---|---|---|
| D9 | **两份资料电流差 3 个数量级**：模组规格书「常规 <55 µA」vs 芯片手册「常规 ≈26 mA」；模组规格书无 ULP 档；两份都无峰值电流 | — | 3 | 观测项 | **不对外发布任何续航/电流数字**；交 T-5 实测裁决 |
| D10 | **模组把芯片三个"外部 pin 控制"（delay / burst_en / 阈值 8 档）全部内部绑死、未引出** → 不做寄存器配置时的实际行为未知 | 3 | 4 | 12 | 固件**强制走寄存器**：`0x45` bit0=1、`0x6e` bit6=1、`0x6c` bit6=1，并回读校验这三处 |
| D11 | **电源纹波 >100 mV 会误报**（规格书明写） | 3 | 3 | 9 | 用 PC USB-C 供电；若改电池/适配器需实测纹波 |
| D12 | 板上 R13/R14（4.7 kΩ I2C 上拉）**DNP 未贴片**，且挂在 IO6/IO7 网络（本次不用） | 4 | 3 | 12 | **H3 侧外并 2×4.7 kΩ**；400 kHz 失败自动降 100 kHz |

### 7.3 对固件的三条硬约束（已下发给嵌入式）
1. `0x6c` bit4（关光敏）在本型号**无实际作用**（模组无光敏脚），保留写 1 并注明"兼容保留"。
2. **`0x45` bit0=1 + `0x6e` bit6=1 + `0x6c` bit6=1 三者缺一不可**，回读日志必须打印这三个寄存器实际值。
3. 软复位**不改变已写寄存器内容**（AN-003 §3.1），但启动顺序仍按「复位→释放→写全配置→回读→开中断」执行（两种理解下都安全）。

### 7.4 用户最终接线（覆盖早期建议）
`EDX106 V→H3 V`、`G→H3 G`、**`SCL→H3 T (IO4)`**、**`SDA→H3 A (IO5)`**、**`OUT→H3 A2 (IO2)`**；IO14 拉高给模组上电；**H3 侧外并 2×4.7 kΩ** 上拉；**OUT 加 10 kΩ 上拉**（IO2 是 strapping 脚）。
选 IO2 的一个额外好处：**IO2 在 GPIO0~7 内，可用于 EXT1 深睡唤醒**（产品化"有人才唤醒 MCU"无需改脚）。

## 八、上板实测记录（2026-10-26/27）

### 8.1 接线与通信：一次通过
| 项 | 实测 |
|---|---|
| I2C（**内部上拉**，100 kHz，SCL=IO4 / SDA=IO5） | ✅ `i2c ok freq=100000 pullup=internal`，`SCAN` 见 `0x28` |
| 芯片存在性 | ✅ `id reg0x0d=0x0a expect=0x0a` |
| 三个控制位 | ✅ `0x6e=0xe8(thr_reg=1)`、`0x45=0x01(delay_reg=1)`、`0x6c=0xd3(mode_reg=1)` |
| 13 寄存器回读 | ✅ `cfg ok` / `cfg state verified=1` |
| OUT 触发 | ✅ `trig=1` → `trig=0 width=2360`（>2000 因二次触发顺延） |
| 闭锁/防抖 | ✅ 0.5 s 间隔连挥 3 次 → **仅 1 次事件**（width=2915） |

> **实践结论**：用户手上**没有任何外部电阻**，全程用 C6 内部上拉 + 100 kHz 即可稳定工作 → 原计划里"必须外并 2×4.7 kΩ"降级为**量产建议**，不阻塞样机验证。

### 8.2 探测距离不足（关键问题，排查中）
| 参数组合 | 实测探测距离 |
|---|---|
| thr=300 **+ ULP 模式**（初始默认） | 要贴很近 |
| thr=115 **+ ULP 模式** | **约 30 cm** |
| thr=70 **+ ULP 模式** | 待测（已在线下发 `rd=70` 回读通过） |
| **thr=70 + 常规模式** | **待测（本次重点）** |

**判断**：ULP 是 burst/duty-cycle 扫描（手册功耗 78~341 µA），探测距离被占空比直接压掉；阈值只是次要因子。目标是 **1 m 级**，因此先切常规模式（≈26 mA）测最大距离，再回头做功耗取舍。

**新增在线调参能力**（避免每次改都要重编）：
`SET mode=ulp|normal`、`SET gain=<0..15>`（0x60 bit7:4，值越小增益越大）、`SET win=<len>,<total>,<cnt>`（0x0d/0x30/0x31）、`SET thr=`、`SET delay=`、`SET lockout=`；以及 `LED on|off|blink|?`、`CFG?`、`SCAN`、`TRIG?`、`RESET`。

### 8.3 新增工具
`tools/edx106_capture.py`：抓取并统计触发事件（次数、宽度 min/max/avg、相对 delay 偏差、触发间隔与闭锁违例），落 CSV，用于"距离 vs 参数"对照实验。

### 8.4 待办
1. 常态模式 + thr=70 的实测距离（本机录制中）
2. 若仍不足 1 m：按 `mode → thr → win<2> → gain` 顺序继续压
3. 定型后在「功耗 vs 距离」之间做产品决策（电池门锁 vs 常供电门锁是两套配置）
### 8.5 实测结论（2026-10-27 定稿）
| 配置 | 阈值 | 实测距离 |
|---|---|---|
| ULP | 300 | 需贴很近 |
| ULP | 115 | ≈30 cm |
| **常规** | **70** | **≥1.0 m（定稿）** |

- **瓶颈是功耗模式，不是阈值**：ULP 是 burst/duty-cycle，电流差约 100 倍；1 m 级只能常供电。
- 用户确认：**1.0 m 满足门锁场景**；**橙灯每次触发都亮**。
- 定稿参数（已进 defaults）：常规模式 + thr=70 + delay=2000 + lockout=2000 + LED 跟随 + I2C 100 kHz 内部上拉。
- 已知限制：本 demo 只做"在线监测 + 亮灯"，未做深睡唤醒（OUT 在 IO2，属 EXT1 域，产品化可直接用）。
