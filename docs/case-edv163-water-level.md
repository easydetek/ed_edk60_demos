在水箱、水塔、地下水池、雨水调蓄池这类地方做**水位监测**，传统做法是装浮子式 / 投入式 / 超声波液位计：
浮子要跟水接触、会卡涩、会结垢；投入式探头长期泡在水里，要防腐蚀、要定期清洗；超声波受温度分层与蒸汽影响大。
而很多现场真正需要的并不是「计量级读数」，而是**「水位现在大概多少、在涨还是在降、离满罐还有多远」**。

我们用 **EDK60 开发板**（ESP32-C6）桥接 **EDV163 60 GHz 雷达模组**，做了一套**非接触水位监测**的参考方案：
模组吊在容器上方、天线朝正下方，测「到水面的距离」（mm）；ESP32-C6 把串口字节**原样**搬到**芯片原生 USB**，
浏览器打开一个单文件网页就能看到水位曲线与水位柱——**不需要 USB 转串口芯片、PC 端不需要装任何驱动**。

水位的换算只有一行：**`水位 = 挂高 − 到水面距离`**。其中「挂高」是传感器天线罩下沿到水位零点的垂直距离，
必须**显式下发给雷达**（出厂默认 3000 mm，忘了改就会整体偏 1 m）。

> **⚠️ 验证状态（必读）**：固件、网页、工具都已就绪并通过无硬件自测（页内用例 **10/10**、桩环境 **44/44**、
> 布局契约 **32/32**、帧校验工具 `--selftest` **36 行对账全过**）；但**这套链路还没有在 EDV163 实物上跑过**——
> 手上那颗模组当前烧的是「挥手」固件，连 `45 44` 帧头都抓不到，`GET` 命令无应答。
> **因此本文没有任何实测性能数字**：帧率、坏帧率、水位精度、漂移全部标着「待实测」。
> 文中的协议帧是**按规则程序化生成/自测合成**的，不是设备抓包。

## 场景需求

| 需求 | 说明 | 方案如何满足 |
|---|---|---|
| **不接触水** | 污水、含砂、含腐蚀性介质的水，探头越少接触越好 | 60 GHz 雷达测距，吊在容器上方**非接触**测量 |
| **无机械件** | 浮子会卡涩、绳缆会缠绕；现场往往没人维护 | 没有浮子、没有导轮、没有运动部件，**无机械磨损** |
| **只看趋势，不看 0.1 mm** | 真正要回答的是「在涨还是在降、离满罐多远」 | 水位显示整数 cm；页面明写「受 8 cm 级分辨率限制，适合趋势/相对变化」 |
| **一台设备一根线** | 现场少装一件是一件 | 单点吊装 + 板载 USB-C：数据与供电同一根线 |
| **免驱动接入 PC** | 现场电脑常是受控/云桌面环境，不能装驱动 | ESP32-C6 原生 USB CDC，插上就是串口 |
| **上位机可替换** | 客户已有自己的平台或网关 | 桥接固件**纯字节透传**，不解析、不加工；协议公开，谁都能写上位机 |

**为什么用雷达而不是超声波**：60 GHz FMCW 的波束窄、不受气压/温度分层影响，对水面这种**平坦镜面**目标
反射条件好；缺点是**对镜面质量极其敏感**——波纹超过约 0.6 mm 就会把镜面回波打成漫反射。这条限制在「已知限制」里写清楚了。

## 方案构成

```text
EDV163 60 GHz 雷达模组（吊装，天线朝正下方）
   │  UART 256000 8N1（模组 TX → IO4，模组 RX ← IO5）
   ▼
EDK60（ESP32-C6）——纯字节双向透传：不解析、不组帧、不做转义、不下发命令、不算水位
   │  芯片原生 USB CDC（免驱动）
   ▼
浏览器（单文件网页 level.html）：还原转义 → 切帧 → 校验和 → 解 0x81 → 水位 = 挂高 − 距离
```

| 环节 | 器件 / 技术 | 关键点 |
|---|---|---|
| 感知 | EDV163（二进制协议 V2.0，设备 ID `EDV163_VB`） | 主动上报 `op=0xA3 / type=0x81`：通道数 + 每通道 **7 字节**（含 `target_distance` 2 B 大端，mm） |
| 主控 | ESP32-C6（EDK60_VA V1.0） | UART1 与模组通信（**256000** 8N1），原生 USB 与 PC 通信，两路各自独立 |
| 连接 | 芯片原生 USB Serial/JTAG | 省掉 USB 转串口芯片与驱动；USB CDC 对波特率不敏感，填 256000 只为与线速对齐 |
| 供电 | PC 的 USB-C 口 | 模组典型 **11 mA ± 2 mA**、综合 **&lt; 0.1 W**；板载 LDO（AP7362，1.5 A）余量 ≥50×，**不需要外部适配器** |
| 上位机 | 单文件网页（Web Serial） | **默认只读**：连上只发 8 条 GET，写入必须你在确认框点确定且逐条等应答 |

## 接线与安装

| 信号 | EDK60 侧 | 模组侧 | 说明 |
|---|---|---|---|
| 模组 TX → MCU RX | **IO4** | H3 排针 `T` 脚 | 数据入口（水面距离全靠这条线） |
| 模组 RX ← MCU TX | **IO5** | H3 排针 `A` 脚 | 下发配置（挂高、上报频率、工作模式） |
| 雷达电源使能 | **IO14**（高有效） | — | 上电后常高；丝印 `RADAR` 红灯 = 已上电 |
| 电源 / 地 | `3.3V_RADAR` / `GND` | `V`、`P` / `G` | 3.3 V 单电源，**不需要电平转换** |
| 串口参数 | **256000 / 8N1**，无流控 | — | **不是** EDV11P 那套的 921600 |

:::warning 模组必须插 H3，不要插 H4
板上 H3 与 H4 两个 8 pin 排针**信号集合相同但顺序相反**：
H3 = `RES A R T G V P`，H4 = `RES P V G R T A`。
H4 的 `T` 脚与雷达电源使能在同一侧的网络关系上，插 H4 会让电源与数据互相干扰，
症状是「红灯亮着、却一个字节都没有」或「偶发丢帧」——最难查的那一类。
另外：**禁止在雷达已上电（红灯亮）时插拔模组**。
:::

## 关键工程点

### 1. 为什么选「雷达 + 非接触」

| 方案 | 接触介质 | 机械件 | 主要失效模式 |
|---|---|---|---|
| 浮子式 | 接触 | 浮子、绳缆、导轮 | 卡涩、缠绕、结垢，需人维护 |
| 投入式（压力） | **长期浸泡** | 无 | 探头结垢/腐蚀、零点漂移，需定期清洗标定 |
| 超声波 | 不接触 | 无 | 温度分层、蒸汽、泡沫影响大；需温度补偿 |
| **60 GHz 雷达（本方案）** | **不接触** | **无** | **水面波纹/泡沫/结露破坏镜面回波**（见已知限制） |

代价要说清楚：**它换掉了机械件，但换来了「对水面状态敏感」**。平静水面是优良镜面（垂直入射回波强），
一旦起波纹、起沫、结露，回波可能掉 10~20 dB。所以现场要么有静水条件（静水井/导波管），
要么在水面放一个**低密度浮子反射靶**（泡沫/EPE，直径 ≥150 mm）——它同时抑制波纹、提升回波。

### 2. 水位 = 挂高 − 距离（原理与那个必踩的坑）

```text
挂高 mount  = 天线罩下沿 → 水位零点（空罐水面/罐底）的垂直距离   （系统零点，单位 mm）
距离 dist   = 雷达上报的 target_distance                        （到当前水面的距离，单位 mm）
水位 level  = mount − dist
```

符号约定：**空罐** → 距离 ≈ 挂高、水位 ≈ 0；**水位 h** → 距离 ≈ 挂高 − h。
手边没有工具时可以用这一条自查：手在水面附近上下移动，**距离与水位的方向一定相反**。

三个必须写进心里的推论：

1. **挂高错 100 mm，全量程就错 100 mm**，而且是**没有任何报错**的系统性偏差。
2. **出厂/驱动默认挂高是 3000 mm**。你按 2000 mm 换算却忘记下发 `0x25 = 2000`，水位就**整体偏 1 m**。
   所以流程必须是：连上 → 先 `GET 0x25` 回读 → 再 `SET 0x25` → 页面把「回读 ≠ 设定」**标红**。
3. **挂高不是「传感器到容器口」**，也不是「传感器到当前水面」。换容器、移位、改支架后**必须重标**。
   标定只有一步关键：空罐时用卷尺量真值 `H0`，**用 `H0` 当挂高**（不要用雷达测到的 `D0`，
   否则把模组偏差写进了零点）。

### 3. 工程坑一：帧尾 `0x0A` 与字节转义

EDV163 的帧是 `45 44 | 长度 | msgid | op | type | tlv_len | 数据 | 校验和 | 0x0A`，
并且**正文里的 `0x0A` 和 `0x09` 必须转义**：`0x0A → 09 01`、`0x09 → 09 00`（**帧尾不转义**）。

这带来三个连锁后果，每一个都能单独把解析器打挂：

| 后果 | 说明 |
|---|---|
| **长度不是线上字节数** | 长度字段按**转义前**算（`12 + N`，含帧尾）。同一个逻辑帧，线上可能多出若干字节 |
| **帧尾 `0x0A` 与正文 `0x0A` 长得一样** | 接收侧必须靠「前面有没有 `0x09` 引导」来区分；用「按 `0x0A` 切分」这种偷懒办法必错 |
| **日志污染升级为致命** | EDV11P 的帧没有帧尾，混进一行日志只是「插在帧之间」；EDV163 的帧尾就是换行，**任何文本日志的 `0x0A` 都会切断当前帧** |

还有一个更隐蔽的：**`target_distance` 的高/低字节很容易落在 `0x09`/`0x0A` 上**
（`2569 mm = 0x0A09`、`1497 mm = 0x05D9`），所以转义不是「偶发情况」，而是**每一帧都在被检验**。
校验和字节本身也可能是 `0x09`/`0x0A`。

> 连「简单」的 SET 帧都会中招：`SET 0x17 = 10`（上报频率 1 s）的 value 就是 `0x000A`，
> 这条帧必须写成 `… 00 09 01 5C 0A`——声明 14 B、**线上 15 B**。手工拼帧忘了这一步，设备会把它当截断帧丢掉。

### 4. 工程坑二：0x81 载荷是 7 字节/通道，不是 8 字节

协议文档 §3 写「每个通道 **8 字节**」，但**同一段紧接着列出的字段只有 6 项、合计 7 字节**。

| 证据 | 结论 |
|---|---|
| 驱动 `edv163_channel_data_t` 是 `packed` 结构，字段 `channel / delay_presence / target_state / motion_direction / target_distance(2) / target_angle(1)` | `sizeof = 7` |
| 驱动 `edv163.c` L372-390：读到 `channel_count` 后按 **7 字节**顺序读取 | 解析实现按 7 |
| 反推 | `tlv_len = 1 + 7×count`（1 通道 → 8、2 通道 → 15、3 通道 → 22） |

**为什么这个笔误会「藏起来」**：单通道帧 `tlv_len = 0x0008`，按 8 B 解析**恰好不报错**；
一旦设备上报 2 通道（`tlv_len = 0x000F`），整个载荷**错位 1 字节**，距离与角度全变成垃圾值，而且**不报错**。
所以网页与帧校验工具都把步长**钉死为 7**，并且 `tlv_len ≠ 1 + 7×count` 时**显式判载荷异常、点明口径**，
绝不按 `tlv_len/8` 去猜通道数——猜错就是静默渲染垃圾数据。

### 5. 静水面会被判「无人」

EDV163 本质是**人体存在检测算法**的衍生品。静止水面没有微动、RCS 也远小于人体，
很可能被判定为 `delay_presence = 0`、`target_state = 0`（无人）。

如果上位机写成「只有 presence = 1 时才取距离」，静水场景就会**长时间没有水位数据**——
现场看起来就是「设备坏了」。本方案的处理是：

- **上位机一律直接读 `target_distance`**，只做两种有效性判断：距离 = 0（无回波）、距离 > 挂高（超量程）；
- `presence` / `target_state` **只作展示**；
- 界面明写「判定：无人（静水面）」并加一行口径提示，避免使用者误判为故障；
- 这条逻辑被页内自测用例 C9 钉死（`presence=0, state=0, distance=1234` → 水位必须算出 766 mm）。

同时把设备侧参数往「别急着判无人」的方向调：`0x1D`（30 min 强制无人）**关**、`0x1C`（无人后持续存在检测）**关**、
`0x11`（检测延时）放宽到 **5 s**。

## 已知限制

写清楚没做的部分，比写清楚做了的部分更重要：

| 限制 | 现状 |
|---|---|
| **未实机验证** | 全部上板用例未做（模组固件不是水位版）。本文不含任何实测性能数字 |
| **分辨率 8 cm 级** | 水位绝对精度按 **±1 个分辨率单元（≈80 mm）** 预期，**不是计量级液位计**；页面只显示整数 cm |

| **近距盲区未知** | 最小可测距离没有规格标注也未实测 → 满罐水位上限只能保守留余量 |
| **通道语义待确认** | `0x81` 带 `channel` 字段、`count` 可为 1~3；本方案按单通道设计，多通道与安装位置的对应关系待上板确认。**与目标 ID 无关**：不追踪、不合并 |
| **`0x28`/`0x29` 未使用** | 自动测高不发（会绕过标定）；屏蔽区只认类型名、不解析 13 B×N |
| **接线有一处悬念** | H3 的 `A`/`R` 两脚「读图 vs 实测」不一致，尚未用万用表定论（定论前不要插满脚） |
| **只测了一条供电路径** | 只用 USB-C 直连 PC；未实测峰值电流。若走板载 DC-005，注意板上是 **LM2596 降压**，要 7~12 V（不能照抄别处的「5 V/2 A」） |
| **未做长期老化** | 计划内最长用例 30 分钟，没有 24 h / 7 天数据，也没有结露、蒸汽环境的量化结论 |
| **浏览器限制** | Web Serial 只在 Chrome / Edge 89+ 可用，需 https 或 localhost；Firefox / Safari 不支持 |
| **不承担计量/安全结论** | 水位是换算结果，未经计量标定，不可用于结算、报警、防洪等有责任后果的场景 |
