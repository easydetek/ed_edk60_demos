# 用 EDK60 配置 EDX106 门锁雷达模组——有人触发（I2C 寄存器 + OUT 电平）

> **一句话**：一块 EDK60_VA 开发板 + 一颗 **EDX106-N-01**（AT10LP1T1RDB，10.5 GHz 频段）雷达模组，
> **只用 5 根线、一个外接电阻都不用**，MCU 通过 **I2C（7 位地址 `0x28`）** 每次上电把 7 组参数写进芯片并逐字节回读校验，
> 然后把芯片 **OUT 引脚的电平变化**翻译成一行一条的 USB 文本事件，橙灯跟着亮。
> 人手在模组正前方 **1.0 m** 内移动 → `EDX106: t=… trig=1` → 高电平保持 2 s 左右 → `trig=0 width=…`。
>
> **这套方案与前三个（EDV11P 人数 / EDV163 水位 / EDV163 手扫）最不一样的一件事**：
> 前三个是「MCU 只搬字节」，**这一套 MCU 是主动方**——寄存器语义、写入顺序、时序、状态机全在固件里。
> 而且这颗芯片**配置掉电不保存**，所以「每次上电重配 + 回读校验」不是可选项，是本 demo 存在的理由。

### 1.2 做好之后你会看到什么

人手在模组正前方移动，USB 口上就会滚出这样的行（每行 `\r\n` 结尾，全部以 `EDX106: ` 开头）：

```text
EDX106: t=2370 trig=1 level=1 delay=2000 lockout=2000 thr=70 mode=normal
EDX106: led on (trigger)
EDX106: t=4738 trig=0 width=2368
EDX106: led off (release)
```

同时**板上丝印 `L` 的橙灯亮起约 2 s**，然后熄灭。

| 界面元素 / 通道 | 内容 |
|---|---|
| **网页测试页** | 大字「有人 / 无人」、触发计数、最近触发时刻、高电平保持时长、闭锁窗口可视化（见 5.1） |
| **命令行** | `CFG?` / `SCAN` / `TRIG?` / `SET` / `LED` / `RESET` 六类命令，全部即敲即回（见 5.2） |
| **橙灯** | 跟随 OUT 电平：触发亮、回落灭（实测确认） |

> **关键预期管理**：本 demo 的输出是**一行一条的文本事件**，不是波形也不是点云。
> 它回答的是「此刻有没有人在门前动」，**不回答「是谁」「离得多远」「往哪走」**。
> 想要距离与坐标，那是另一类模组（本次这颗只给 OUT 高低电平）。

1. **一条完整链路**：EDX106 模组 →（I2C 两根 + OUT 一根 + 电源两根）→ EDK60 →（原生 USB，免驱）→ PC / 浏览器
2. **实测确认的接线表**（H3 五根线，零外部电阻，见 3.2）
3. **两种烧录路径**（本地 `build_all.ps1` + `idf.py`；以及「烧 `0x0`」的单文件合并固件）
4. **一份可照抄的寄存器配置表** + **13 字节回读校验** + **三个「缺一不可」的控制位**

## 3. 接线

### 3.1 先认清 H3 的丝印顺序（本链路最容易搞错的一处）

板上有两个 8 pin 排针，**同一物料、同一信号集合、顺序完全相反**：

| 脚位（自上而下） | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|
| **H3**（雷达插槽，**用这个**） | RES | **A** | **R** | **T** | **G** | **V** | **P** | RES |
| **H4**（**不要用**） | RES | P | V | G | T | R | A | RES |

- 证据：`docs/SCH_EDK60_VA.pdf` 文本对象逐脚还原 + `docs/EDK60-pinmap.md` 的**上板实测**结论
  「模组必须插 H3，H4 会导致电源与数据互扰」。
- 本 demo 只用 H3 的 5 个脚，`RES`（1、8 脚）、`R`（3 脚）、`P`（7 脚）**全部空置**。

### 3.2 五根线（用户最终接线，以此为准）

| EDX106 引脚 | 接到 EDK60 | GPIO | 方向 | 说明 |
|---|---|---|---|---|
| **V** | H3 的 `V` | — | 电源入 | 走 `3.3V_RADAR` 轨，**由 IO14 使能**，固件启动即拉高 |
| **G** | H3 的 `G` | — | 地 | 共地 |
| **SCL** | **H3 的 `T`** | **IO4** | MCU → 模组 | 走 GPIO matrix 硬件 I2C。⚠ 这根脚原本是模组 TX，本次改作 SCL |
| **SDA** | **H3 的 `A`** | **IO5** | 双向 | 同上，原本是 MCU TX，本次改作 SDA |
| **O（OUT）** | **H3 的 `A2`** | **IO2** | 模组 → MCU | **默认高有效**：检测到目标输出高。只配输入 + 内部上拉，**固件从不驱动它** |

```text
EDK60 H3 排针                      EDX106 模组（5 脚）
┌──────────────────────┐          ┌─────────────────────┐
│  RES                  │          │                     │
│  A   ──[IO5]──────────┼──────────┤ SDA                 │
│  R                    │          │                     │
│  T   ──[IO4]──────────┼──────────┤ SCL                 │
│  G   ─────────────────┼──────────┤ G                   │
│  V   ──3V3_RADAR──────┼──────────┤ V                   │
│  P                    │          │                     │
│  RES                  │          └─────────────────────┘
└──────────────────────┘
        A2  ──[IO2]──────────────────  O（OUT，默认高有效）
```

上电顺序（防经 IO 灌电流）：**先接 GND → 再接 VCC → 最后接 SCL / SDA / OUT**；拆线顺序相反。

### 3.3 为什么必须走 H3

1. **H3 的 `T`/`A` 落在 IO4/IO5**，与 `3.3V_RADAR` 的使能网络不冲突；H4 把顺序镜像过来，
   `T` 与**雷达电源使能**处在同一侧的网络关系上，会出现「红灯亮着、却一个 ACK 都没有」这类最难查的现象。
2. **`A2` 落在 IO2**，正好在 GPIO0~7 范围内 → 将来做「有人才唤醒 MCU」时**不需要改脚**（见 3.6）。

### 3.4 上电自检：只看一个灯

| 灯 | 丝印 | 含义 | 能不能判断雷达供电 |
|---|---|---|---|
| 绿 | `ON` | 主板 3.3 V 正常 | 不能 |
| 橙 | `L`（IO15 驱动） | 本 demo 里**跟着 OUT 亮灭**（触发指示） | **不能**（它是指示灯，不是电源灯） |
| **红** | **`RADAR`** | 直接挂在 `3.3V_RADAR` 轨上 | **能——红灯亮 = 雷达已上电** |

**电源使能是 IO14，高有效**，且板上的使能脚经 10 kΩ **下拉**到地 → **上电默认是关的**，
固件启动后主动拉高才给雷达供电（这个顺序是安全的：MCU 复位时雷达一定先掉电）。

```text
① MCU 启动（主 3.3 V + USB 枚举稳定）
      ↓
② 固件先把 OUT(IO2) 配成输入 + 内部上拉（模组还没上电，防浮空）
      ↓
③ IO14 拉高 → 3.3V_RADAR 建立 → 丝印 RADAR 红灯亮
      ↓
④ 等 ≥100 ms（上电稳定）→ I2C 建总线 → probe 0x28
      ↓
⑤ 软复位 → 写 7 组配置 → 回读 13 字节 → 挂 OUT 中断
      ↓
⑥ 自检窗口（≈3000 ms，从模组上电起算）内**丢弃所有 OUT 事件**
```

**失败先查**：

| 现象 | 先查什么 |
|---|---|
| 一个灯都不亮 | USB 线是不是充电线；换 USB 口（台式机优先机箱后面）；换一根线 |
| 绿灯亮、**红灯不亮** | 模组没插紧 / 插到了 H4 / 固件没把 IO14 拉高（确认烧的是 `door_lock_edx106`） |
| 红灯亮、`SCAN` 扫不到 `0x28` | 进 9.2：先查 SCL/SDA 是否接反、再降频到 50 kHz、最后考虑外置上拉 |

### 3.5 上拉、电平、以及「走 H3 的代价」

| 项 | 事实 | 依据 |
|---|---|---|
| I2C 上拉 | **不需要外部电阻**：全程 ESP32-C6 内部上拉 + **100 kHz** | 2026-10-27 首次上板即通过（`pullup=internal`） |
| 板上 R13/R14 | **DNP 未贴片**，且挂在 **IO6/IO7** 网络 → 与本次用的 IO4/IO5 **无关** | 原理图 + 本工程既有结论 |
| 外置上拉什么时候要 | 想跑 **400 kHz**、或跳线 **>10 cm**、或出现 ACK 不稳 | 量产建议（**待实测**，见附录 C） |
| 电平转换 | **不需要**：模组输入 2.7~4.8 V、输出 3.3 V±0.1 V 推挽 | 模组规格书 |
| **走 H3 的代价** | **不能同时接 EDV11P / EDV163**（共用 IO4/IO5 这组脚） | 本工程四个雷达 demo 的接线互斥关系 |

> ⚠️ **一次只能跑一个雷达 demo。** 想切回 EDV11P/EDV163 时，要先拔掉 EDX106 的线并重新烧对应固件——
> 否则两边同时占用 IO4/IO5，会出现「谁都通不了」的现象，而现象本身**不会告诉你是接线冲突**。

### 3.6 IO2 是 strapping 脚：一条「现在能跑、产品化要看」的约束

IO2 属 **GPIO0~GPIO7**，是 C6 的 **strapping 关注脚**，同时也在 **EXT1 深睡唤醒域**内。

| 需求 | 该用哪根脚 | 本 demo 怎么处理 |
|---|---|---|
| 在线监测 OUT 电平 / 边沿中断（当前形态） | **IO2**（H3 的 `A2`） ✅ | 已经在用 |
| 产品化「有人靠近才唤醒 MCU」（电池门锁必需） | 仍在 **IO2** 即可（同属 EXT1 域） | 本 demo **未实现**深睡唤醒（附录 C ③） |
| 若上电偶发异常 / 偶发进下载模式 | **Plan B：改用 H3 的 `A3`（IO3）** | 改动只有两步，见下 |

**Plan B 怎么落地**（已验证「改一行 Kconfig 即可」，本 demo 未触发过）：

1. Kconfig 里把 `APP_EDK60_EDX106_OUT_GPIO` 改成 **3**；
2. 把模组 OUT 那根线从 H3 的 `A2` 挪到 **H3 的 `A3`**；
3. 重新构建烧录。IO3 **不是 strapping 脚**，同样在 EXT1 域内，源码不需要改。

> 固件侧的三条纪律（都在代码里守着）：**只配 `GPIO_MODE_INPUT` + 内部上拉、从不 `gpio_set_level()`、
> 先配引脚再给模组上电**。因为从不驱动，所以不会影响 C6 的 strapping 判定。

## 6. 寄存器与配置逻辑（本文最重要的一章）

**这一节的结论全部来自 AN-003《AT10LP1T1RDB 寄存器读写说明》V1.2 + 本固件实现**。
换了芯片/代次就以新手册为准，不要相信任何二手转述（包括本文）。

### 6.1 为什么每次上电都必须重配

| 事实 | 后果 |
|---|---|
| 芯片寄存器**掉电不保存**（手册明写「每次上电后需要配置」） | MCU 每次上电都要把 7 组参数重新写进去 |
| 出厂默认值**不是**门锁要的值（`0x6e` 默认 `0x98`、`0x45` 默认 `0x00`、`0x6c` 默认 `0x03`） | 不配就是「出厂行为」：阈值走 pin、延时走 pin、模式走 pin，**这三条在模组上全部落空**（见 6.2） |
| 软复位**不改变已写寄存器内容**（手册明写） | 所以「复位→写配置」两种理解下都安全，固件固定一个顺序，不做分支 |

**这就是本 demo 的核心价值**：不是「读一个传感器」，而是**每次上电把一颗需要配置的芯片带回已知状态，
并且用回读校验证明它真的在状态里**。

固件启动序列（严格顺序，每步失败都有明确上报）：

| # | 动作 | 失败会打印 |
|---|---|---|
| 0 | 先把 OUT(IO2) 配成输入 + 内部上拉（**在模组上电之前**） | `err OUT_INIT` |
| 1 | IO14 拉高 → 等 ≥100 ms | `err PWR_INIT` |
| 2 | 建 I2C 总线（内部上拉，100 kHz） | `err I2C_BUS_INIT` |
| 3 | `probe 0x28`，失败**逐级降频**（配置值 → 100 kHz → 50 kHz） | `err I2C_NO_DEVICE` + 提示加外置上拉 |
| 4 | 读 `0x0d`（期望 `0x0a`）作存在性探针 | 只打印实际值，不一致不中止 |
| 5 | 软复位 `0x00=0x00` → 10 ms → `0x00=0x01` → 20 ms | `err CFG_WRITE reg=0x00` |
| 6 | 写配置块 7 组（**`0x6e` 排在阈值之前**） | `err CFG_WRITE block` |
| 7 | 回读校验 **13 个字节** | 逐条 `CFG_MISMATCH reg=… wrote=… read=…` |
| 8 | 挂 OUT 双边沿中断 | `err OUT_INIT` |
| 9 | 自检窗口内丢弃事件（默认 3000 ms，**从模组上电起算**） | 窗口结束打 `SELFCHECK done` |
| 10 | 进入监控循环（20 ms 节拍 + 队列唤醒） | — |

### 6.2 三个「外部 pin 控制」为什么必须改寄存器（本方案最容易静默失败的地方）

这颗芯片有三个开关：**阈值档位、延时、工作模式**。出厂时它们由**芯片的物理 pin** 决定，
只有把对应的「寄存器控制位」置 1，才会改由寄存器决定：

| 控制位 | 不置 1 的后果 | 为什么在 EDX106 上尤其致命 |
|---|---|---|
| **`0x6e` bit6** | 阈值由**外部 pin 的 8 档**决定，`0x0f/0x10` **完全不生效**（出厂 `0x6e=0x98`，bit6=0！） | 模组只有 5 个脚，**这个 pin 没有引出**，模组内部绑成什么未知 |
| **`0x45` bit0** | 延时由**外部 delay pin** 决定，`0x46~0x49` 不生效 | 同上，`delay pin` 也没有引出 |
| **`0x6c` bit6** | 工作模式由**外部 burst_en pin** 决定 | 同上，`burst_en` 也没有引出 |

**「静默失效」为什么最难查**：写完 `0x0f=70` 之后**回读仍然是 70**（写入通路完全正常），
但芯片实际用的是 pin 档位 —— 现象是「**参数改了没反应**」，现场极容易误判成「芯片坏」或「接线松」。

所以本固件做了三重保护：

1. **写顺序**：`0x6e` 排在 `0x0f/0x10` **之前**；
2. **单独日志**：启动时打一行 `EDX106: ctrl 0x6c=… 0x6d=… 0x6e=… 0x45=… (thr_reg=… delay_reg=… mode_reg=…)`；
3. **编译期断言**：把「这三位必须为 1、且三个字节的默认值分别等于 `0xD3`/`0xF8`/`0xE8`」钉死，
   改坏了直接**构建失败**（负控已验证：把 `0x6e` bit6 改成 0 → `static assertion failed`）。

> ⚠️ **本次定稿的 `0x6c` 是 `0x53`（不是 `0xD3`）**：两者的差别只在 **bit7（ULP）**。
> `0xD3` = 超低功耗档，`0x53` = 常规模式。**这正是第 7 节测距的关键**，别以为是写错了。

### 6.3 为什么实测高电平宽度会大于 `delay`

实测 `delay=2000 ms`，但三次触发的高电平宽度是 **2368 / 3198 / 3845 ms**。原因不是误差，是**二次触发顺延**：

```text
        t0(有人)                      t0+2000                      t0+…
OUT ─────┐‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾┌─────────────────────
         │   高电平 = 芯片内部的 delay 定时（0x46~0x49） │
         │        ▲ 期间又检测到运动 → 定时器被再次装满 → 继续高
LED  ────┐‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾┌──── （灯直接映射 OUT 电平）
USB  ────┤ trig=1 t=t0 …                          │ trig=0 t=t0+width
         └── 闭锁（lockout, 0x52/0x53）在延时结束之后才开始计时 ──►
```

要点：

- `width` 是**实测宽度**（固件算的），不是配置值。判据是「`width ≥ delay`」而不是「`width ≈ delay`」；
- 只要人手一直在门前动，`width` 就会一直顺延——**这是门锁场景想要的**（人还在就不灭灯）；
- 若确实要「到点必灭」，手册里 `0x32` bit6 有关二次触发的位（本 demo **没有改**它，保持出厂行为）。
- **LED 定时在芯片里、不在 MCU 里**：固件只做「电平 → 灯」的映射，不做任何软件定时，
  所以「灯和 OUT 同步」是结构性正确，不依赖定时精度。

### 6.4 上电自检期 OUT 恒高 ≈3000 ms（必须丢弃）

| 项 | 值 |
|---|---|
| 自检时间 | **≈3000 ms**（`0x3c`/`0x3d` 默认 `0x0bb8`，单位 ms） |
| 期间 OUT | **强制高**（看起来像「一直有人」） |
| 固件行为 | 自检窗口内**丢弃所有事件**，只累计 `dropped`，窗口结束打一行 `SELFCHECK done level=… dropped=…` |
| 窗口起点 | **从模组上电（IO14 拉高）起算**，不是从「配置写完」起算 |

**为什么起点要从上电算**：芯片自检是它自己上电后开始的，与 MCU 什么时候写完配置无关。
若从「配置写完」起算，窗口会被推迟，等于把芯片自检的最后一段**暴露成误触发**。

**`RESET` 命令会重开窗口**：软复位同样会重跑芯片内部自检。

### 6.5 闭锁时间（防抖）怎么工作

| 项 | 值 | 说明 |
|---|---|---|
| 寄存器 | `0x52` / `0x53`（16 位，单位 **1 ms**） | 出厂 `0x05e8 ≈ 1512 ms`，本 demo 写 **2000 ms** |
| 起算点 | **延时（高电平）结束之后** | 所以两次事件的最小间隔 ≈ `delay + lockout` = 4000 ms |
| 实测 | 0.5 s 间隔连挥 3 次 → **只记 1 次事件** | 闭锁生效 |
| 实测 | 1.0 m 处 22 s 内 3 次触发，间隔 6.4 s / 8.1 s | 均 ≥ 4 s，**0 次违例** |

**闭锁是「门锁不误触发」的第一道工程手段**，比调阈值更直接：
调阈值是「降低灵敏度」，闭锁是「同一件事只算一次」。

### 6.6 本固件实际写入的寄存器表（可照抄）

| 寄存器 | 写入值（定稿） | 语义 | 出厂默认 |
|---|---|---|---|
| `0x00` | `0x00` → 延时 → `0x01` | 软复位 → 释放 | `0x01` |
| **`0x6c`** | **`0x53`**（常规）／`0xD3`（ULP） | bit7=1 超低功耗 / **bit6=1 模式走寄存器** / bit4=1 关光敏（兼容保留） | `0x03` |
| **`0x6d`** | **`0xF8`** | bit3=1 参数可调 / bits2:0=000 最低功耗档 | `0xf3` |
| **`0x6e`** | **`0xE8`** | **bit6=1 阈值走寄存器** / bit5=1 burst 可调 / bits4:3=01 | `0x98` |
| `0x0f` / `0x10` | `thr` 低 8 位 / 高 2 位（`thr=70` → `0x46`/`0x00`） | 阈值 **0~1023** | `0x06`/`0x00` |
| **`0x45`** | **`0x01`** | **bit0=1 延时走寄存器** | `0x00` |
| `0x46~0x49` | `delay` 32 位小端（2000 → `D0 07 00 00`） | 高电平延时，单位 ms | `0x0400` = 1024 ms |
| `0x52` / `0x53` | `lockout` 16 位小端（2000 → `D0 07`） | 闭锁时间，单位 ms | `≈1512 ms` |
| `0x60` | `0x33` | 第一级接收增益（3 dB/step，**值越大增益越小**） | `0x33` |

**回读校验覆盖 13 个字节**：`0x6c / 0x6d / 0x6e / 0x0f / 0x10 / 0x45 / 0x46~0x49 / 0x52 / 0x53 / 0x60`。

### 6.7 关于 I2C 本身

| 项 | 值 |
|---|---|
| 7 位从机地址 | **`0x28`**（8 位写法：写 `0x50` / 读 `0x51`） |
| 速率 | 芯片上限 **400 kHz**；**本 demo 用 100 kHz**（内部上拉下才稳） |
| 寄存器空间 | **111 个字节**，偏移 `0x00~0x6f`，连续读写**地址自动加一** |
| 单字节读 | 必须**重复起始（Sr）**：写偏移 → Sr → 读 |
| 地址选择脚 | **没有**（模组只 5 个脚，地址固定） |

## 7. 调参即测距（本文第二重要的一章）

### 7.1 决定性对比：瓶颈是功耗模式，不是阈值

同一颗模组、同一套接线（内部上拉 100 kHz）、同一安装位置，**只改工作模式与阈值**：

| 配置 | 写入值 | 阈值 | 实测触发距离 | 备注 |
|---|---|---|---|---|
| **ULP 模式** | `0x6c=0xD3` | 300 | 需贴很近 | 出厂参考代码的初始默认 |
| **ULP 模式** | `0x6c=0xD3` | 115 | **≈30 cm** | 降阈值只换来一点距离 |
| ULP 模式 | `0x6c=0xD3` | 70 | 只验了在线写入 `rd=70`（未单独测距） | — |
| **常规模式** | **`0x6c=0x53`** | **70** | **≥1.0 m 稳定触发** | **本次定稿配置** |

> **结论：探测距离由占空比决定，不由阈值决定。**
> ULP 是 burst / duty-cycle 扫描，把平均电流压到 µA 级，代价就是探测距离被占空比直接压掉；
> 常规模式是连续工作，距离回到芯片标称水平。
> **想要 1 m 级距离，只能常供电。**

### 7.2 两档功耗差约 100 倍（并且本文不给续航数字）

| 档位 | 电流量级 | 来源 | 备注 |
|---|---|---|---|
| **ULP 模式** | **78~341 µA** | 芯片手册实测表（对应不同功耗档/burst 频率） | 模组规格书没有这一栏 |
| **常规模式** | **≈26 mA** | 芯片手册 | 模组规格书写的是「常规 &lt;55 µA」，**与芯片手册矛盾** |

**两档差约 100 倍**，这是「30 cm 对 1.0 m」的电气根源。

> 🚫 **本文不写任何续航 / 平均功耗 / 「能用几个月」的数字。**
> 原因：两份资料的电流本身互相矛盾（模组规格书「常规 &lt;55 µA」vs 芯片手册「常规 ≈26 mA」），
> 且**两份都没有给峰值/启动浪涌**。续航结论依赖电池容量、占空比策略、唤醒频率与整机静态电流，
> 这些在本 demo 里**一项都没实测**。需要续航结论时，按附录 C ④ 先测功耗再说。

### 7.3 现场调参顺序（照这个顺序，代价从低到高）

| # | 命令 | 预期效果 | 代价 / 副作用 |
|---|---|---|---|
| **1** | `SET mode=normal` | **最大杠杆**（`0xD3`→`0x53`）。距离回到芯片标称水平 | 电流涨到 **≈26 mA** 量级；电池供电场景要重新评估 |
| **2** | `SET thr=70` → `60` → `40` | 灵敏度提高，1 m 站稳更易触发 | 误触发上升（走廊人流、窗帘、风扇都可能触发）；低于约 40 后底噪开始主导 |
| **3** | `SET win=10,4,2` | 「超阈值的窗口数」减一，**明显更易触发** | 抗噪变差：单窗偶然尖峰就会被判成「有人」 |
| **4** | `SET gain=3`（值越小增益越大） | 调小（`4→3→2`）增益变大 → 距离增加 | 增益变大同时放大噪声与本振泄漏，容易误触发 |
| **5** | 检查**安装朝向 / 壳体** | 10.5 GHz 穿透极差：金属完全挡死，塑料壳要留窗 | 纯结构改动，无电气副作用 |
| **6** | 检查**电源纹波**（H3 的 `V` 对 `G`） | 纹波超标会同时造成**误报**与**灵敏度下降** | 需要示波器；对策是加去耦/换电源 |

**一次完整的现场脚本（照抄即可）**：

```text
CFG?                     → 先看现状（thr / delay / lockout / mode 分别是什么）
SET mode=normal          → EDX106: set mode=normal ok rd=0x53
                           EDX106: run mode=normal thr=70 ...   ← 先确认模式真的切了
（此时手在 1.0 m 处试；已 OK 就到此为止）
SET thr=60               → EDX106: set thr=60 ok rd=60
SET win=10,4,2           → 明显更易触发（抗噪变差）
SET gain=3               → 增益变大（值越小增益越大）
TRIG?                    → 看累计次数与当前电平，确认这次改动有没有效果
```

两条容易踩的坑：

- **`SET` 不落 NVS**：设置只在本次运行有效，**复位/重新上电就回到编译期默认**（本 demo 默认已是常规模式 + `thr=70`）。
  现场调好后要固化，得改 `sdkconfig.defaults.door_lock_edx106` 并重新构建烧录。
- **改过 `0x0d`（`SET win=`）之后重启**，启动日志可能出现
  `id reg0x0d=… expect=0x0a (mismatch, continue)` —— 这**不是器件坏**：
  `0x0d` 同时是「窗口长度」和本固件拿来当存在性探针的寄存器。判据依旧看 5.3 那三行。

### 7.4 怎么把「距离 vs 参数」变成数据而不是印象

用 `tools/edx106_capture.py` 抓触发事件并落 CSV（每次触发一行：宽度、间隔），
每换一组参数就换一个 `--label`：

```powershell
py -3 tools\edx106_capture.py --port COM8 --duration 22 --label "normal_thr70_1.0m"
```

判据：

- 每行**宽度 ≥ `delay`**（小于 `delay` 说明 `0x45` bit0 没生效，延时还在走 pin）；
- 两次 `trig=1` 的间隔 **≥ `delay + lockout`**（否则说明闭锁没生效）；
- **一次只测一个固定距离**：异步指令下无法对齐「用户实际开始时刻」，站定后持续挥手 18 s 最干净。

## 9. 故障排查

### 9.1 三层法：电源 → 总线 → 参数与安装

**照顺序走，不要跳层。** 前一层的现象会伪装成后一层的问题。

#### 第①层 RADAR 红灯不亮 = 模组没上电

| 现象 | 判据 | 处置 |
|---|---|---|
| 红灯不亮、绿灯亮 | `3.3V_RADAR` 没建立 | 确认插的是 **H3**（不是 H4）；固件是否把 **IO14** 拉高（确认烧的是 `door_lock_edx106`）；量 H3 的 `V` 对 `G` 是否 3.3 V ±5%（3.14~3.47 V） |
| 两个灯都不亮 | USB 链路 | 换数据线（最常见）→ 换 USB 口（台式机用机箱后面）→ 换主机 |
| 红灯亮但设备管理器没有串口 | USB 链路 | 同上；按住 `BOOT` 再插 USB 后松开 |

> **红灯是唯一能直接判断「模组有没有电」的指示**。红灯不亮时，任何 I2C 排查都是白做——
> 芯片没上电，`SCAN` 一定扫不到 `0x28`。

#### 第②层 `SCAN` 扫不到 `0x28` = 接线 / 上拉 / 降频

按顺序做，**每一步都只改一个变量**：

| # | 动作 | 期望 |
|---|---|---|
| 1 | 查 **SCL 与 SDA 是否接反**（`SCL→H3 的 T(IO4)`、`SDA→A(IO5)`） | 接反的现象就是「红灯亮、扫不到」 |
| 2 | 确认启动日志里有 `pullup=internal`、`boot pwr_en=1` | 内部上拉没启用时总线是浮空的 |
| 3 | 把跳线**缩短**（≤10~15 cm），确认**共地**良好 | 内部上拉约 45 kΩ，线越长上升沿越慢 |
| 4 | 把 `APP_EDK60_EDX106_I2C_FREQ_HZ` 设成 **50000**，重建后再扫 | 固件本身有三级降频（配置值 → 100 kHz → 50 kHz），若看到 `I2C_DOWNSHIFT` 说明已到边缘 |
| 5 | 仍不行 → H3 侧外并 **2×4.7 kΩ** 到 3V3 | 固件连续两次失败会自己提示这一条（`hint 建议加 2x4.7k 外置上拉`） |

**`SCAN` 扫不到 ≠ 芯片坏**：这颗芯片没有复位脚、没有地址脚，扫不到只有三种可能——
**没上电 / 线不通 / 上拉不足**。

#### 第③层 能通信但测不远 = 功耗模式 / 阈值 / 安装

这一层是最容易「以为硬件坏了」的一层。**先看 `run` 行的 `mode`**：

| 现象 | 先看什么 | 结论与处置 |
|---|---|---|
| `run … mode=ulp` / `ctrl … 0x6c=0xd3(ulp=1)` | 模式还在 ULP | **这是 30 cm 级的默认档**。`SET mode=normal`（7.1 第 1 步） |
| `mode=normal` 但 1 m 不触发 | 阈值 / 窗口 / 增益 | 按 7.3 顺序：`thr 70→60→40`、`win 的 cnt 3→2`、`gain 4→3→2` |
| 阈值改了没反应 | `CFG?` 里有没有 `thr_src=pin` 告警 | **`0x6e` bit6=0** → 阈值仍走 pin，写进去不生效（6.2） |
| 触发但 `width` 远小于 `delay` | `ctrl … 0x45=0x01(delay_reg=1)` | `0x45` bit0 没生效 → 延时还在走 pin |
| 完全不动也报触发 | 电源纹波 / 安装朝向 | 纹波 >100 mV 会误报；金属门/玻璃/陶瓷贴在模组前方也会异常（10.5 GHz 穿透极差） |
| 一上电就 `trig=1` 且久久不落 | 自检窗口太短 | 调大 `APP_EDK60_EDX106_SELFCHECK_MS`（默认 3000，芯片标称即 3000） |

### 9.2 本方案特有的坑（按杀伤力排序）

| # | 现象 | 根因 | 处置 |
|---|---|---|---|
| 1 | **参数改了没反应**（回读却正确） | 三个控制位之一没置 1，参数走的是 pin | 看 `ctrl` 行三个 `*_reg=1`；`CFG?` 有 `thr_src=pin` 告警 |
| 2 | 忘了每次上电重配，现场「参数不对」 | 芯片寄存器**掉电不保存** | 本固件已在启动序列里强制重配 + 回读；自己写固件时别省这一步 |
| 3 | 上电前 3 s 被判成「一直有人」 | 自检期 OUT 恒高 | 固件已在自检窗口内丢事件；自己写固件时用 `0x3c/0x3d` 的毫秒数 + 余量 |
| 4 | 「宽度比 delay 长，是 bug 吗」 | **二次触发顺延**（6.3） | 不是 bug；判据用 `width ≥ delay` |
| 5 | 想同时接 EDV11P/EDV163 | 共用 **IO4/IO5** | 一次只能一个雷达 demo；换 demo 要拔线 + 重烧 |
| 6 | 换到 H4 后一个 ACK 都没有 | H4 顺序镜像，`T` 与电源使能同侧 | **认准丝印 H3**，按 `RES A R T G V P` 对齐 |
| 7 | 跑 400 kHz 就大量 NACK | 内部上拉约 45 kΩ，上升沿不够快 | 先降回 100 kHz；要 400 kHz 必须外并 2×4.7 kΩ（待实测，附录 C ⑤） |
| 8 | 上电偶发进下载模式 | **IO2 是 strapping 关注脚** | **Plan B：`OUT_GPIO=3` + 线挪到 H3 的 `A3`**（3.6） |
| 9 | 改了 `SET win=` 后重启，`id reg0x0d` 报 mismatch | `0x0d` 既是窗口长度又是存在性探针 | 不是故障；判据看 5.3 三行 |
| 10 | 网页页面打开是 404 | 静态资源（`edx106/test.html`、`flash.html`）尚未部署 | 先用命令行；不要因此怀疑接线 |
| 11 | 网页与命令行/`idf.py monitor` 同时开 | 同一个 COM 口只能一个程序占用 | 先断开一个 |

## 10. 已知边界

诚实列出这个方案**没有**做到的地方——照着做之前请先看这一节。

| # | 边界 | 说明 |
|---|---|---|
| 1 | **本型号无光敏** | 型号 `EDX106-N-01`，命名规则里 `N = 无光敏` → **没有光敏脚**。`0x6c` bit4（关光敏）在本型号上**无实际作用**，固件写 1 属**兼容保留**（换 `-Y` 型号才有意义）。所以「白天/夜晚不同灵敏度」这类策略**做不了** |
| 2 | **模组没有 delay / burst_en / 阈值档位 pin** | 5 个脚里这三路**全部没有引出**，芯片内部把这三个「外部 pin 控制」绑成了什么**未知**。本 demo 的应对是把三个控制位**强制切到寄存器**（6.2），因此**不依赖**这个未知量 |
| 3 | **供电纹波要求 ≤50~100 mV** | 规格书注意事项明写：纹波超标会「受干扰和误报」。本 demo 用 PC 的 USB-C 供电（未实测纹波值）；若改电池/适配器，**第一件事是量纹波** |
| 4 | **10.5 GHz 穿透极差** | 金属完全挡死；玻璃、陶瓷、金属拉手也不能放在天线前方；天线板与金属平面要保持 **5~12 mm**，且前方必须是塑胶。门锁里常见的金属面板/玻璃面板都在禁区 |
| 5 | **电池场景必须用 ULP 换距离** | ULP 档（78~341 µA）实测只有 **≈30 cm**，常规档（≈26 mA）才 **≥1.0 m**。**两档差约 100 倍电流**——电池门锁要么接受近距离方案，要么接受常供电 |
| 6 | **不给续航数字** | 见 7.2：两份资料电流矛盾且都没给峰值。**任何「能用 X 个月」的说法在此刻都没有依据** |
| 7 | **`SET` 不落 NVS** | 运行期改动**复位即失效**。固化要改 `sdkconfig.defaults.door_lock_edx106` 并重新构建 |
| 8 | **本 demo 只做「在线监测 + 亮灯」** | **未实现深睡唤醒**。好在 OUT 在 IO2（GPIO0~7，EXT1 域），产品化可直接用，**不需要改脚** |
| 9 | **只给「有人/无人」，不给距离与坐标** | OUT 是单比特电平，不含距离、速度、方向信息。需要这些请换带数据接口的模组 |
| 10 | **「有人」是运动感应，不是存在感应** | 10.5 GHz 多普勒测的是**运动**。人坐在门前一动不动可能不触发（本次未专项实测） |
| 11 | **外部上拉 + 400 kHz 未验证** | 样机全程 **100 kHz + 内部上拉**（零外部电阻）。量产要升 400 kHz 时需补测（附录 C ⑤） |
| 12 | **IO2 是 strapping 脚** | app 运行前的电平由芯片内部默认决定，固件管不到。固件只配输入 + 上拉、从不驱动；异常时走 Plan B（IO3） |
| 13 | **走 H3 就不能同时接其它雷达** | 与 EDV11P / EDV163 共用 IO4/IO5 |
| 14 | **不承担安全/控制责任** | 这是技术演示：触发信号**未经功能安全评估**，不可直接驱动锁体、门禁联锁等有安全后果的执行机构 |

## 附录 A · 寄存器速查

### A.1 本 demo 写入的 7 组（定稿值）

```text
0x00 ← 0x00, 延时 10 ms, 0x01            软复位 → 释放（不改变其它寄存器内容）
0x6c ← 0x53（常规） / 0xD3（ULP）        模式走寄存器 + 关光敏（兼容保留）
0x6d ← 0xF8                              参数可调 + 最低功耗档
0x6e ← 0xE8                              ★ bit6=1 阈值走寄存器
0x0f ← thr & 0xFF   0x10 ← (thr>>8) & 0x03   阈值 0~1023（默认 70）
0x45 ← 0x01                              ★ bit0=1 延时走寄存器
0x46~0x49 ← delay 32 位小端（ms）         默认 2000 → D0 07 00 00
0x52,0x53 ← lockout 16 位小端（ms）       默认 2000 → D0 07
0x60 ← 0x33                              第一级增益（值越大增益越小）
```

**写入顺序硬约束**：`0x6e` 必须写在 `0x0f/0x10` **之前**（否则阈值那一刻仍由 pin 决定）。

### A.2 三个「缺一不可」的控制位

| 位 | 置 1 后 | 不置 1 会怎样 |
|---|---|---|
| `0x6e` bit6 | 阈值由 `0x0f/0x10` 决定 | 阈值由外部 pin 的 8 档决定，写进去**不生效** |
| `0x45` bit0 | 延时由 `0x46~0x49` 决定 | 延时由外部 delay pin 决定，写进去**不生效** |
| `0x6c` bit6 | 工作模式由寄存器 bit7 决定 | 模式由外部 burst_en pin 决定，ULP/常规切换**无效** |

### A.3 回读校验覆盖的 13 字节

```text
0x6c 0x6d 0x6e 0x0f 0x10 0x45 0x46 0x47 0x48 0x49 0x52 0x53 0x60
```

### A.4 只读/参考寄存器（本 demo 不改，但排查时会看）

| 寄存器 | 出厂默认 | 用途 |
|---|---|---|
| `0x0d` | `0x0a` | 窗口长度（采样点数）；本固件拿它当**存在性探针** |
| `0x30` / `0x31` | `0x04` / `0x03` | 观察 4 个窗口、其中 3 个超阈值即触发（`SET win=` 可改） |
| `0x3c` / `0x3d` | `0x0bb8` = 3000 ms | **上电自检期**（OUT 恒高），改后需软复位 |
| `0x32` | `0x04` | bit6 关二次触发；bits5:4 GPIO 逻辑极性 |

## 附录 B · 命令速查

| 命令 | 作用 | 写芯片 | 回执示例 |
|---|---|---|---|
| `CFG?` | 逐条回读 9 组寄存器并翻译语义（含 `thr_src=pin` 告警） | 否 | 多行寄存器清单 |
| `SCAN` | 扫 `0x08~0x77`，标出 `0x28` | 否 | 地址列表 |
| `TRIG?` | 当前电平 / 最近触发时刻 / 累计次数 / 丢弃计数 | 否 | 单行 |
| `SET thr=70` | 写 `0x0f/0x10` + 回读 + 复查 `0x6e` bit6 | 是 | `set thr=70 ok rd=70` |
| `SET delay=2000` | 写 `0x46~0x49` + 回读 | 是 | `set delay=2000 ok rd=2000` |
| `SET lockout=2000` | 写 `0x52/0x53` + 回读 | 是 | `set lockout=2000 ok rd=2000` |
| `SET mode=normal` | 只翻 `0x6c` bit7 + 回读 | 是 | `set mode=normal ok rd=0x53` |
| `SET gain=3` | 写 `0x60` 高 4 位（低 4 位保持）+ 回读 | 是 | `set gain=3 ok rd=0x33…` 形式 |
| `SET win=10,4,3` | 写 `0x0d`/`0x30`/`0x31` + 三项回读 | 是 | `set win=10,4,3 ok rd=10,4,3` |
| `LED on` / `LED off` | 只动 IO15，不碰 I2C | 否 | `led on gpio=15 level=1` |
| `LED blink` | 亮灭 3 × 200 ms | 否 | `led blink done` |
| `LED?` | 电平原值 / 是否点亮 / 编译开关 | 否 | `led? level=1 on=1 …` |
| `RESET` | 重跑启动序列（软复位 + 重配 + 重开自检窗口） | 是 | 重复整段启动日志 |

**事件行格式**（每行 `\r\n` 结尾，全部以 `EDX106: ` 开头）：

```text
EDX106: t=<ms> trig=1 level=1 delay=<ms> lockout=<ms> thr=<n> mode=<normal|ulp>
EDX106: led on (trigger)
EDX106: t=<ms> trig=0 width=<实测毫秒>
EDX106: led off (release)
EDX106: stat interval=10s trig=<n> width_min=<ms> width_max=<ms> i2c_err=<n>
EDX106: SELFCHECK done level=<n> dropped=<n>
EDX106: ctrl 0x6c=0x.. 0x6d=0x.. 0x6e=0x.. 0x45=0x..
EDX106: cfg ok thr=.. delay=.. lockout=.. mode=.. light=off
EDX106: run mode=.. thr=.. delay=.. lockout=.. gain=0x33(0x60) win=..,..,..
EDX106: CFG_MISMATCH reg=0x.. wrote=0x.. read=0x..
EDX106: err <CODE> ...
```

> `stat` 行里的 `width_min=` 与 `width_max=` 是**两个独立键**（不是一格两值），
> 自己写解析器时按两个键取。
