开始前，确认三件事

✅检查项怎么确认
1EDX106 模组已插在板子的 H3，5 根线全接： V→V、G→G、SCL→T、SDA→A、OUT→A2 H3 丝印 RES A R T G V P。本固件用 IO4=SCL / IO5=SDA / IO2=OUT（A2）， IO14 拉高给模组上电。接反 SCL/SDA 的典型现象是 err I2C_NO_DEVICE
2不需要任何外部电阻 固件用 C6 内部上拉 + 100 kHz 已在实物上稳定跑通（i2c ok … pullup=internal）。 只有当你把线拉得很长、或 SCAN 扫不到 0x28 时，才需要外并 2×4.7 kΩ 上拉
3USB-C 线已连到电脑，且用的是 Chrome / Edge 板上有绿灯亮，电脑设备列表里能看到串口；Firefox、Safari 不支持 Web Serial，会看不到烧录按钮
为什么只要 5 根线：EDX106 模组只引出 V / G / SCL / SDA / O 五个脚 （EDX106-N-01，无光敏、无复位脚、无延时 pin）。本固件是 I2C 主控： 所有参数（阈值 / 延时 / 闭锁 / 功耗模式）都靠 写寄存器 配上，不依赖任何外部跳线或电位器。

这套固件做什么

它不是透传桥。EDK60 上的 ESP32-C6 通过 I2C 直接配置 EDX106 的 13 个关键寄存器， 再把模组的 OUT 电平接到 IO2 上用中断监测： 有人 → OUT 变高 → 橙灯（IO15）点亮 → 保持 delay 毫秒 → 熄灭； 期间再次触发会顺延，所以宽度可能大于设定值。

协议解析全部在 MCU 里完成，串口里是干净的文本行：启动横幅 + 事件行 + 每 10 s 一行统计。 这意味着 —— 雷达芯片本身不保存配置（手册明写"每次上电后需要配置"）， 所以固件每次上电都会自动重配一遍并回读校验，断电重启不会丢参数。

常见问题

1. 一上电页面就显示「有人」，持续 3 秒左右，是不是误报？
不是，这是芯片自检。AT10LP1T1RDB 上电后 OUT 会恒定输出高电平约 3000 ms （自检时间，寄存器 0x3c/0x3d 默认 0x0bb8）。它的下降沿会以 trig=0 width=1xx 的形式出现（宽度只有一百多毫秒）。
→ 测试页按「width < 500 ms 且发生在自检窗口内」判定，把这一段画成灰色并标注 「自检期，非触发」，不计入触发次数、不进宽度统计。3 秒后恢复正常。
→ 如果你想确认：串口里会看到 EDX106: SELFCHECK done level=1 dropped=0， 表示自检窗口已结束
2. 测试页里 SCAN 扫不到 0x28 怎么办？
按这个顺序查（90% 是前两条）：
→ ① SCL/SDA 接反了：SCL 必须接 H3 的 T（IO4），SDA 接 A（IO5）。 接反的表现就是 err I2C_NO_DEVICE tried=…
→ ② 模组没上电：先看丝印 RADAR 的红灯亮不亮；本固件在启动时把 IO14 拉高 给模组供电，红灯不亮说明供电脚接错了
→ ③ 线太长/接触不良：把线缩短、重插；仍不行再并 2×4.7 kΩ 上拉到 3V3（默认不需要）
→ ④ 已经是 100 kHz 仍然失败：可以降到 50 kHz 重新构建（APP_EDK60_EDX106_I2C_FREQ_HZ）
3. 只能测到 30 cm 左右，稍微远一点就没反应？
说明芯片在超低功耗（ULP）模式。ULP 是 burst / duty-cycle 扫描， 平均发射时间只占很小比例，探测距离会被直接压掉（实测 thr=115 + ULP 只有 ≈30 cm）。
→ 在测试页右列把「模式」改成 常规（normal）、阈值 thr=70，点「下发配置」并确认， 回执里应看到 EDX106: set mode=normal ok rd=0x53，然后重新测 1 m； 本固件出厂默认就是常规 + thr=70，如果你读回来是 ULP，说明有人改过
→ 代价是功耗：常规 ≈26 mA（ULP 是 µA 级）。电池门锁要在"距离"和"续航"之间做取舍， 常供电门锁直接用常规模式
4. 设定延时 2000 ms，但测到的宽度是 2364 / 2950 ms，是不是坏了？
正常。delay 是"高电平保持时间"，期间只要再次检测到人就会顺延， 所以宽度 ≥ delay 是设计行为，不是异常。
→ 实测常见值：单次挥手 2000~2400 ms；连续挥手 2900 ms 左右
→ 反过来，如果宽度明显小于 delay（比如 1000 ms），才要怀疑参数没写进去 —— 用 CFG? 看 reg 0x46..0x49 … delay=…ms 是否等于你的设定值
5. 我在测试页改了参数，断电再上电就没了？
是的，设计如此。SET 命令只写芯片寄存器并回读确认， 不写 NVS；而芯片本身也不保存配置（手册明写"每次上电后需要配置"）。
→ 所以固件每次上电都会自动重配成"定稿默认"（常规 / thr=70 / delay=2000 / lockout=2000）， 复位或重新上电 = 回到这组值；页面右列也一直挂着这条提示
→ 想把调好的参数变成新的默认值：改固件里那张配置表（demo_get_started_door_lock_edx106.c） 或对应的 Kconfig 项，重新构建后再烧一次
6. 能不能把 EDX106 和 EDV11P / EDV163 同时插上一起用？
不能同时用。EDX106 这套用的是 H3 的全部信号脚（T=SCL、A=SDA、A2=OUT）， 而 EDV11P / EDV163 也是插 H3（UART 走 T/A）。两者抢同一组排针， 同时插会既抢总线又抢电源使能，表现为两边数据都乱、或 i2c ok 都过不去。
→ 一次只插一个模组；换模组时先断电再插拔，然后烧对应固件
→ 另外：EDV151 走的是 H3 的 UART 版本固件，同样不能与本源共存 —— 板上同一时间只能有一套雷达固件 + 一个模组
