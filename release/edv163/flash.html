EDK60_VA V1.0（ESP32-C6）+ EDV163 水位监测雷达的桥接固件。 不需要安装任何软件。用 Chrome 或 Edge 浏览器打开本页，插上 USB 线，点按钮即可。

开始前，确认三件事

✅检查项怎么确认
1雷达模组已插在板子的 H3 排针上模组插紧，不要插在 H4（H4 顺序相反，会电源/数据互扰）
2USB-C 线已连到电脑板上有绿灯亮，电脑设备列表里能看到串口
3用的是 Chrome / EdgeFirefox、Safari 不支持 Web Serial，会看不到烧录按钮

烧录（三步）

  1. 点下面的按钮，浏览器会弹出一个设备列表
  2. 在列表里选带 USB / JTAG / COM 字样的那一项，点「连接」
  3. 点 安装 / Install，等进度条走完（约 10~20 秒），看到「完成」就好了
当前浏览器不支持。请改用电脑上的 Chrome 或 Edge 打开本页。 本页需要用 https:// 或 localhost 打开才能使用串口功能。

如果按钮点了没反应，见下面「常见问题」第 3 条。

本次写入的内容：合并固件 edk60_edv163_level.bin， 244,192 字节，烧录偏移 0x0，目标芯片 ESP32-C6，版本 0.9.0。 烧录器会自动整片擦除后写入（一次成型，不需要分别烧 bootloader / 分区表 / app）。

烧完之后

  1. 拔掉 USB 线，等 2 秒，再插回去（让板子重新启动）
  2. 看板子上的 丝印 RADAR 的红灯：亮了 = 雷达已上电，正常
  3. 打开演示页 level.html（同一目录，也可以直接点这个链接）
  4. 在演示页里点 「连接串口」，在弹窗里选那个 USB 串行设备； 串口参数固定 256000 8N1 无流控，页面已设好，不要改成 921600
  5. 连上后如果 10 秒内还没有数据点，到右栏点一次 「下发配置…（需确认）」并在确认框里点确定——它会按推荐参数把挂高、上报频率、 工作模式写进模组（雷达需要先被配置才会按 0xA3/0x81 上报）
  6. 水位曲线会自己开始滚动，顶栏状态条能看到帧率、坏帧数、最后上报时间
演示页是「默认只读」的：连上之后只发查询指令（op=0xA0）， 不改写模组配置；任何写入都必须你先点「下发配置…」并在确认框里点确定。
如果没有硬件，勾选页面上的「模拟演示（无需硬件）」也能看到完整的解析与曲线效果。

这套固件做什么

它是一根透明的桥：EDK60 板上的 ESP32-C6 把 EDV163 雷达串口上的字节 原样转发到板子的原生 USB（CDC，免驱），固件本身不做任何协议解析。 也就是说雷达上报的每一帧都完整送到上位机，帧怎么解、水位怎么算， 全部在上位机（网页或你的程序）里完成——雷达固件升级、协议字段调整都不需要重新烧板子。

项值
固件名radar_bridge_edv163（纯字节透传桥，工程内 18 个 demo 中的第 5.3 个）
目标芯片 / 板子ESP32-C6 · EDK60_VA V1.0
雷达模组EDV163（水位监测）
模组插入位置H3（必须，不能插 H4）
串口参数256000 · 8N1 · 无流控（不是 921600）
帧格式帧头 45 44，帧尾 0A，正文转义： 0A → 09 01、09 → 09 00；长度域与校验和按还原后字节计算
上报帧op=0xA3 / type=0x81，载荷 count(1B) + count × 7B （channel / presence / state / direction 各 1B + distance 2B 大端 mm + angle 1B int8）
水位换算水位 = 挂高 − distance（挂高在网页里设定，或从设备 0x25 回读）
上板实测❌ 尚未在 EDV163 实物上验证（模组当前烧的是其它固件，换固件后才能测）
已有验证解析工具自测通过（tools/edv163_frame_check.py --selftest）； 网页自测 10/10 + 44/44 + 32/32（帧解析用例 / 整页桩环境 / 布局与不变量契约）。 以上均为无硬件验证，不能替代实机数据

常见问题

1. 烧好了，但我用串口助手打开只看到一堆乱码 / 乱字符？
这是正常的，不是坏了。本固件转发的是雷达的二进制协议帧（以 0x45 0x44 开头， 中间含不可打印字节与转义序列），不是文本。串口助手默认按文本显示，自然就是乱码。
→ 想看有意义的内容，请用演示页 level.html（它按协议解析并画水位曲线）
→ 想在串口助手里看，切到 Hex / 十六进制显示，端口参数必须是 256000 8N1；参数填错时连十六进制也是错乱的
2. 模组插在 H4 上行不行？
不行。H3 与 H4 的信号集合相同但顺序相反：H4 上模组的 T（数据）与 电源使能落在同一网络，插 H4 会造成电源与数据互相干扰——典型现象是红灯忽明忽暗、 串口要么没数据要么全坏帧。
→ 断电后把模组移到 H3，插紧，再上电
3. 网页连不上串口 / 点了没反应 / 根本没有按钮？
→ 浏览器不对：只有电脑版 Chrome / Edge 支持 Web Serial；Firefox、Safari、 手机浏览器、微信内置浏览器都不支持
→ 页面不是安全上下文：Web Serial 只在 https:// 或 http://localhost 下可用。 用本站 https 页面访问即正常；直接双击打开本地 file:// 文件可能失败， 本地测试请在该目录起一个静态服务（例如 py -3 -m http.server 8771） 再访问 http://localhost:8771/level.html
→ 串口被占用：关掉串口助手、Arduino IDE、其它浏览器标签页后重试
→ 还不行：换一根能传数据的 USB 线（很多充电线只有电、没有数据），优先插机箱后面的 USB 口
4. 波特率为什么要 256000？能不能用 921600？
不能。EDV163 这一代水位雷达的串口固定 256000 8N1 无流控， 和 EDV151 / EDV11P 用的 921600 不是一个档位。波特率填错的表现是： 串口能打开、但一个合法帧都收不到，状态条坏帧数与收字节数会一直往上飙。
→ 演示页已把 256000 写死在代码里，正常不需要手动填；自己写程序对接时务必对齐这一档
5. 水面很平静，页面却显示「无人 / 无目标」，是不是坏了？
不是坏了，这是正常的。EDV163 是人体存在检测算法的衍生品，静止水面常常被判为「无人」 （presence=0、state=0）。这不影响水位：只要距离在合法范围内 （0 < distance ≤ 挂高），距离值照常参与水位计算、曲线照常画。
真正无效的只有两种情况：距离为 0（无回波）或 距离 > 挂高（超量程，页面会标出来）
另注：模组距离分辨率约 ±8 cm，所以页面只显示整数 cm，不显示 0.1 cm 的虚假精度。
